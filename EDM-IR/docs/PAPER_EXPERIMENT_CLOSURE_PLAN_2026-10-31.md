# EDM IR 论文完整实验与验收计划

2026-10-31。适用对象：当前代码与 LaTeX 初稿，首投目标 FGCS。本计划覆盖从现有反例诊断到完整 MoE 推理、图表和复现材料的收尾，不把下一次 GPU 采集当作全部实验。计划已形成，执行清单尚未封存；本次没有训练、GPU 操作或新增性能数据。

研究问题固定为：在单机 NVLink 通信条件下，如何依据执行工作、资源服务和依赖关系，在数值合格的执行路径中选择完整耗时较低的方案，并判断选择成本能否在真实 MoE 中收回。成功既包括支持声明，也包括用反例否定、收窄声明；不以跑出正加速或零误选作为停止条件。

## 3 协议身份和数据隔离

每行记录必须绑定 shape（显式 P/M/K/N）、dtype、累加和写回精度、输入/路由/权重哈希、候选 ID、实际 kernel/库算法、依赖策略、metadata 策略、软件与二进制、GPU UUID/拓扑、计时边界、重复/配对 ID。host 始终指 CPU 发起的 GPU 路径，不是 CPU GEMM。

均匀算子从已驻留的 source activation 和 destination weight 开始，到所有声明输出可消费结束；每调用必要的复制、打包、转换、CPU 提交和同步计入。一次性准备可在区间外，但必须单列。不可变输入的依赖简化不能直接用于每步会改变的 serving 输入。

数据分为五类：历史开发数据、新执行身份开发数据、六形状独立评价、真实请求开发集、真实请求评价集。一个形状全部候选与重复同组；同一父请求的路由、切片、不同 P 回放及人造控制同组。公开 benchmark 只用于方法和合理性核对，未满足执行身份不能拼成训练标签。

六形状 protocol/descriptions 及哈希不变，不运行其特征生成或评分来挑模型。执行前另存模型、候选、训练数据、标准化、超参、平局规则、binary 和环境的封存清单。先完成封存，再采集并打开评价标签。

早期文档的 0.5%/1% 与 99% 目标属于旧目标记录；本轮六形状验收严格使用 2026-10-28 冻结协议的平均/最坏 1%/3% 及其他条件。两者分列，不能将通过后者说成通过前者。D7 的语义和测量合同继续保留；本轮应用是新收尾协议，不把其子集写成 D7 全部 18 格已完成。

## 4 E0 本地准备和正确性

付费前完成以下工作，并由脚本输出 PASS、FAIL 或 NOT_RUN；没有真实设备就不能输出 GPU PASS。

1. 多候选运行器：一个形状一个进程，候选间清理必要状态，固定预热规则，轮次独立；超时、一个候选失败后的安全清理、断点恢复和回收演练。CUDA 上下文已损坏必须结束进程，不能继续制造计时。
2. 三种 host、十种 fused 的身份与完整边界；新增流水化路径独立版本。真实 routed BF16 与 FP16 uniform 分目录、分标定。
3. 计数枚举：尾部、q 整除/非法分片、g1/g2、M 和 PM、远端来源 P−1、FP16 serial reduction、输出依赖及缺失项；由独立参考核对，不以同一公式的复制验证自己。
4. 正确性：非零随机输入、有限值、取消抵消和幅值压力、空 bucket、尾部、不均匀专家；至少三颗固定种子。正式计时也使用声明的非零输入，避免沿用历史零输入计时却未说明。CPU 数值参考与 GPU layout 生成不要共享关键索引逻辑。
5. FP16 沿用对应合同的误差定义和阈值；BF16 routed 投影沿用 D7 的相对 L2≤1e-2、全局归一化最大误差≤2e-2，零分母规则明确。不能用 atol+rtol 偷换原来的判据。q16 修复若改成 FP32 partial，则作为新实现评估显存、额外 kernel、同步和速度，不替换历史候选。
6. 只复用已有有限状态模型检查其安全属性；不能将其结果扩展为 CUDA weak memory、NCCL 内部或完整引擎的形式化证明。
7. 资产和环境：固定 revision/镜像或锁文件、目标架构、编译产物、离线安装、profiler 短窗口和导出；先核对网络卷可挂载位置。旧算子 CUDA 12.8 环境与新引擎缓存分开。下载完成不等于驱动/ABI/JIT 通过。

输出：correctness-contract.json、environment-lock.json、candidate-manifest.json、运行器 CPU 演练、资源与单点超时限制、回收清单。完整执行包必须能在开机前列出将运行的每个工作块，不能启动后临时生成无界遍历。

## 5 E1 完整候选与强基线

原四个开发形状继续使用，不把它们叫独立测试：

| P | M | K | N | 主要作用 |
|---|---|---|---|---|
| 8 | 64 | 4096 | 2048 | 大 N 与 host/fused 边界 |
| 8 | 64 | 8192 | 1024 | grouped-N 与分片深度 |
| 8 | 256 | 8192 | 512 | M256 退步 |
| 8 | 512 | 8192 | 512 | M512 外推、累加与低估 |

前两点同时改变 K/N；后两点改变 M，也改变有效工作、输出体积和 CTA 数。这不是单因素实验，机制归因由 E2 完成。

主候选保持三 host（逐源 CUTLASS、合并 CUTLASS、合并 cuBLASLt）和十 fused（q=1/2/4/8/16 × g=1/2）。先通过数值，再计时。每配置三进程轮次，4×13×3=156 块。上一答复的九候选/108 块是赶时间的开发子集，只能作中途交付，不能替代本计划的完整验收。

q16 等失败保留输入、误差、状态和 null 耗时。已验证不合格的候选不计入有效最优；未知、超时或未测的有效性不能当失败排除后宣布完整最优。

合并 host 不能免费忽略重排；记录 cuBLASLt 算法、workspace、精度和调优预算。增加固定配置的流水化 host 作为强挑战者，见 E2。旧 13 候选主评价保持原样，流水化性能单列，不能在结果出来后把它免费加到选择器。

若四开发点仍全是 fused 胜，host/fused 分类边界不可辨识。最多调用旧八形状开发包中余下四个已暴露形状作为预先登记的备用开发点，最多增加156块；依据候选覆盖/秩/胜负覆盖触发，不从六形状挑点。如果没有合适覆盖，就报告不足，不增大网络来掩盖。

## 6 E2 机制证据

### 6.1 流水化对照

先在大 N 和 M512 两点实现一 source block 一 chunk、chunk_rows=M、两 staging buffers。串行与流水版本使用相同 chunk、buffer、传输顺序和本地 GEMM，只增加/移除声明的串行依赖。验证输入就绪和 buffer 复用安全，再用时间线检查实际并行。

两点×两策略×三轮=12块，已在原450块协议内。其余两个开发点仅补流水版本三轮，共6块；六独立形状每个补固定流水版本三轮，共18块，作为独立强基线附表。总增加24块。参数在开发结束前固定，不在六点上扫 chunk 或 buffer。

报告串行/流水 wall-time 配对差、GEMM 退化、等待和 CPU 空隙。差值是整个调度变化的净收益，不是纯通信时间。即使流水线没有加速，仍完成这个机制检验。direct kernel 内部的 load/compute overlap 不能用外部 kernel 时间线直接定量。

若流水基线稳定胜过原选择器，应据此否定原候选空间的实用充分性。需要把流水化加入最终策略时，必须在六点标签开启前另建14候选协议并冻结；原13候选结果独立报告。当前不改13候选文件，也不预授权14候选额外搜索预算。

### 6.2 固定资源与依赖的反例检验

| 控制 | 固定项与变化项 | 最小记录 | 能否定什么 |
|---|---|---|---|
| q4/q8 × g1/g2 | 同形状/精度/输入；四格改变 q/g | 完整四格时间、grid、K深度、寄存器/SMEM、等待证据 | 简单独立 q 项加 g 项；grid 恢复即性能恢复 |
| 单目的 rank / 全部目的 rank 活动 | 目标 rank 工作和来源不变，改变其他 rank 活动 | 目标区间与整程序区间、源/目的活动、时钟背景 | 固定局部服务可解释全部时间；不单独识别链路与HBM |
| 本地输入 / peer 输入 | 同 GEMM、模板、输入值，改变地址路径 | kernel区间与包含物化/同步的完整区间 | 远端路径没有影响；差值不直接叫通信成本 |
| legacy / revised 依赖 | 同数学工作、launch 数与模板，改变依赖 | 提交、ready、等待、完成时间 | 单位深度直接等于实际关键路径 |
| P4 旧短 K 配对 | 同机固定四卡子集；只重测已暴露错误配对 | q2/direct 配对区间与重复 | 用 P8 成功冒充 P4 原错误已解决 |

四格结果复用 E1，不额外搜索。额外诊断上限：五个已有短 K 点×两候选×三轮=30块；两候选×两活动条件×三轮=12块；两候选×两输入路径×三轮=12块；两形状×两依赖策略×三轮=12块；合计≤66块，执行前绑定具体ID，不扣除潜在复用来低估预算。优先级为流水化、grouped四格、短K、活动争用、local/peer、依赖政策。预算不足保留 NOT_RUN，不省略必需机制证据后宣称 C2 已全通过。

最多六个预先选定的短 trace：串行/流水一对、grouped一对、活动条件一对。NCU 只采可安全分析的少数 kernel，通常不使用完整计数集或普通 replay 去测跨卡并发；不具备权限就记 unavailable。逻辑请求、L2/HBM 流量和物理 NVLink 流量分栏，不能用一个代替另一个。

共享服务假设成立需要干预效应和执行证据共同支持；仅见到相关性不指定根因。条件DAG聚合若需填入实测节点耗时，只作为诊断上界/解释工具，不能再当作无测量预测的输入；诊断图的时间不能泄漏到在线模型特征。

## 7 E3 预测模型和结构消融

先检查执行身份、正确性、计时边界与数据覆盖，再决定修改。历史P4的3/41不作为新的训练目标函数或晋升终点。

固定五组比较：原始特征形式重标定、简单带宽/计算成本基线、保留评分器、受证据约束的结构模型、共享小网络。所有可比模型使用相同新身份开发数据、完整形状切分与标定预算。旧权重直接迁移另列，不能与重标定混合。Roofline 类基线仅作估计模型，不能拿其时间当实测。

结构消融只回答三件事：加入K/q与tile尾部是否有帮助；加入资源条件是否有帮助；加入实际依赖/整程序外围是否有帮助。只删除/加入一个表达组，其余训练划分固定；已需要训练的模型用同组折重新拟合，不用评价标签选消融。资源信息只能来自编译期、输入或允许的独立标定；未知库几何保留缺失标志。

开发采用按完整形状的交叉验证；另列M整组、K/N边界、候选族留出，明确它们均是开发压力测试，不增加所谓独立样本量。新P8只有四个形状时，不能声称可靠训练了跨形状通用网络；覆盖不足时宁可保留简单策略或拒绝外推。

若启用学习：共享评分函数、数值输入、训练集标准化；时间拟合和已测候选选择损失分列，未测候选masked。交叉熵仅为辅助，不把最优候选的噪声硬标签当唯一目标；softmax不称为真实最优概率。先用一个固定AdamW方案；Muon仅在确有优化诊断需求时作为本地、同结构/预算对照，不进入必做GPU矩阵。所有试验和失败保留，不按六点表现追加轮次。

确定一套正式策略和一个主预算后冻结。原论文主预算k=2，k=1/3同时报告；k=1是纯选择，k=2/3是预测后实际测量再选，二者必须分开。原始排序、精确平局优先规则和遍历顺序稳定性全部保留。模型不再以“开发结果再降一个错误”为上机前无限门槛。

## 8 E4 六形状独立验收

沿用原六点、13候选、3验证块，共234块。尾部、参考并行容量边界、同MN不同长宽比三组问题不改。参考容量不是实测occupancy，两个点间同时变化的因素随表报告。

六点评分前冻结最终模型及所有统计规则；k≤3选择最多18块、两host控制最多12块、等预算搜索最多18块。选择块与234验证块ID隔离，不能用验证计时来决定候选或决定重训。候选排序反转不靠删除异常慢样本解决。

18块上限依赖于固定的嵌套top3清单：k=2/3共用这批独立选择计时，k=1直接使用封存的首选；等预算搜索同样使用预先固定的嵌套前三项。最终性能均由独立验证块取得。若不同k使用非嵌套搜索或额外测量，必须另计预算，不能仍声称只用18块。

主指标 R(x)=T_selected(x)/min(T_valid_measured(x))−1，按形状等权报告平均/最坏值，附每点数据。主验收沿用均值≤1%、最坏≤3%，相对训练固定顺序和强host控制的平均/最坏均不更差，顺序稳定；双向host/fused胜负须各有超过2%的实测差距。未出现某方向时记“覆盖未建立”，即使误选为零也不能判双向通过。

同时报告硬错误数、两方向错误、top1/2/3保留率、候选耗时MAPE、全误差表、失败/缺测候选。独立流水化附表用于判断是否仍有实际价值，不伪装成原13候选最优。全部完成且准确排除数值不合格候选，才可使用“已测有效集合最优”。

六点只是有限边界确认，不能支持广泛随机泛化、未见GPU或未见模型的声明。若看过结果后修改模型，该集转为开发集；论文保留第一次封存结果，新的独立验证必须另立集合和预算，不默认开启下一轮。

## 9 E5 调优成本和摊销

比较模型k=1/2/3、训练期确定的固定候选/固定顺序、测两种强host、同预算搜索，以及离线全候选最优。搜索候选顺序与随机种子预先固定。除候选数以外还报告实际搜索秒数，因为不同候选的构建和预热成本不同。

对每个策略s定义 C_s 为首次准备/编译/预热/选择成本，h_s 为每次调用额外决策成本，t_s 为完整执行时间。重复U次的总成本为 C_s+U(h_s+t_s)。对照策略b的净节省为 Δ_U=C_b+U(h_b+t_b)−C_s−U(h_s+t_s)。标定成本分别按全项目总成本、每新环境部署成本、跨形状分摊报告，不能免费隐藏。

U=1、10、100、1000给出曲线，同时从实测差值计算回本点；每次节省≤0时不存在靠复用回本。区分代码缓存热/冷、权重加载冷启动、动态路由每步metadata，不能把动态工作当一次性成本。U是形状/策略复用，不等同KV cache命中次数。

验收：报告置信区间、有效范围与真实工作负载中是否有对应复用。如果仅在极高U才回本，论文如实限定；即使regret很低，也不能宣布经济性成立。

## 10 E6 真实路由与完整 MoE 层

本阶段新建版本化BF16应用协议，固定一个模型、一个vLLM版本、EP8、专家放置和请求集。EP组必须由实际rank映射验证，八个独立副本不算EP8。禁用speculative decoding；prefix cache、EPLB、CUDA Graph等开关在A/B间一致，方法仅支持eager时，eager匹配比较和原生最优模式必须同时保留。

先用原生引擎在开发请求运行，不等待预测器变成零误选。检查实际形状、目标子图关键路径占比及容量；不依据应用加速选择主模型。逻辑上T×top_k/E只是均匀期望，不替代真实专家M。

路由诊断独立运行：每个四点负载固定前3个完整prefill和3个完整decode step，全部MoE层、全部EP来源rank，包括空expert/rank。记录source-expert M、合并expert M、后端实际padded M、两投影K/N、layer/step、频率和偏斜；检查Σexpert counts=有效token×top_k。缺层/来源或未完成phase应报失败，不将局部直方图当全局。

原23个P8形状、四开发点、六边界点分别给出次数/行数/FLOPs覆盖，明确分母和抽样范围；真实kernel时间另测。只凭形状相同不能跨dtype/通信模式复用延迟。小诊断窗口不代表所有请求分布。

三层正确性依次通过：D7单投影canonical输出；完整MoE层（两投影、激活、router权重、combine及shared expert若存在）；完整模型logits。D7 gate weight仅metadata的旧边界不自动扩展为完整层。

完整层回放固定实际路由、各专家独立权重及输入，不丢token；A/B均计入dispatch、permutation、metadata、专家计算、activation、down、combine与同步。以引擎实际原生MoE backend为强基线，不用单纯cuBLAS GEMM替代整层对手。

本地按父请求哈希预先划分开发/评价；所有派生trace和控制不跨区。正式三种子、请求名单、source/placement、误差定义在执行清单绑定。完整层输出采用预注册BF16误差合同；最终logits同时报告相对L2、最大归一化差和固定文本的NLL变化。建议新应用验收起点为相对L2≤1e-2、归一化最大差≤2e-2、固定语料困惑度相对变化≤1%；这些是新方案目标，必须在评价前固定，不能不通过后放宽。生成文本差异另记，不要求浮点变化后逐token相同，也不凭少量文本证明所有能力不变。

原生层、固定开发期选定策略、冻结模型策略三组，各prefill/decode固定三个开发或评价trace窗口，三轮重复；开发与评价各自分开，主评价2×3×3×3=54块。若只能完整保存更少trace，采集前改变应用清单并报告样本限制，不能截断某个step当完整层。内存上限和缺失原因提前写入清单。

D7 balanced/hotset/fragmentation 控制可用于明确的路由机制假设，但不作为本轮强制全P2/P4/P8扩展。若论文保留“对碎片化鲁棒”的声明，则必须执行其守恒sentinel并对比；否则删除该声明，不凭CPU守恒检查支持性能鲁棒性。

## 11 E7 完整引擎对照

沿用先前收尾方案的四点正式负载：输入512/4096 token × 并发1/128，输出预算128 token。上一轮聊天给出的其他长度是备选，不混入主矩阵。每块请求数max(128,4×并发)，即128或512；请求token IDs、采样、EOS和实际输出长度保存。容量smoke若不成立，在任何正式结果前形成共同的新配置并记录，不只为优化组减负载。

三个版本：原生引擎；相同集成接口下的开发期最佳固定策略；冻结模型动态选择。第三者相对第二者隔离选择器价值，第二者相对原生隔离执行改动价值。四负载×三版本×三独立计时区组=36块，这是对旧24块A/B计划增加固定策略对照的显式增补。合计11520次请求执行，输出预算上限1474560 token；重复使用同一评价请求集不增加独立请求数量。整机权重可驻留，但轮次按预先随机/轮换顺序运行，记录进程复用、预热和缓存；不能将连续请求当独立进程重复。

主测量是相同请求/并发下的实际输出token/s、请求耗时、TTFT、TPOT和ITL（定义分开）、p50/p95、峰值显存、错误/OOM；包括模型特征、选择、fallback和必要同步。低成本计数确认方法实际调用次数、选择分布和覆盖；完整路由hook和profiler不进入正式计时。所有fallback明确计入，基线占优时选择基线是合法输出，但不能将这种结果说成融合加速。

这个闭环并发实验不证明开放到达流下的最大可持续吞吐。若正文要保留“相同SLO下最大吞吐提高”，另在开发阶段固定TTFT/TPOT的绝对SLO、公开请求到达序列和有限到达率搜索上限，再做开放到达A/B；否则全文仅写四个给定负载的端到端结果。这是条件扩展，不默认加入本轮36块。

性能验收必须同时满足正确性、真实调用、完整边界和独立请求。候选/配置固定后，预先定义四负载等权几何平均speedup与配对区间，逐点展示所有退步；不只展示有利点。只有区间支持的正收益才写正加速，区间覆盖1写收益未确定；样本量不足不宣称可靠p99。固定策略与模型无差别时，不能把执行器收益归给预测器。

若目标子图只占很小关键路径，可用1/((1−f)+f/s)作固定其他工作且无重叠变化下的近似收益预估；f必须有时间证据。这不是实际端到端结果。局部加速而整模型无收益，是有效负结果，需要解释集成成本、覆盖和关键路径，不换模型继续追分。

## 12 统计和异常处理

算子协议使用3个独立进程轮次，每候选20次预热、100次正式计时作为新收尾采集的默认；已有封存合同如规定更多，按其原值执行并分开身份。D7正常块的10 warmups/10 blocks/20 samples不被这个默认覆盖。新应用的预热和块格式在开发pilot后固定，不能将历史2000次repeat与bootstrap次数混淆。

保留每次原始计时，先形成完整rank/调用边界，再按固定估计量聚合。三进程中位数及max/min用于复核，不能当置信区间。主排序与旧协议一致；配对差与95%区间补充报告。bootstrap按独立进程/区组层重采样，真实请求保留父请求聚类，不将同进程100个样本当100个独立环境。仅3轮的区间不稳健，应同时显示3个原始配对差。

近似平局的复核规则必须在采集前写入清单，例如区间跨0或差值小于开发期确定的测量分辨率；最多增加2轮，原3轮结果与复核结果都保留。不能根据是否将会“通过”决定补跑。原六点硬错误/阈值不变，复核不用于把错误免费改成平局。

CUDA/NCCL错误、Xid/ECC、外部进程、明确设备异常按预设规则标为invalid block，保留并整块重跑；性能不符合预期不属于删点理由。无效候选、缺测、OOM、启动失败分别列出。没有权限的计数器记null，仿真值不填实测列。新表同时给样本数、单位、候选范围和执行身份。

## 15 失败如何形成最终结论

| 结果 | 下一步与完成边界 |
|---|---|
| 新计数或数值合同失败 | 修实现/定义，受影响数据作废并保留；未修好不进入性能主表 |
| 流水化强基线吞掉融合收益 | 保留该反例，缩小direct的优势区域；不弱化基线继续宣称普遍加速 |
| 简单固定策略与模型相当 | 报告模型增量价值不足，采用简单策略；方法贡献转向边界与可解释分析 |
| 六点未通过 | 记录失败；不再用该六点声称独立通过，不开启无上限重训 |
| 真实shape/关键路径覆盖不足 | 描述应用范围，停止把uniform proxy当通用MoE证据 |
| 层快但完整推理不快 | 分析调用覆盖、外围和关键路径；删除端到端加速声明 |
| 无法完成八卡真实集成 | 保留未完成项；完整系统论文目标尚未达成，算子版是明确的范围缩减 |

完整收尾的定义是：C1—C8每项均有支持、否定或明确未确定的状态；保留的正面声明全部有证据；失败不被删除；原始数据和图表可复核；一个真实模型的同口径对照完成。若选择不补某项证据，必须同步删除依赖它的声明，不能在计划中悄悄标为完成。负结果可能降低论文竞争力，但不应以反复更换实验对象回避。
