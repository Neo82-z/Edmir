# Analytical Performance Estimation during Code Generation on Modern GPUs

Dominik Ernst 等，arXiv:2204.14242v1；[全文](https://arxiv.org/html/2204.14242v1)，[期刊 DOI](https://doi.org/10.1016/j.jpdc.2022.11.003)。阅读日期：2026-10-25。

## 原文中最相关的三处

- §4–5 分开验证中间硬件指标与最终性能，因而可以定位错误属于哪一层。
- §4.5 的缓存命中近似含经验拟合；解析建模并不意味着完全不标定。
- §5.8 中 stencil 预测首选实测排第 12，仍达到最快配置约 96% 的吞吐；LBM 上模型不能分清中等与较优配置。作者没有掩盖这些局限，§6 将延迟效应列为后续工作。

## 对本项目的具体约束

以下是我们的研究安排，不是该论文的结论或算法复现：

1. 先分清精确计数、资源上界、待测指标和耗时拟合。只有逻辑字节时，不写成已预测 HBM/NVLink 流量。
2. 同时保留单选损失和有限候选集合的损失。筛选结果好不能抹掉既有单选失败；缩减候选数也不能直接等同于节省 GPU 时间。
3. 任何经验项注明数据来源、单位、适用域与反例。加入一个新项，要提出能够区分它与旧表达的控制实验。
4. 不把 stencil 的缓存假设、命中曲线或硬件常数移植到 Tensor Core GEMM、远端读取和多 GPU 执行。若未来研究缓存机制，需要我们自己的地址/事务分析与独立计数器验证。

本轮已经实现的动作是[有限候选评估](../../experiments/2026-10-25-bounded-candidate-selection/README.md)，主线安排见[收敛方案](../../paper/BOUNDED_SELECTION_PLAN.md)。没有移植 Warpspeed，也没有宣称其指标估计方法已在本仓库复现。

后续已落实[中间量核对、有限组合修订与 host 覆盖审查](../../experiments/2026-10-25-post-gpu-revision/README.md)：保留逻辑计数/资源界限/未测硬件指标的区分，独立复核留出选择损失，并用已有附加标签纠正部分 host 覆盖不足。新的组合表达尚未通过晋升，不能将其写成该论文支持或本项目已验证的物理模型。
