# 本轮 GPU 结果之后的研究与修改方案

后续范围更新：按论文需求，八卡已作为主验证规模，四卡保留为机制对照。见[八卡模型与原始数据回放](../experiments/2026-10-25-initial-data-replay/README.md)及[八卡论文与验证计划](P8_PUBLICATION_PLAN.md)。下文是四卡采集后的局部修订记录，其“单机四卡”描述限定该批证据，不再限制整个论文的实验规模。

2026-10-25。状态：受控表达、证据核对与 host 覆盖修订已实施，见[交付与结果](../experiments/2026-10-25-post-gpu-revision/README.md)。fused 新表达未获晋升；已有附加 host 标签使 M512 合并 CUTLASS 的留出误差从 36.28% 降至 6.63%，没有新增 GPU 测量。以下保留原修改设计及停止条件。适用范围仍是单机四卡 A100、静态均匀 FP16 All-to-All–GEMM。本方案承接[研究边界](BOUNDED_SELECTION_PLAN.md)，依据[本轮报告](../experiments/2026-10-25-runpod-hour-01/README.md)与[原验收记录](../experiments/2026-10-25-runpod-hour-01/acceptance-result.json)。

研究问题确定为：**在完整、同等计时的强基线面前，可检查的成本表达能否解释执行方式的适用边界，并在有限测量预算下提供额外选择价值？** “融合一定更快”与“模型能直接单选最优”都不是预设结论。

## 1. 已经证实什么

所有形状按 P/M/K/N 定义；本轮 P=4，M 是每个 peer 的行数。

| 问题 | 第一套 / 复跑证据 | 可以下的结论 | 尚不能下的结论 |
|---|---|---|---|
| M256/K8192/N512，q8 相对 q2 | 实测差值 −79.18 / −78.02 μs，冻结预测 +56.32 μs | 主要排序错误稳定复现 | 已经定位到某一种 semaphore、SM 或内存瓶颈 |
| M64/K4096/N2048，q4g2 相对原 host | 实测 +37.48 / +35.61 μs，预测 −7.24 μs | 大 N 的比较表达仍不充分 | 单独归罪于 fused 或 host 一侧 |
| M 方向增长 | K8192/N512/q2，M192→256 实测约 1108→1258 μs，预测均约 1147 μs | 当前局部平坦响应不符合观测 | 增加任意 M 特征就能正确外推 |
| 强基线 | 补充的四个形状中，合并 cuBLASLt 都快于对应已测 fused；K768 又由合并 CUTLASS 胜出 | 需要完整的两种合并 host，不能只比较原 host | cuBLASLt 永远最优，或 fused 在所有形状都没有机会 |

57 个配置跨采集的中位耗时变化最大 1.40%，主要反例远大于这个变化；不能用一般噪声解释掉它们。近边界 q2/q2g2 的一次方向翻转、复跑的一个质量异常及文件同步边界仍按原记录保留。390 个进程和 39,000 个样本不等于 390 个独立形状。

**计数恒等式、时间组合、最终选择是三个不同的检验对象。** 本轮暴露的是后两层。平均误差约 4% 不能替代严重错序验收；原自动选择验收仍为不通过。

## 2. 修改顺序及交付

### P0：先统一候选、执行身份和可用收益

先交付候选覆盖表与逐形状比较表，不改模型参数。

- 四种 host 分开记录：原 CUTLASS、编译器 cuBLAS、合并 CUTLASS、合并 cuBLASLt。两种合并实现是主要强基线，另两种用于解释执行组织的差异。
- 列明每个形状实测、未测、质量异常及实际算法配置。没有测量就保留缺口，不补标签，也不把补充阶段伪装成预先冻结的预测成绩。
- 记录源代码、二进制、库、硬件、依赖策略、metadata 模式和计时边界。10/21 与 10/25 按执行环境分别报告，不直接混合拟合；同一形状的不同进程不跨训练/评价划分。
- 审查实际执行工作量：当前几何账本中，全系统逐源 GEMM 数为 P²、合并为 P，GEMM 行数分别为 M 与 PM。这是已知执行差异；不能将全部收益归为某个库更快。
- 对已经共同覆盖的候选计算可用收益；不完整集合只称“已测子集最优”。补充数据可以说明基线强弱，但完整候选的严格同批比较仍需要下轮补齐。

新增一个必须比较的简单策略：**只测合并 CUTLASS 和合并 cuBLASLt，选其中较快者。** 它与模型 top-2 的候选预算相同。若它已经取得相同结果，新预测器就没有获得额外选择价值的证据。

### P1：拆清 M/q/g 的时间表达，只允许一组受控修订

当前 `regime_prediction.py` 使用公共项加 `max(aL,bW)`；L 是 K 分片深度代理，W 是逻辑 A 重读量代理。某一项较小时，其变化完全不进入 max 部分。现有 `residual_depth` 增加未隐藏的 L 项，但没有直接解决 L 占优时 W 变化被抹去的问题，不能因为平均误差较低就晋升。

本地先交付逐对分解：对 M256、M192/256/320 增长序列及大 N 反例，列出各公共项、aL、bW、激活分支及候选差值。计数从独立枚举核对，不能用预测函数自身生成“正确答案”。

第一组候选修订只检验“较小项被完全隐藏是否过强”这一假设：

\[
\widehat T=C(x)+\max(aL,bW)+\rho\min(aL,bW),\quad 0\leq\rho\leq1.
\]

这是**待检验的组合表达**，不是已经成立的流水公式。L、W 还不是两个独立实测阶段，ρ 不能称为真实未重叠比例；各项系数也不能解释为实测带宽或占用率。

本轮仅检查固定的 ρ∈{0, 0.25, 0.5, 0.75, 1}，完整报告五个结果；两个端点分别对应 max 与 sum。保持原八项系数、形状权重、固定正则化和 host 表达不变，不搜索新特征组合，不按 M256 或某个 N 单独加修正。使用已有有限分区与非负求解方法扩展，并检查端点等价、量纲、分支连续性、数值证书和排序输入重排不变性。五个候选选择本身也计入模型选择过程，不能当作免费调参。

资源几何只作为第二步的解释证据：独立 M tile、N tile、K 分片、寄存器/共享内存界限、有序输出累加逐项核对。资源容量推导的轮数下界不等于真实调度轮数，SM 上限不等于实际 occupancy。**第一组修订若不能同时修复稳定反例并守住原有表现，就停止新增总耗时拟合项，转入定向测量。**

### P2：单独处理 host 和库算法边界

交付 host 执行账本与测量设计；暂不把新的 fused 表达和 host 重标定捆成一次改动。

- 主计时保持 `execute()+synchronize()` 的墙钟时间。将提交、实际 GPU 通信/GEMM、依赖等待、最终同步放到执行依赖图中，不能直接相加各段持续时间而重复计算重叠。
- 对短 K 比较逐源与合并执行，检查启动次数、准备工作是否进入计时、实际 GEMM M 以及选定算法。现有 20/200 预热对照不能解释旧漂移，也不支持继续只靠加预热解决。
- CUTLASS 的已知 tile/mainloop 与 cuBLASLt 的库策略分开表示。算法 ID 只作为身份，不能作为有大小意义的数值特征；只允许使用计时前可获得的配置，不允许从目标耗时反推算法。
- 没有阶段观测时，提交成本、通信服务、kernel 时间及等待的单独系数不可识别，就明确输出“未识别”，不增加四个自由参数去拟合一个总时间。

后续 GPU 诊断保持原主计时，并另做少量隔离采集：提交/同步边界、各设备实际事件时长、通信/计算与依赖的时间线，以及相同 kernel 的隔离 GEMM。多 GPU 的独立事件时钟不能直接拼成全局时间线；隔离 GEMM 与端到端差值也不能直接称为通信开销。只有时间线指向具体资源限制时才加相应硬件计数器；诊断数据与无 profiler 的验收计时分开。

### P3：评价最终选择，不再只优化平均拟合误差

交付统一回放报告与下一轮冻结清单。

- 比较旧 `row_service`、当前 `regime_max`、`residual_depth`、上述有限修订，以及固定合并 CUTLASS、固定合并 cuBLASLt、固定“两种合并 host”、训练阶段确定的固定顺序和等预算随机选择。
- 全部使用相同形状与候选支持集，报告缺口；优先看最坏选择损失、严重错序、逐形状表现，再看平均误差。host/fused 判断保留双向比较，不能靠永远选 host 掩盖表达错误。
- 主预算固定 k=2；k=1 和 k=3 作为已声明的补充，不从测试结果中挑最好看的预算。保护 host 时它占据预算，不能免费附加。
- 实际策略的选优计时和验收计时使用不同区组。预测时不读实测标签；近似平局标为待测，不把 softmax 或分数差当真实概率。
- 完整计算特征提取、预测、编译、预热、测量与选择成本。候选减少、理想 top-2 回放通过，都不等于实际节省 GPU 时间。

## 3. 本地与 GPU 的验收界限

本轮数据已经参与方案设计；后续用于开发后，不能再次当独立测试。第一套、复跑、质量异常和附加基线保持独立身份。原冻结目录及验收门槛不改写。

| 检验 | 本地交付要求 | 不通过时的处理 |
|---|---|---|
| 数据与计数 | 原始哈希、候选身份、输出语义、计时边界、覆盖表可核对；异常原样保留 | 先修数据合同，不拟合 |
| 稳定反例 | M256 q8/q2 与大 N q4g2/原 host 在完整形状留出中方向正确；M 增长序列逐点展示，不以强 host 获胜遮盖 fused 内部错序 | 标明修订无效，进入针对这些反例的诊断 |
| 旧结果退步 | 旧/新环境分别做整形状留出和 M、N 分组检查；按相同支持集比较，平均与最坏选择损失均不得以跨环境平均掩盖退步 | 不晋升；保留反例 |
| 原预测门槛 | 保留形状平均误差≤10%、最大候选误差≤25%、无损失>10%的错序；必须同时看完整集和固定质量规则下的子集 | 不获得自动首选资格 |
| 候选筛选目标 | 新目标：k=2 在评价子集中保留耗时距已测最优≤5%的候选；与“两种合并 host”对比 | 目标是今后标准，不回写为本轮已通过的性能保证 |
| 工程可终止性 | 单次求解保留 10 s 上限；整次本地实验 15 min 上限，逐折保存进度；失败显式返回，不能把超时结果当通过 | 缩减诊断或优化求解实现，不在服务器上调试遍历 |

上述是研发门槛，不保证靠现有数据必然通过。留形状验证中的某一库若训练覆盖不足，应标记不可评价，不能临时借入被留出的标签。选择最终修订使用开发证据，最终性能主张仍需冻结后的新测试。

下一次 GPU 包分为两条用途明确的路径：

1. **机制仍不清楚：** 只运行反例附近的阶段诊断与少量对照，不启动大范围标定；诊断结果属于开发数据。
2. **本地修订通过：** 冻结源代码、表达、参数、候选、形状、质量规则和预算，再做独立选择验证。新的形状先定后测，所有候选完整覆盖；若读了结果后再修改，该批立即转为开发集，不反复充当测试。

两条路径都先完成本地正确性与有界执行检查。继续沿用本轮旧 runtime 才能直接复查原反例；若切换后来修复的 runtime，先单列执行语义与兼容性验证，另建标定身份，不能直接沿用旧参数或把性能差异归功于模型。硬件继续按原四卡 A100/NVLink 范围，不扩展新架构。

## 4. 论文主张与停止条件

可继续研究的是执行组织的适用边界、可检查的成本表达，以及强基线之上的有限候选选择。当前不能写“融合普遍加速”“跨模型 serving 泛化”或“模型已可靠自动选择”。

若强 host 已消除已测空间中的可用收益，就转向融合适用边界与失败分析；若固定“两种合并 host”与新模型效果相同，不声称新模型必要；若旧模型达到相同筛选效果，不声称新增表达带来选择贡献。若选择成本在合理复用次数下不能摊销，不声称部署收益。

本轮先完成 P0，再进行一次 P1 的受控修订；P2 的执行账本可在本地同步整理。是否需要下一次 GPU，由缺失的阶段证据决定，不由继续调参的轮数决定。
