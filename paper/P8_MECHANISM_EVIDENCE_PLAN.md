## 1. 我们能提出什么贡献

主问题：在固定单机 NVLink 通信条件下，交付与消费远端输入时哪些延迟仍暴露在完成路径上，tile 几何、资源服务和执行依赖如何改变这些延迟；能否据此选择总成本更低的物化或直接读取方案？

| 内容 | 当前证据 | 创新强度与缺口 |
|---|---|---|
| g 增大同时减少 A 的逻辑重读和每次 launch 的 CTA 数；q 增大恢复网格并改变 K 分片深度、串行归约 | 源码计数与条件不等式已推导；历史比较有反例 | 是具体映射的分析结果，不能声称首次发现复用/并行度权衡。需要硬件中间量与未见形状上的边界预测，才能成为主要方法贡献 |
| 区分每源/合并 host、新旧依赖策略、P4/P8 的执行账本 | 静态核对和历史回放已有证据 | 执行身份管理是可信实验基础；修复多余依赖本身不等于通用新算法。要证明不同执行身份如何改变时间与排序 |
| 物理结构约束的有限候选筛选 | 旧数据回放已改善；新 runtime 与合并 host 未获得对应模型验收 | top-k、非负拟合、计入调优成本均非独立新概念。只有相对固定策略、两种合并 host 和同预算搜索的净价值成立，才能写成方法贡献 |

相对 Ernst/Warpspeed，我们新增的研究对象是跨 GPU peer 访问、串行 split-K、执行依赖及 materialize/direct 的选择；对方对缓存/事务中间量的验证比我们充分。对象不同不能直接推出原创性或优越性。FLUX、TileLink、COMET 已覆盖融合、细粒度重叠与资源权衡，不能将这些宽泛表述作为本项目创新。

正文围绕一条待完成的贡献链：**通信暴露的执行机制、可验证代价边界，以及模型选择的实际价值**。计数、诊断工具与历史失败分析作为支撑材料。强 host 若消除全部可用收益，保留边界与负结果，撤回系统加速主张。

## 2. 最小机制证据

四个历史假设归入三个连续问题：路径比较（H4 加固定粒度流水化）、consumer 的联合服务（H1/H2）、完整依赖与完成时间（H3）。不增加一套彼此无关的预测任务。流水化还需报告“是否出现并行区间、是否降低完整耗时、是否牺牲 GEMM 效率”；三个判断分别记录。

| 编号 | 待验证假设 | 必须记录/控制 | 能否否证 |
|---|---|---|---|
| H1 | grouped-N 的逻辑字节节省未全部转成物理访问节省，或节省被并发下降抵消 | q 固定的 g1/g2；编译寄存器、shared memory、理论驻留上限；实际活跃 warp/CTA、内存等待；若可获得，L2/DRAM 与 peer 链路读流量及精确口径 | 若物理流量不降，不能归因为“节省 NVLink 字节”；若资源/并发未下降，不能归因为“CTA 减半导致吞吐减半” |
| H2 | 增大 q 缩短 K 主循环，但引入 serial split-K epilogue/同步代价，解释 M256、M512 的不同排序 | 固定 g 的 q 对照；相同 kernel 的本地 A 与 peer A 对照；记录输出/同步访存及可用的指令或等待证据 | 单看 q 的总时差无法隔离归约成本。没有专门等待观测时只报告综合 split-K 代价，不声称 semaphore 已定位 |
| H3 | P4→P8 的部分误差来自执行依赖/提交的变化 | 同一形状/输入/二进制配置比较新旧依赖策略；CPU API 与各 GPU 的时间线，GEMM 次数、空隙、重叠和结束时间 | 单位权重 DAG 深度不是实测关键路径。图变短却时间不降时，不能继续以链长作唯一原因 |
| H4 | 旧 host 太碎，合并的收益来自执行组织与 GEMM 利用率 | 同一 NCCL 路径下逐源 CUTLASS vs 合并 CUTLASS，再比较合并 cuBLASLt；计时含完整数据准备/通信/计算/同步，记录算法与 workspace | 同库比较仍同时改变 GEMM 行数、launch 数和布局，不能把全部差值指定为 launch 开销；用时间线/本地 GEMM 支撑分解 |

延迟限制与吞吐限制的切换归入 H1/H2。需要独立改变可在途工作量的有界访存实验，并在实际 GEMM 的同 q/g 对照中确认关联。单 warp pointer chasing 是依赖链延迟，不能直接当作 Tensor Core GEMM 的有效 peer 延迟；CTA 数不等于在途事务数。

沿用 Ernst 的“中间量替换”诊断：保留原计数预测，另用独立测得的流量/资源信息检查排序是否改善；若仍错，继续检查时间组合和执行依赖。逻辑字节与物理事务不能直接替换到旧拟合系数中。替换表达、单位和独立服务率来源需先声明；这种事后诊断也不属于独立测试成绩。禁止从同一个总耗时反算带宽，再以该带宽解释该耗时。

## 3. 与已有八卡包共用的配置

原包包含 8 个历史开发形状、每点 13 个主候选、13 个额外旧策略对照，共 117 配置/351 进程；无 profiler 计时仍是主结果。这些形状均不能重新标为独立测试集。

最多四个机制重点，均来自现有 8 点，不另开大矩阵。下表形状顺序为 M/K/N，P 固定为 8。

| 重点 | 形状 | 直接复用的对照 |
|---|---|---|
| 大 N/grouped-N | 64/4096/2048 | (q,g)=(4,1),(4,2),(8,2)；已有新旧 q4g2 策略对照；三种 host |
| K 耦合/迁移 | 64/8192/1024 | (8,1),(8,2),(16,2)；同时复用 64/2048/1024 的同 q/g 无 profiler 结果，构成同 M/N 的 K 对照 |
| M256/split-K | 256/8192/512 | (2,1),(8,1)；不预设 q8 一定更快 |
| M512/串行代价 | 512/8192/512 | (8,2),(16,2)；已有新旧 q16g2 策略对照 |

三角比较 (q,1)/(q,2)/(2q,2) 同时改变 K 深度和 tile 资源；只能检验联合预测，不能称为“只恢复 occupancy”的纯控制实验。

新增诊断按以下顺序准备，不改写原封存包：

1. **先补固定粒度的流水化机制对照。** 复用大 N `(8,64,4096,2048)` 与 M512 `(8,512,8192,512)` 两个点，固定 `chunk_rows=M`、`buffer_count=2`、每源 M 行 CUTLASS consumer，不搜索 chunk/q/g。以同一 pipeline 图构造流水版与加入串行约束的控制版，保持块粒度、buffer、传输顺序、kernel、数值与计时边界相同；不能直接拿旧全量 staging 的耗时当这个控制组。2 点×2 策略×3 独立进程，共最多 12 次计划主计时。现有 `build_pipelined_program()` 只是实现入口；新控制图、CUDA 检查、计时与身份登记尚待完成。它是额外诊断组，不能静默将历史 11/当前封存 13 个候选改成 14 个，也不能免费加入候选预算。
2. **最多 6 条时间线。** 大 N 的流水版/串行控制、大 N 两种合并 host、M512 新/旧 q16g2。用前两条替换原计划的大 N 新/旧 q4g2 时间线，控制诊断总量。若流水版未准备好则记录缺失，不能用合并 host 冒充。`trace` 的单条 180 秒上限与完整循环仍需改为受总预算约束的独立诊断入口。
3. **最多 6 个本地/远端 kernel 计数器样本。** 大 N 三角对照×本地/peer A；本地 A 预拷贝仅用于隔离诊断，拷贝成本单列。编译资源可覆盖现有目标，计数器只采这几个点。时间差不直接等于 peer 通信时间，单个 kernel 时间线不能量出内部 overlap。

同机 P4/P8 缩放保留为后续优先级，不挤占上面三个缺口的窗口：若预算和适配允许，以大 N 的 `(8,64,4096,2048)` 为锚点，用 `(4,64,4096,2048)`、`(4,128,4096,2048)` 控制固定 M 与固定 PM，仅用 q4g1/q4g2/q8g2 和两种合并 host，共 10 配置×3 区组。现 P8 runner 会拒绝 P4 身份，需另行准备。未完成时明确记录为未测。

以上增补均须在租机前准备好；不因诊断失败在 GPU 上临时开发，不启动无界 ncu 扫描。保留计数、联合执行观测和选择结果三种证据；任何缺项都不从总耗时反算补齐。

## 4. 一小时内的优先级和停止条件

原授权保持 $15 且不超过 1 小时，采集截止第 45 分钟，回收/校验后目标第 55 分钟前 Stop。实际小时价变化时按两种上限中更早者停止。

拟定时间分配：环境/编译/数值检查 0–12 分钟，主计时 12–30 分钟，诊断与同机对照 30–40 分钟，40–45 分钟只完成已开始的区组与落盘。此为预算分配，未实测编译和进程启动速度，**不是全部完成承诺**。新版本需按完整形状区组安排优先级；不能通过减少失败候选/丢弃慢样本凑出好结果。

优先取得四个机制重点的完整主候选数据，然后保留诊断窗口，再补其余已有点。缺项、超时、计数器权限与质量异常单独登记。本轮不叠加原计划的 12 个新评价形状或真实 MoE；它们仍是后续冻结验证与收尾阶段。当前 351 次主进程加诊断是否能全部完成，以预检吞吐和剩余时间为准，不能默认一小时足够。

硬件计数器先查询可用指标和权限，不预设 A100/Nsight 一定提供 NVLink 逐 kernel 字节数。DRAM 字节、L2 sector、peer 链路字节分别保存，不能互相替代。记录源/目的 GPU、读/写方向、采集范围、重放方式与缓存控制。若多 GPU 依赖被重放/串行化破坏，改用隔离诊断或记为不可测；不将失真的结果用于结论。参考 [Nsight Compute Profiling Guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html)。

所有主计时关闭 profiler，诊断时长不能导入训练标签。CUDA event 只作同一 GPU 内的时间测量；跨 GPU 用可对齐的时间线和 CPU 全流程边界，不直接相减不同设备事件。不把异步阶段耗时相加成总耗时。

## 5. 验收与模型回填

- 正确性、执行身份与完整计时优先；任何错误配置不进入性能排名。
- 路径/流水化比较及 H1–H4 每项交付“支持/反对/证据不足”，附原始记录；不以所有假设成立为通过条件。
- 新旧依赖策略分开报告；旧 `ScaleAwareModel` 的拟合系数只适用归档策略。新增 host 候选需要自己的模型适配，不能免费加入旧 11 候选评分。
- 若指标表明缺少机制，本地进行一组预先限定的表达修改；把当前 8 点记为开发数据。下一轮冻结形状才承担独立验证职责。
- 选择价值仍需对比：固定候选、两种合并 host、同预算搜索与已测集合 oracle。计入校准、预测、编译、预热和选优成本，报告复用次数下的净收益。
- 合并 cuBLASLt 目前只取一个启发式算法，合并 host 仍用逐对 NCCL 提交；它们是重要增强基线，并非“全库最优”。后续真实 MoE 至少用原生引擎，并核对一个可比公开融合实现。FLUX 仓库已有 SM80 构建入口，不能仅以使用 A100 排除；需检查 AllGather/All-to-All、路由、布局及精度语义。不能运行匹配对照时，收紧性能主张。

## 6. 可复用的 benchmark 与最短阅读清单

Ernst 的 stencil/LBM 应用不能直接充当我们 All-to-All–GEMM 的任务基准，也不能用其公开 A100 时间拟合 peer 成本。可复用的是分层诊断方法和独立硬件微基准。当前未导入或执行对方代码。

| 材料 | 本项目借鉴的具体部分 | 限制 |
|---|---|---|
| [Warpspeed](https://github.com/te42kyfo/warpspeed) / [Ernst 正文](https://arxiv.org/html/2204.14242v1) | 地址/访存估计与最终性能模型分离；中间量实测替换 | 不直接支持我们完整多 GPU 候选语义；需逐项适配，不适合作为无需改造的预测基线 |
| [RRZE gpu-benches](https://github.com/RRZE-HPC/gpu-benches) | gpu-latency、gpu-stream、gpu-l2-stream 的延迟/并发/缓存测量设计 | gpu-latency 原实现是本地访问；gpu-stream 原实现是本地 streaming。不是 NVLink/LSA 测量。原始循环很大，复用前固定 commit、许可证、范围、种子和超时，保留补丁 |
| [Hong & Kim, ISCA 2009](https://faculty.cc.gatech.edu/~hyesoon/hong_isca09.pdf) | 用 memory warp parallelism 区分延迟隐藏与带宽限制 | 只借鉴结构；旧 GPU 常数及执行细节不迁移到 A100 |
| [NeuSight, ASPLOS 2025](https://arxiv.org/html/2407.13853v3) | tile/利用率/整算子分层，未见形状和硬件验证 | 有学习部分；不要求照搬训练或宣称其数据包含 peer GEMM 标签 |
| [COMET, MLSys 2025](https://proceedings.mlsys.org/paper_files/paper/2025/hash/e27ea0cd50b798ff8942caf9203f0992-Abstract-Conference.html) / [TileLink](https://arxiv.org/html/2503.20313v3) | 资源划分、MoE 语义、融合 prior art 和消融设计 | 对齐任务后才能直接比较；两者已覆盖宽泛的资源权衡叙述 |
| [Entwine, 2026-09 预印本](https://arxiv.org/html/2609.11562v1) | 计算顺序/通信粒度/资源预算的消融；独立与并发通信的区别 | 已核对版本是预印本，文中表示发表后开源；任务为 GEMM–ReduceScatter，不能冒充我们的可直接运行基线 |

本轮最优先精读 Hong & Kim 的 MWP 机制、NeuSight §3–4、Entwine §5.3–5.4；Ernst 继续作为证据组织范本。补文献不增加新模型、新卡型或新实验方向。
