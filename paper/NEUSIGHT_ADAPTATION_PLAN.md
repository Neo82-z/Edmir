# NeuSight 对本项目的具体启发

**同日后续审查：**[三个 host 误选诊断](../experiments/2026-10-28-host-decision-audit/README.md)发现线性路径比值限制、100 轮训练不足，以及 M512 无约束外推曲线反向。恢复逐折经验代价底座后，三个原 host 优势点均可选对；受限残差平均/最坏损失为 0.48%/7.36%，仍有一个反向误选，且纯底座平均损失更低（0.36%）。全部 M512 留出仍未通过。六个冻结形状及协议不改，新模型只作开发修订，不能冒充独立验收成功。

**2026-10-28 更新：**已落实[形状评价闭环与共享候选评分](../experiments/2026-10-28-shape-evaluation/README.md)：四点机制诊断保留，六个未有新标签的边界形状冻结，真实 MoE 统计接口实现。小型共享决策网络的历史开发试验平均损失 1.89%、最坏 19.62%，三个 host 优势点仍误选，未准入编译器。冻结的是协议，最终模型、binary 和执行环境尚未冻结；真实 MoE 尚无 trace。以下几何、服务和依赖分层继续成立，训练改善不能替代机制证据。

## 当前主线（2026-10-27）

> 在固定单机 NVLink 通信条件下，交付与消费远端输入时哪些延迟仍暴露在完成路径上，tile 几何、资源服务和执行依赖如何改变这些延迟；能否据此选择总成本更低的物化或直接读取方案？

正文从这个问题开始，以“通信约定 → 三种执行路径 → tile/wave 几何 → 共同执行时的资源服务 → 依赖汇总 → 候选选择”组织。选择损失是最后的应用检验；总耗时拟合改善不作为 overlap 机制证据。NeuSight 提供分层方式，本项目仍须自己识别 FP16 peer 访问、serial split-K 和流水化 staging 的服务代价。

通信约定集中声明单节点 P4/P8、NVLink/P2P、均衡固定输入、源端 activation 与目的端 weight、输入上传完成，以及包含通信、计算、提交和完成等待的全算子计时。历史 runtime 的执行身份单列，PCIe、跨节点和上游实时生成 activation 不在已验证范围。

三条路径在正文第一张图并列：先 staging 再 GEMM、按就绪块流水化 staging/GEMM、GEMM 直接读 peer。合并 host 改善计算粒度，不能替代流水化基线。原有加法公式降为“通信完全暴露”特例；现有 max/min 拟合中的分支和系数不解释为独立通信/计算时间或实测重叠比例。

本轮交付的是正文和验收结构修订。几何表示与条件 DAG 汇总沿用已有实现；服务证据、流水化匹配结果、完整 wall-time 预测仍未补造。下一轮只沿原四个重点形状补证据；流水化对照限定两点、固定块粒度，具体版本与预算见 [P8 机制计划](P8_MECHANISM_EVIDENCE_PLAN.md#3-与已有八卡包共用的配置)。

## 1. 采用哪部分思路

它对我们的价值主要在于：把执行几何、资源上限、利用率和整算子汇总分开；用未见模型与硬件检查外推，并在同一数据条件下比较预测基线。我们继续采用小规模、可检查的表达。新增数值共享评分头借鉴 Laya 的候选决策思路，不复制 NeuSight 的模型权重或 FP32 服务率，也不声称复现 Jev 未公开的训练配方。

| 层次 | NeuSight 的做法 | 本项目需要保留或补齐的表达 |
|---|---|---|
| 几何 | 从 tile 大小和 block 数计算执行波次数 | 明确保留输出 tile 数、q、g、每片 K 迭代、边缘有效比例及尾部；不能只用一个截断的网格不足项 |
| tile 服务 | 用硬件能力归一化，并学习资源利用率 | 先区分本地计算、peer 访问、串行累加与等待；服务率需有对应测量，逻辑字节不能冒充 NVLink 实际字节 |
| 汇总 | tile → 算子 → 用户指定的模型/分布式执行安排 | 区分单个 GEMM、每目的 rank 的 P 个源块及完整程序；按实测或可验证的依赖汇总，不能把单位权重 DAG 深度直接当时间 |
| 验证 | 训练设备之外的设备和模型；比较 Roofline、Habitat、Li 等 | 固定执行身份内做整形状留出，再单独报告 P4→P8 或 runtime 变化；不因此扩展到新卡型 |

其通用大网络外推失败的实验支持“结构值得检验”，不证明任何小模型必然准确。其分布式支持也不等于已经建模我们的 LSA peer consumer、serial split-K 或合并 host。

## 2. 已完成的本地表达审查

运行入口：`EDM-IR/tools/audit_prediction_geometry.py`。输出：[审查记录](../experiments/2026-10-26-neusight-geometry-audit/audit.json)和[几何表](../experiments/2026-10-26-neusight-geometry-audit/geometry.csv)。读取 599 条历史记录，分析其中 535 条 fused 候选，执行约 0.015 秒；没有使用耗时标签进行判断，没有拟合或 GPU 执行。

当前 `scale_aware_prediction.py` 的网格项是 `max(1 − Γ/108, 0)`。535 条记录中有 65 条 Γ≥108，此项均为零。其他项仍可能间接区分网格，因此仅凭这一现象不能断言整个模型看不到 Γ；下面的完整特征碰撞才证明具体缺口。

固定 P=8、q=8、g=2，构造两个合法形状（顺序 M/K/N）：

| 形状 | 每次 GEMM 的 CTA 数 Γ | 输出 tile 有效比例 | 一 CTA/SM 的参考轮次 |
|---|---:|---:|---:|
| 32/8192/8192 | 256 | 0.5 | 3 |
| 64/8192/4096 | 128 | 1.0 | 2 |

二者的 MN、K/q 和 M×K×N-tile 数相同；P、q、g 及其图深代理相同；网格不足项均为零。因此**完整的八维 fused 特征相同，在同一个拟合模型内无论怎么调系数都只能预测相同耗时**。另一个 q8/g1 的构造例也出现碰撞。历史数据内另有 8 组相同特征、不同边缘有效比例的记录。

这些结果只证明表达不能区分某些执行几何，**没有证明这些形状实际耗时不同，也没有定位 M512 或大 N 的既有误选原因**。掩码 tile 可能仍执行相同指令；参考轮次不是实际调度波次，不能据此声称耗时为 3:2。

## 3. 按三个方向实施

本轮已经实现本地表示、条件依赖汇总和开发划分检查。入口为 `EDM-IR/tools/prepare_tile_model_revision.py`，实现为 `EDM-IR/edmir/compiler/tile_execution_model.py` 与 `structured_validation.py`。它们复用现有执行账本，不替换已归档的 `ScaleAwareModel`，不改变封存 GPU 包。[本地交付记录](../experiments/2026-10-26-tile-model-revision/README.md)列出运行结果与剩余条件。

### 方向一：保留能区分执行几何的表示

定义 `O=ceil(M_GEMM/64)×ceil(N/(128g))`、`Γ=qO`、`D=K/(32q)`、`f=M_GEMM×N/(O×64×128g)`。逐源 GEMM 的 `M_GEMM=M`，合并 CUTLASS 的 `M_GEMM=PM`。库内部未知的 cuBLASLt tile、CTA、轮次保持未知，不能套用 CUTLASS 的计数。

新表示明确保留 M/N tile 数、O、Γ、D、边缘有效比例、末 tile 行列数、有效工作量、按 tile 填充的参考工作量，以及每输出 tile 的 q 级 epilogue 顺序。参考工作量不等于已执行指令数。以前的两个完整特征碰撞现在可由这些字段区分；这只通过表示验收，不构成耗时预测准确率验收。

轮次和尾部采用显式容量约定：若参考容量 `S=SM×r`，`W=ceil(Γ/S)`、`last=(Γ−1) mod S + 1`。Γ 恰好整除 S 时，最后一轮是满轮而非零。默认输出 r=1 的参考值；实际静态驻留上限另传，必须注明构建来源和执行身份。未知 r 不填估计值。

**验收**：小规模独立 tile 枚举与闭式计数一致；107/108/109/216/217 个 CTA 的跨轮边界正确；q 不改变唯一输入工作量；合并与逐源 host 身份明确。serial split-K 的 q 个 CTA 共享输出累加依赖，参考轮次不得直接乘成最终耗时，也不能宣称是实际 occupancy。

### 方向二：将服务证据与执行依赖分开

表示中分别登记本地计算、peer 访问或 staging 传输、串行 epilogue/等待、CPU 提交与完成的证据缺项。计数具备作用范围和单位；未知服务时间为 `null`，不以零或旧拟合系数代填。

已实现基于真实执行图的条件汇总：调用者提供同一执行身份下每个完整操作的非负耗时，再按 `finish(v)=duration(v)+max(finish(parent))` 计算依赖跨度。它不是内部阶段模型；不能把单独测得、可能相互重叠的计算/通信阶段直接相加后当成操作时长。新旧依赖策略分别使用自身的图。

该接口检查缺失节点、未知节点、负值、NaN/Inf、环和身份不符，并限制图遍历规模。缺少任一节点耗时时不返回跨度。即使全部节点齐全，仍只给**给定节点耗时与依赖条件下的跨度**；资源竞争、CPU 空隙、完成开销未识别时，程序墙钟预测仍为 `null`，不能拿它宣称实测上下界或系统加速。

**验收**：合成单位权重下，P8 的独立目标队列得到 8 级跨度，旧资源队列图得到 33 级；这只是图结构测试，不是 33/8 的加速预测。节点和边重排不改变结果；缺项不会以零成本参与比较。真实服务率、占用率及 semaphore 暴露时间仍须 GPU 证据。

### 方向三：固定消融问题、数据分组和停止条件

保留三种结构比较，新增自由参数和公式必须在独立评价前写明：

| 版本 | 改动范围 | 当前状态 |
|---|---|---|
| A | 适配新执行身份的简单成本基线 | 尚未标定，不能偷用旧 runtime 的系数 |
| B | A 加入明确的 tile 几何、容量约定和尾部表达 | 表示已实现，最终时间组合与参数量待开发数据及证据约束 |
| C | B 加入独立证据支持的服务和依赖组合 | 条件 DAG 汇总已实现，真实服务时间未识别 |

本地计划只使用原有四个重点形状：P=8，M/K/N 分别为 64/4096/2048、64/8192/1024、256/8192/512、512/8192/512。每点保留三种 host 和十种 fused，共 52 配置；三个重复区组共 156 次**计划运行**。这是原八点包的重点子集设计，不是另一个已完成的采集，也没有新增必测形状。

已生成四折整形状开发划分：每折三个形状开发，一个形状评价，该形状的所有候选和重复始终在同一侧。检查器拒绝跨分区重复、候选缺项、重复记录、未声明候选和同一环境混用 P4/P8。它检查的是计划/记录的一致性，不会把计划区组认证为真实测量，也不会把已看过的四个形状变成独立测试。

**验收**：A/B/C 必须使用相同候选、开发形状、标定测量预算和选择预算；整形状划分对候选及记录顺序不敏感。每次拟合最多 10 秒、一次回放最多 120 秒，失败即记录，不自动重启无限搜索。这些拟合上限是已有求解器的约束，当前准备工具不调用拟合。最终公式、参数量和独立形状尚未冻结，因此当前不能宣布独立验证就绪。

若 B/C 未改善平均与最坏选择损失、同预算候选保留或中间量解释，就停止扩充表达并保留失败版本。强 host 消除可用收益时，收紧加速主张，不移除基线。

## 4. 评价如何对应论文

- 内层标定/模型选择按完整形状分组：所有候选、重复进程均留在同一分区。外层冻结未用于设计的形状；GPU 数或依赖策略改变时另列迁移实验。反复查看过的 19 个 P8 点仍是开发证据。
- 同时保留耗时误差、候选对方向错误、top-1 平均/最大选择损失、top-k 保留和摊销成本。不能因为平均 MAPE 下降就宣布选择变好。
- 固定强 host、两种合并 host 的预算内实测选择、训练确定的固定顺序、同预算搜索及已测集合 oracle 都保留。NeuSight 的预测模型比较不能替代这些部署基线。
- 下一次采集仍围绕现有四个重点形状，按 [P8 机制计划](P8_MECHANISM_EVIDENCE_PLAN.md)执行。上面的构造反例仅作本地代数检验，不追加必测 GPU 矩阵。独立形状评估和一个真实 MoE 仍按既定收尾顺序安排。
- 本轮已完成几何表示、条件依赖跨度和划分边界的本地检查；封存执行包、拟合系数、历史图表和 GPU 结论保持原样。实际并发、归约暴露时间、新 runtime 强 host 的排序仍需要 GPU 证据。

### 形状的用途与 NeuSight 的区别（2026-10-28）

NeuSight §6.1 的 BMM 标定范围是 batch 与矩阵维度 1–1024；FC 的 batch 为 1–8192、输入/输出维度 1–65536。论文报告的 87,627/32,256 是算子数据点数，不能当作同一 GPU 上独立形状数。其后另在真实模型和未参与标定的设备上评价。我们不复制其 FP32 标签或大规模采样。

现有 P4 是 41 个控制变量形状：M∈{32,64,128,256,512}、K∈{512,1024,2048,4096,8192}、N∈{128,256,512,1024,2048}，主要沿 N=512 的 M 切片和 M=64 的 N 切片采样，不是 125 点全笛卡尔积。P8 是 23 点，考察固定每源 M 与固定每目的 PM。当前四点来自历史问题，只承担机制诊断。

例如两个现有点按 M/K/N 记为 64/4096/2048 和 64/8192/1024：固定 P=8、q=1、g=1，单 consumer 的有用 FLOPs 都是 1,073,741,824，每目的端逻辑 peer 请求都为 58,720,256 字节；但 CTA 为 16 与 8，K 循环为 128 与 256。这说明仅看总工作量会遗漏执行几何，不证明两点实测耗时一定不同，也不是严格的单因素干预。

后续保持三类用途独立：原四点查机制；预先冻结未用于设计的形状检验边界；一个真实 MoE 提供实际 expert token 数、投影维度与出现频率的应用证据。现有 M32 或 N128/g2 已有部分边缘 tile，但并不构成系统的 wave/tail 边界覆盖。新增边界点须先检查 kernel 合法性与预算，不借此扩展为全网格扫参。没有新的 GPU 采集或冻结测试集。

## 5. 源码与数据复用的三个注意点

**维度命名不同。** [`collect.py`](https://github.com/scai-tech/NeuSight/blob/6945927d9afcca2b9daf021f8395e53edc5b4eef/neusight/Dataset/collect.py) 的 BMM 是 `[B,M,N]×[B,N,K]`；我们的约定是 `[M,K]×[K,N]`。因此 `M_ours=M_src`、`K_ours=N_src`、`N_ours=K_src`。B 是独立矩阵批次，不是通信 rank 数 P；其 linear 还带 bias。公开 FP32 数据不能直接作为本项目 FP16 peer 候选标签。

**波次不是完整物理模型。** [`mlp_wave.py`](https://github.com/scai-tech/NeuSight/blob/6945927d9afcca2b9daf021f8395e53edc5b4eef/neusight/Model/mlp_wave.py) 明确计算 `ceil(num_block/num_sm)`；[`mlp_wave_mm.py`](https://github.com/scai-tech/NeuSight/blob/6945927d9afcca2b9daf021f8395e53edc5b4eef/neusight/Model/mlp_wave_mm.py) 再结合 tile 操作量和访存量。其利用率实现是两个 sigmoid 输出相减的 `gamma−alpha/num_wave`，表达式本身未保证严格为正；不代表已发布权重实际产生了负值，但说明复用时仍需自己检查数学边界。

**随机验证与外部测试不是一回事。** [`trainer.py`](https://github.com/scai-tech/NeuSight/blob/6945927d9afcca2b9daf021f8395e53edc5b4eef/neusight/Model/trainer.py) 内部使用 80/20 随机划分、AdamW 和配置的损失；论文另外设计未见 GPU/模型测试。这不构成对论文泄漏的指控。我们的同形状多候选强相关，内部随机行划分不能照搬，应改为整形状分组。无需下载大型 artifact 或启动训练才能完成本轮借鉴。

最短阅读顺序：正文 §3–4（结构理由）、§6（划分和基线）→ `mlp_wave.py` → `mlp_wave_mm.py` → `collect.py` / `trainer.py`。源码是参考材料；本轮审查脚本未复制上游实现。
