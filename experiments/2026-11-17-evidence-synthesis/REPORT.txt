EDM-IR 已采集数据综合分析与论文结论边界
2026-11-17

本次结论

现有数据支持“执行方案有实际收益，但几何计数不足以可靠决定最优候选”，不支持“预测器已经能普遍选对”。最强的证据是归并精度、基线身份、q/g 联合效应以及平衡顺序复测；最弱的是独立形状泛化、host 优势区域的双向判断和真实 MoE/serving 代表性。

最后一轮误选不是 Python 排序或候选遍历错误，也不是当前回归求解器没有收敛。现有证据指向：执行成本表达及其跨形状迁移有偏差，点式回归目标没有直接约束局部候选顺序，而开发数据没有覆盖关键的 K×N 变化与 host 获胜边界。不能据此唯一归因于某个损失函数，更不能断言换 Muon、加网络宽度或多训练就会解决。

按约定，预测器与候选实现继续封存。本次没有训练、调参、修改生产代码、上 GPU 或租用资源；不使用六个冻结形状的标签，不改变其协议。没有按结果剔除失败或漂移样本。

历史组件数据也揭示了早期成本迁移的边界：36 组匹配独立 GEMM 中，cuBLAS 均快于固定 CUTLASS 内核，CUTLASS/cuBLAS 延迟比中位数为 2.01，范围 1.55–2.65。这不是“CUTLASS 总是更慢”的结论，而是不能用一个固定内核代表整个库实现的证据。独立 GEMM 用 FP16 和 CUDA event 计时，NCCL-Test 用 FP32、单独 collective 计时；它们不能直接相加或取 max，就当作 FP16 整程序 fused 延迟。公共 benchmark 同理，只能在明确兼容条件后提供组件参考，不能替代本项目同执行身份的候选标签。

最优已测 q2 对本轮较快 host 的比值为 1.877×；封存选中的 q8/g2 对该 host 约为 1.814×。前者是已测候选最优值，后者是已选候选的描述性收益，都不是 vLLM 加速，也不是自动编译器已经通过新会话准入的证明。

11 月 16 日 large_n 汇总最快为 q4/g2，封存选择损失 3.05%；11 月 17 日汇总最快为 q2，损失 3.48%。源码/构建及主要库身份相同，但实例和测量协议变化，动态 GPU 状态未被证明相同。这里没有“新版模型退步”的对照，因为模型没有修改。

三、是排序、分类，还是训练方式的问题

1. 候选枚举顺序：未发现问题。
对六候选的全部 720 种排列分别检查两个封存评分版本，共 1440 次，候选分数、排除结果和选择完全一致。实现按 candidate_id 固定处理，平局有固定规则。
这排除了当前评分器的位置偏好，不等于排除了 GPU 执行顺序的影响。平衡顺序后的误选仍存在，说明不能把它全部解释成先测谁、后测谁。

2. 当前不是独立的 host/fused 分类网络。
实际模型先以数值正确性及执行身份决定候选是否准入，再对所有可用候选共享打分，最后取最小值。host/fused 是 argmin 的结果，不存在单独训练的二分类器。
近期四个形状的最佳已测候选全是 fused；“永远选一个 fused”也能在这四点取得 100% 的类别方向命中。故不能据此宣称双向判断能力好。旧 P4 上三个 host 优势点，历史 linear_latency、linear_decision 和 mlp_decision 三种模型全部误选 fused；该失败仍保留，但它们不是当前 W1 执行身份下的测试。

3. 当前求解没有“不收敛”的证据。
封存 W1 评分器是标准化特征上的对数耗时岭回归：
  min_theta sum_i w_i [log(T_i)-z_i·theta]^2 + 0.01||theta_without_intercept||²。
每个形状等权，形状内部 host 与 fused 各占一半权重；一次 np.linalg.solve 求解。original_geometry 有 31 个特征，coupled_geometry 有 44 个，均另加截距。它不是正在用 Muon/AdamW 迭代的神经网络。
本次只检查已有 theta，没有重新求解。八个封存折的正规方程相对残差均不超过 6.14×10^-17；加正则后的矩阵正定，条件数约 1234–2004。因此“当前目标没有优化到位”不是这些错误的合理主因。
这只证明该正则回归目标已被解好，不证明目标正确、特征充分或泛化可靠；也不能外推为历史所有神经网络训练都收敛。

4. 表达缺失有直接证据，但不能概括为参数量不够。
六对已通过数值检查的 FP16/FP32 归并候选在原 31 维特征下完全重合，FP32 实测却慢 6.64%–27.99%。相同输入不能产生两个不同的确定耗时预测，换优化器不能解决这一冲突。补入 FP32 部分和缓冲、最终转换调用等表达有明确理由。
但在耦合版本的大 N 留出折中，训练 fused 的未加权 MAPE 仍为 11.10%，host 为 4.11%。新增表达没有充分描述全部候选成本；回归残差集中在 fused，并不是只有测试形状出了问题。

5. 关键失败是局部排序外推，而非全局平均损失大小。
coupled_geometry 预测 q8/g2 为 470.07μs，q2 为 761.35μs，即 q8/g2 只需 q2 的 61.74% 时间。真实比值为 103.48%。模型不是对一个几乎平局的问题“略微猜错”；它给出了方向相反且幅度很大的相对优势。
该折训练形状的 K 全为 8192，N 为 512 或 1024；待测点却 K=4096、N=2048。缺少 K 方向变化，且 K、N 同时外推。重复采集这三个训练几何点不能补出缺失的变化方向。
q2→q8/g2 同时改变 q、g、每块 warp 数、K 分片深度、CTA 数、暂存需求和归并反馈。大 N 中 q2 每 GEMM 有 32 个 CTA、每 CTA 4 个 warp、64 次 K 迭代；q8/g2 为 64 个 CTA、每 CTA 8 个 warp、16 次 K 迭代。暂存下界由 36 KiB 变为 60 KiB，串行部分和逻辑反馈量由 0.5 MiB 变为 3.5 MiB。不能只用“CTA 变多、分片变短”判定收益。
这些是源码可推出的计数；CTA/SM 不是已测占用率，逻辑反馈/重放量也不是实测 HBM/NVLink 字节。

6. 计数进入回归后，并没有自动成为物理代价项。
大 N 的 q8/g2 相对 q2 的预测 log 比值为 -0.4822。代数分解中 q×output_tiles 贡献 -0.2023，n_tiles 贡献 -0.1599，log_q 贡献 +0.1593，serial_feedback_bytes 贡献 -0.0436。连“反馈量增加”都在这个联合回归中提供了更快的分数贡献。
这些数是相关特征下的代数归属，不能当作硬件因果重要性；负系数也不单独证明某个系数是 bug。但它明确说明：当前模型是可正可负的经验映射，不是由非负阶段服务时间组成、可逐项解释的执行成本模型。

7. 不把秩亏当成万能解释。
耦合版本每折 45 个系数，训练设计秩为 28；岭正则仍给出唯一数值解。更细查 q8/g2−q2 和 q8/g2−q4/g2 的特征差，训练零空间投影比例分别约 1.19×10^-9 和 6.63×10^-16，几乎为零。
因此，虽然绝对预测与部分系数存在识别限制，这两个具体排序差不能直接归咎于“任意零空间系数都能把名次翻转”。这里的证据更支持：在当前特征基底和回归约束下学到的候选对比关系，不能正确迁移到新的 K×N 组合。

四、损失函数和过去的神经网络尝试应怎样解释

当前目标优化逐候选 log 耗时拟合，不直接优化同一形状内的名次、首选命中率或选错代价。host/fused 各一半权重可防止候选数不平衡，但不会自动保证 fused 内部 q/g 排序正确。

旧 P4 41 形状的已存开发比较：
  linear_latency：平均选择损失 3.41%，最坏 19.62%，三个 host 优势点全部误选。
  linear_decision：平均 3.61%，最坏 28.21%，三个 host 优势点全部误选。
  mlp_decision：平均 1.89%，最坏 19.62%，三个 host 优势点全部误选。
它支持“平均损失改善未必修复稀少但关键的 host 获胜区域”，不支持“加决策损失一定有效”。这是历史开发集比较，不是三种方法的独立最终测试。

旧 P8 小网络审计中，留出 M256 时，AdamW 的训练 MAPE 为 0.0148%，留出 MAPE 为 24.51%；Dion3 分别为 0.0971% 和 29.03%。几乎精确拟合训练点仍未解决形状迁移。这是已有 AdamW/Dion3 记录，不是 Muon 对照实验，不能写成 Muon 无效。该历史结果也不能和当前 W1 岭回归混成一条训练曲线。

可能的目标选择，现阶段只能作方法讨论：
  点式耗时回归：保留延迟量纲，便于解释；不直接保障局部名次。
  成对排序：直接约束候选先后；微小、会换位的差异不宜当强标签，且无法补造缺失执行条件。
  one-hot 最优候选交叉熵：优化名次，但可能把 0.5% 的微小差异与巨大退化都当作一次分类错误。
  期望 regret：按损失幅度加权，但不等价于校准耗时；候选都测过才能计算完整监督。

若 p_j=softmax(-s_j/τ)，r_j=T_j/min(T)-1，L=sum_j p_j*r_j，则
  dL/ds_j=-(p_j/τ)(r_j-sum_k p_k*r_k)。
即使 s 已等于真实 log 耗时，该梯度通常也不为零：决策损失会继续压尖选择权重。它可能改善决策，却不能同时被解释成“预测延迟更准确”或“p 是最优真实概率”。这解释了为什么应分别报告回归误差、成对方向、首选命中、平均与最坏 regret。

现有记录不足以把最终错误唯一归因于 loss、正则或模型结构中的某一个，也没有同一 W1 数据/划分下完备的 CE、pairwise、cost-loss、Muon 对照。本次不新增这些训练，保留此限制。

六、能够写入论文的机制证据

A. 全量数值检查与归并精度是候选准入条件，不是速度模型的附带约束。
11 月 11 日、16 日各有 24 条数值检查失败，对应各自版本内十个形状×候选组合；都在计时和 oracle 之前排除，失败记录保留。M512 的既有 CPU 全输出重放在 q8 找到一个越阈输出，在 q16 找到 38 个；抽样检查可能遗漏极少量错误。阈值为 max(|out-ref|/max(1,|ref|))≤0.02，不能改写成普通 atol+rtol allclose。
11 月 16 日新增十六个 FP32 部分和实现×形状组合，三种子共 48/48 全输出检查通过。这支持该数值修复在已测输入上的有效性；不证明所有随机输入都正确。FP32 的成本必须按新的实现重新测量，不能借用 FP16 延迟。

B. 基线必须同时固定通信、GEMM 组织、精度、metadata 和计时边界。
11 月 11 日，将旧逐源 host 换为本轮较快的合并 host，本身就有 1.78–2.32× 差距。用弱 host 会显著放大 fused 收益。
以每批各自较快的已测合并 host 为基准：

grouped             q8/g2 / 1.911×               q4 / 1.686×
M512                q4/g2 / 3.079×               q4/g2 / 3.157×
large N             q2 / 1.741×                  q4/g2 / 1.825×

这些是各批内已测 oracle 的合成算子收益，不是模型选中收益。host 使用当前实现的 NCCL 分组和库启发式，不能称为所有可能 NCCL/DeepEP/库配置中的最强基线。

C. q 与 g 的效果取决于联合执行条件，不能从逻辑字节减少直接推出提速。
11 月 11 日 grouped 点上，g2 相对 g1 在 q=1 慢约 19–20%、q=2 慢约 13%，在 q=8 则降低延迟约 7.3–9.8%。同样的分组变换会随 q 改变收益方向。
M512 上 q4/g2 相对 q4/g1 降低延迟约 39.7–43.7%，尽管每 GEMM 的 CTA 数由 128 降到 64，低于 108 个 SM。这否定单独以 CTA 数或简单填充率排序的充分性，但并未唯一证明带宽、寄存器或调度中的某一项是主因。

D. 有限的 staged pipeline 收益已经测到，不能继续写成完全未测。
11 月 11 日配对实验中，M512 的 pipeline 相对同实现串行控制降低延迟 10.33–16.36%（三个区组），large N 降低 7.09–9.99%。其中位数比值分别为 1.162× 与 1.106×。
但该 pipeline 仍慢于已测合并 host/direct fused。它证明这个具体调度有收益，不证明生产级流水最优，也不是“隐藏了多少通信”的测量。主比较与 pair 阶段不同；只有 matched pipeline/serial 对照可用于这项局部结论。

E. 性能标签必须与 profiler 诊断分开。
11 月 16 日七份 trace 覆盖所有八卡和预期调用；诊断 capture 按三次执行归一后，是独立无 profiler 中位数的约 2.73–4.58 倍。这个比值含 profiler/NVTX 与诊断执行方式差异，不能用作通用校正系数。
trace 能说明调用顺序、事件和时间段，不能把 kernel 时间存在比例当作 SM 利用率，更不能分解内核内部通信等待。没有实际硬件带宽/争用计数器，因此保留“共享资源争用”等待验证解释，不伪装成已证明机制。

七、论文可以怎样写，哪些话必须删去或收窄

可以作为结果陈述：
  1. 在明确的 FP16、A100 NVLink、平衡 All-to-All–GEMM 条件下，执行组织与 q/g 改变会影响正确性和耗时；最优有效方案依赖形状和执行条件。
  2. 正确性门禁、实际 host 实现身份与统一计时边界是可比较性能标签的前提。
  3. FP32 归并修复了所测失败，同时引入可观成本；必须把归并精度作为候选身份/成本的一部分。
  4. 加入耦合和精度表达降低开发集严重误选损失，但未提高四点首选命中率，并仍有跨形状排序偏差。
  5. 最终平衡顺序复测保留了失败；host/fused 类别正确不意味着 fused 内部排序正确，低 regret 不意味着准确的收益预测。

不能以当前证据陈述：
  “预测器稳定优于简单规则”“已经解决双向 host/fused”“在未见形状上可靠泛化”；
  “整体加速全部来自 overlap”“实现了某个通信隐藏比例”“逻辑字节等于链路流量”；
  “四个合成点代表真实专家负载/真实 MoE 吞吐”“vLLM/模型质量得到提升”；
  “FP16 结果适用于 BF16”“八卡现象仅由 P 的变化导致”；
  “换 Muon 或增加模型规模就能修复现存错误”。

建议论文的主叙述是：从通信与计算依赖以及候选准入出发，给出可执行的候选空间、可信的比较口径和具有边界的成本选择方法；用数据说明何时得到收益、何时计数到耗时的映射失效。预测器作为有明确失败范围的组件，不再包装成近乎完美的普适调度器。
这比隐去失败更符合现有证据，但方法主张与泛化结论的范围需要随之收窄；不能据此承诺论文所有核心论点已闭环或达到某个期刊录用标准。
