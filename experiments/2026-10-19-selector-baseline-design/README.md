# 调度选择器与基线实验设计

下一轮研究编译器能否在相同语义、计时边界和合法候选集合内可靠选择实现。
当前先完成本地离线开发和公开数据审核，后续 GPU 工作分成最小核验、必要补测
和独立评估。下文完整 GPU 矩阵是候选范围，不是启动开发的前提或已确定的租机任务；
`interaction_results.json` 仅分析既有数据。
本轮范围是均匀 FP16 算子，与真实路由 BF16 的 D7 协议分开。

2026-10-20 的[数据审计与离线预测器修改](../2026-10-20-offline-predictor/README.md)
已整理来源、计时范围和固定候选基线。新相对模型仍有约 64% 的 P8 最坏选择损失，
尚不满足替换条件；后续需优先处理 grouped-N 在不同 M 下的覆盖缺口，
以及完整程序计时中的调度/同步开销。

后续的[特征耦合、grouped-N 范围和 host 身份整理](../2026-10-20-predictor-contracts/README.md)
已落实到代码。旧 relative 加范围限制后 P8 校准回放仍为 8.65% 平均 regret；
新的三分量拟合反而退步，没有替换旧模型。新独立协议在原 36 点网格上增加
M=64 的 9 个点，形成每个 P 的 45 点；同时区分旧 CUTLASS host、编译器
cuBLAS host、merged CUTLASS 和 merged cuBLASLt。冻结 JSON 是测量计划，
不代表已经实现新基线采集器或获得独立结果。

## 研究问题与判定原则

主问题：对当前均匀 FP16 All-to-All–GEMM，能否根据问题形状、实现信息和有限
硬件校准，在物化、流水线和直接远端读取之间可靠选择，并在计入额外选择成本后，
相对预先确定的强基线取得收益？收益范围和退化风险都需要独立评估。

| 问题 | 所需证据 | 需要收缩结论的结果 |
|---|---|---|
| 候选集合是否仍有优化空间？ | 在相同语义和计时边界下，比较强基线与已测候选中的最快实现 | 强基线消除原有收益，则重新界定融合的适用范围 |
| 选择器是否能取得这部分收益？ | 在独立形状上比较固定策略、原模型、改进模型和事后最优选择，计入额外成本 | 固定策略已相当，或调优成本无法摊销，则不能主张复杂选择器的必要性 |
| 提出的机制是否解释了差异？ | 固定其他因素的 q/g 对照、计时和独立采集的时间线/计数器 | 仅计数符合而性能不符合，只能保留计数恒等式，不能宣称性能机制已证实 |

用同一 workload 的三个耗时分开诊断：

- \(T_{\mathrm{base}}\)：开发或校准阶段确定的可部署强基线；
- \(T_*\)：同一已测候选集合的最小耗时，集合包含上述基线，仅作事后参照；
- \(T_{\mathrm{sel}}\)：选择器实际选中实现的耗时。

\[
T_{\mathrm{base}}-T_{\mathrm{sel}}
= (T_{\mathrm{base}}-T_*)-(T_{\mathrm{sel}}-T_*).
\]

右侧分别是可取得的收益和因选择失误损失的收益。前者很小与后者很大是不同问题，
不能统一归因于预测器。若额外选择或调优成本 C 尚未包含在算子计时中，复用 R 次
后的平均净收益还要减去 \(C/R\)，避免把免费事后最优选择当成部署效果。

后续讨论依次确定四件事：主张和反证条件；基线及公平比较规则；预测器输入、
校准和简单策略对照；独立矩阵、测量与补充实验。下文矩阵是讨论起点。
真实 MoE 路由、不同专家权重和 serving 收益需要各自的执行路径与证据，
不从当前均匀算子结果直接推导。

## 已核实的问题

1. `compile-fused` 通过 `fused_selection.py` 的 K 阈值在 host、direct、split-K8
   中选择。论文的 `TwoStageSelector` 用于离线评估和冻结预测，尚未接入该入口。
   修改回归特征不等于完成编译器集成。
2. 旧 `host_regressions` 只统计 oracle 为 host 时误选 fused 的情况。若最快方案
   是 fused，但选中的另一个 fused 比 host 更慢，旧口径会漏报。当前评估改为直接
   比较 `selected_ms > host_ms`，旧含义保留为 `host_admission_errors`；报告版本升至 v2。
   这些计数仍是点估计，不能解释成显著退化次数。
3. P4 的 41 个形状中，20 个有完整 11 候选且全部 M=64；另 21 个只有 6 个
   基础候选。旧数据不能完整检验 grouping 对不同 M 的响应，也不能补造缺失耗时。
4. 100 组固定 q 的 grouping 对比中，75 组请求量和 grid 减半，grouped 胜 4 组；
   N=128 的另 25 组两项计数都不变，grouped 胜 0 组。原稿已更正相应表述。
5. 当前 host 为每个源分别分配 staging/output buffer，再逐个调用 CUTLASS。
   合并为 PM 行 GEMM 需要连续布局或带偏移的 buffer view，以及正确的完成依赖；
   不能只修改 GEMM 的行数。

## 预测器当前限制

当前论文模型分别拟合 host 与 fused 的对数耗时，再取预测最快的合法候选。
它是经验代价模型；编译器还负责合法性、实现生成和执行身份的一致性。
以下区分已经确认的模型限制与需要新测量才能归因的问题。

**原特征存在确定的表达限制。** 固定 P、M、N、q 和环境后，原加性模型中随 K
变化的特征在 g=1 与 g=2 间相同，二者相减后抵消。因此预测的
\(\widehat T_{g=2}/\widehat T_{g=1}\) 不随 K 改变，重新拟合系数也无法改变这一点。
旧 P8 四形状拟合在 M=64、N=1024、q=8 时预测比值恒为 1.069，而 K=512、4096、
8192 的实测比值分别为 1.088、0.973、0.907：grouping 的优劣实际发生了反转。
新增深度交互项解除这个限制，但不保证选对；离线对照见下节。

**优化目标和粗粒度指标不足以约束最终选择。** 回归拟合的是对数耗时误差，
并不直接最小化选择损失。“host/fused 方向正确”也不等于 q/g 选对。旧 P8 四形状
拟合后，19 个形状的方向准确率为 100%，平均 regret 仍为 15.02%。
其中 P=8、M=512、K=8192、N=512 时，最快 split-K4/grouped-N2 为 3.4733 ms，
所选 split-K4 为 5.7082 ms，旧 host 为 5.0696 ms；方向正确仍可比 host 更慢。
这些是存档点估计，不能替代置信区间或新基线比较。

**数据覆盖和校准能力有限。** P4 完整候选仅覆盖 M=64；旧 P8 所谓四形状校准
实际重新拟合全部回归系数，并非只调整已有模型的少量环境参数。其平均 regret
从不校准的 10.87% 增至 15.02%，说明该做法没有改善整体选择；仅凭这个结果不能
断定唯一原因是过拟合。下一轮需要完整候选的多 M 覆盖、低维校准和独立评估。

**静态计数不能直接代替运行代价。** replay、grid 和规约量是分析特征，
underfill 仅由 grid 相对 SM 数计算，不能视为实际 occupancy。当前模型未显式
分解远端读取、缓存、规约、启动及重叠的服务时间，也没有对这些代价分别校准。
这些因素是否主导某个失败点，需要控制变量或设备观测；不能先把所有误差归到通信。

**部署边界仍未验证。** 候选集合尚缺强 materialized 基线，加入它们会改变最优标签；
论文选择器也尚未接入 compile-fused。模型提供固定的融合优势门槛，但没有校准过的
逐点不确定性或分布外判断，评估后的门槛检查不能充当单次选择的可靠性保证。

修订顺序为：先解除已证明的表达限制，同时完成强基线和完整候选描述；再用开发
矩阵比较实际 regret、退化和固定策略，确定校准与回退规则；最后冻结方法并接入
编译入口，进行独立评估。不以扩大模型复杂度或增加 GPU 点数代替这些检查。

## 选择器的目标与接口

目标是降低实际选择损失，并控制相对可靠基线的退化。绝对延迟拟合误差作为诊断，
不作为唯一优化目标。候选是否可运行由编译器判断，模型只对可运行候选评分。

候选描述至少包含实现族、GEMM provider、kernel、q/g、分块方式、源块布局、
规约方式、精度、workspace、启动数量、环境和实现版本。静态描述不携带实测耗时；
测量记录通过候选 ID 关联。新增合并或流水线路径不能继续统称为同一个 `host`。
编译器生成产物中的候选 ID、q/g、provider 和实际执行身份必须与选择结果一致。

预测时使用可在部署前获得的信息：M/N/K/P、每次启动的 grid、K/q、规约计数、
实现的静态资源信息和已标定的环境参数。目标 workload 的实测延迟和性能计数器
只能用于评估或明确计费的调优，不能混入零测量预测特征。

## 离线特征对照

固定 ridge=1、相同输入、相同分组及原有 host。只比较以下四种方案，不搜索超参数：

| 方案 | 融合模型特征变化 |
|---|---|
| 原模型 | 保持原有加性特征 |
| 去掉 replay 特征 | 保留历史 no-rho 消融作为简单参照 |
| 深度交互 | 增加 `1[g=2] * log2(K/q)` |
| 深度与 grid 交互 | 再增加 `underfill * log2(K/q)`；underfill 仍只是 grid 指标 |

平均 selection regret 如下，越低越好：

| 方案 | P4 按扫描组留出 41 形状 | P4 训练后在原 P8 19 形状评分 | 原 P8 四形状重新拟合后评分 |
|---|---:|---:|---:|
| 原模型 | 4.19% | 10.87% | 15.02% |
| 去掉 replay 特征 | 2.13% | 9.48% | 20.51% |
| 深度交互 | 4.26% | 10.87% | 13.20% |
| 深度与 grid 交互 | 3.27% | 9.41% | 14.88% |

交互项允许 grouping 偏好随 K 改变。深度与 grid 交互在三种评估的均值上均有
下降，但幅度有限，P8 最坏 regret 仍约 64%。原模型两种 P8 评估各有 2 个选择比 host 慢；
它们的 oracle 都是 fused，所以旧的 admission-error 口径不会计入。
这些数据已参与方法设计，结果属于探索分析，不能重新称为独立泛化验证。
P4 表格在每个形状已测的候选中评分；完整 11 候选子集的单独指标也保留在 JSON。

## 本地开发与公开数据复用

预测器拟合、候选评分和旧数据重放都可以在 CPU 上完成。现有 P4 的 346 条和
P8 的 253 条记录本身就是实测数据，不必为每次模型修改重新测量。当前优先完成：
特征表达检查、相对代价或排序目标的有限对照、按形状分组的开发评估、候选身份
与编译入口的数据流检查，以及运行器的日志解析、恢复和结果导出。
合成数据只验证数学与程序逻辑，CPU 或其他设备的执行时间不能代替 A100 标签。

旧数据已经参与设计，继续使用时统一作为开发证据。新 kernel、新基线和未测形状
的性能仍是未知；已有记录不足以证明这些实现的数值正确性或速度。GPU 并发、
远端访问、同步和实际数值误差不能靠本地静态检查全部排除。

**预算约束下的推进顺序。** 先完成上述本地工作并列出仍缺的证据，再安排有限的
GPU 核验。复用固定版本的成熟基线代码，只适配本项目的语义、布局和计时，不重跑
各框架的全套官方 benchmark，也不要求同时接入 CUTLASS、Triton 和 TileLang。
首先核验新增路径的编译、数值和必要的多 GPU 同步；发现问题时保留最小复现，
停止大矩阵扫描。单卡或少卡通过不能代替目标 P 下的正确性和性能验证。

正式性能比较只测论文主张所需的同环境、成对 workload。可复用的历史记录保留，
改变环境或实现后的新结果单列；缺少可比强基线的点不据此宣称加速。
每次新增测量先说明要区分哪些候选或解释哪个失败；若预算不足以形成独立验证，
则保留离线方法分析和条件预测的结论范围，不用公开局部结果补造完整融合收益。

## 基线与候选集合

| 路径 | 定义 | 作用 |
|---|---|---|
| 逐源 materialized CUTLASS | 保持旧路径和原有精度 | 与历史结果连接，解释启动和合并的影响 |
| 合并 materialized CUTLASS | 所有源数据在目的端形成连续 PM×K 输入，调用一次 PM×K GEMM | 控制“逐源小 GEMM”这一差别 |
| 合并 materialized 库实现 | 相同通信和布局，使用 cuBLASLt 或确认兼容的库 GEMM | 检验优化后的本地计算是否改变融合价值 |
| 流水线 materialized | 复用已有流水线结构，显式固定 chunk、缓冲区和 GEMM provider | 比较通信与计算重叠 |
| direct-peer CUTLASS | q∈{1,2,4,8,16}，g∈{1,2} | 被选择的十个融合候选 |

合并输入适用于当前每个目的端只有一个 W_d 的 proxy。真实多专家的不同权重不能
直接合成同一 GEMM；那时需要按专家组织的基线，不能复用这里的简化结论。

新基线必须采用相同输入、输出顺序、累加及输出精度和同步边界。必要的复制、
排列、规约和恢复输出顺序都计入算子时间。分配、注册和编译等准备开销单列，
对所有路径采用同一规则。库算法查询、流水线配置搜索也必须记录时间及缓存命中。
cuBLASLt 的启发式查询结果可以复用，但复用前提和首次成本要写清楚。

最终参考同时包括：一个在开发/校准阶段确定的可部署 materialized 策略，以及
事后计算的 materialized oracle。后者只是已测集合的参照，不能伪装成免费可用的
部署策略。所有选择器面对同一候选集合；缺失或非法候选有明确记录。

## 后续候选矩阵

**硬件范围：A100 为主，H100 不作为本轮完成条件。** 当前融合实现和既有选择
profile 使用 SM80，主要历史数据来自 A100 SXM4 80GB。优先保持这一环境，
在单节点 NVLink/NVSwitch 互联及完整 peer access 下进行关键补测。
选择 80GB 是为了与历史环境可比，并非已证明这些 GEMM 必须占用 80GB。
不同显存版本、PCIe/SXM 形态、拓扑或软件栈的结果分别记录，不能直接合池。
参考 [NVIDIA A100 规格](https://www.nvidia.com/en-us/data-center/a100/)。

最小开发核验与补测可先用 P4；需要 P4→P8 迁移证据时，再安排同一八卡节点
上的固定四卡子集与八卡成对测量。更换节点时保留必要的重叠点连接旧结果，
不能把机器差异全部归因于 P 的变化。H100 仅在明确研究跨架构泛化，
或出现需要 Hopper 专有能力的新方法时另立实验；A100 结果不外推为跨架构保证。

以下是需要新实测时的候选范围。先根据本地重放、公开数据可用性和最小核验结果
收敛开发点，再冻结独立评估点；不将全部网格作为首轮租机任务。
同环境开发拟在同一台 A100 节点进行，避免只在 M=64 上学习 grouping：

- M∈{32,64,256}，N∈{512,1024}，K∈{1024,8192}，共 12 个形状。
- P∈{4,8}，共 24 个 workload；两种 P 使用固定 GPU 子集、相同软件版本。
- 每个 workload 覆盖全部合法融合候选和四类 materialized 路径。
- 库算法和流水线内部调优配置另计，不能把“实现族数量”当成总测试点数。

P4 开发数据用于拟合与按 M/N 组留出的内部比较。P8 的开发数据用于诊断环境差异。
若测试少量校准，预先固定四个开发形状 `(M,K,N)`：
`(32,1024,512)`、`(32,8192,1024)`、`(64,8192,512)`、`(256,1024,1024)`。
第一版校准只调整各实现族的低维延迟偏置，融合候选共享偏置，不用四个形状重新
学习全部交互系数。共享偏置只影响跨族选择，不会修复族内 q/g 排序。

待实现族、特征和校准规则固定后，独立评估使用以下拟定网格：

- M∈{48,96,192,384}，N∈{384,768,1536}，K∈{1536,3072,6144}，共 36 个新形状。
- 在同一节点测 P4/P8；预测必须在读取这批耗时前保存。
- 按偶数/奇数 base-N tile 数、M 尾块及相对训练范围分层报告，不把全部点解释成
  “请求与 grid 恰好减半”的对照。
- 使用编译器和实际 kernel 检查合法性后再冻结清单；不依据性能结果删除失败点。
- 两个 P 的对应形状属于同一评估单元。若研究“已知形状从 P4 到 P8”的迁移，
  单列协议，不能与“新形状且新 P”的泛化混为一个数字。

这一网格是均匀算子的独立验证，不支持真实 MoE 或 serving 结论。H100 和另一种
代码生成实现留到 A100 主比较完成后，根据尚未解决的问题选择。

## 选择策略与费用

第一轮对照固定为：可靠 materialized 策略、训练集选出的单一固定调度、原模型、
开发阶段选定的一个交互模型。不能在评估集上挑哪个模型作为主方法。
若族内排序仍不可靠，再开发直接预测相对代价或成对排序的方法；不同时展开多种
树模型、MLP 和大规模特征搜索。

有限调优作为独立策略比较：模型缩小候选集合，在固定预算内测量，然后缓存选择。
调优样本与最终评分样本分开，记录选候选、编译、预热和测量的额外成本 C。
若一次执行节省 ΔT，至少需要复用次数 R 满足 `R * ΔT > C` 才有净收益；
同时报告首次执行、缓存命中和收支平衡次数。总是回退 host 的策略不能凭零退化
被称为成功，还要报告放弃的融合机会。

主要指标为每个 workload 的 regret、均值、p95、最大值，以及相对部署基线的
退化次数和幅度。精确选中 oracle 的比例是辅助指标。接近持平的候选需要配对
重复和置信区间；p95 延迟不是中位数的置信区间。论文性能收益必须使用无 profiler
干扰的计时，设备时间线和计数器单独用于解释。

## 实施顺序

1. 本地统一候选描述、测量记录与模型输入，审核公开来源，重放旧数据并比较有限模型。
2. 复用成熟实现，完成合并路径、库基线和流水线的适配及本地接口检查，准备可恢复的运行器。
3. 用最小 GPU 工作量核验新增路径的编译、数值和同步，随后只补开发阶段缺少的关键测量。
4. 将选定方法接入编译入口，检查所选配置和生成代码一致；固定方法及独立评估清单。
5. 完成主张所需的同环境独立比较，计入选择成本；按剩余问题决定是否扩展候选矩阵。

预测器改进与基线设计共同推进。新基线改变候选最优解和融合准入边界，因此旧 host
数据只能用于定位缺陷，不能直接作为最终调度器的训练标签。
