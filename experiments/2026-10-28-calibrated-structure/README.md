# 从耗时含义与执行结构出发的一轮修正

2026-10-28。本轮已完成代码修改、40 组本地训练与整形状留出对照。**损失含义和外推暴露已修正，但新预测器未达到替换现有选择器的标准。M512 仍误选；八卡 M256 的差距仍不可靠。** 默认编译器、原始实测、历史权重和冻结六形状均未改动，GPU 花费为零。

## 结构应该约束什么

目标是选择满足正确性要求、端到端耗时最小的执行方案。同一候选的顺序必须由其耗时估计导出：

\[
s_c=\log\widehat T_c,\qquad \widehat c=\arg\min_{c\in C_{valid}}s_c.
\]

输入首先要明确执行身份、GPU 数与连接环境、输入/输出/累加/中间结果精度，再描述形状和候选属性。host、merged host、fused 不能因为都叫 GEMM 就混用底座；四卡旧执行与八卡新执行也不能直接共用经验系数。FP16 正确性不能替代 BF16 证据。

物理计数是确定的，耗时却还需要服务速率、依赖和资源竞争。`MK` 输入量、tile 数、`MKN` 工作量都不能直接当成时间；也不能仅由总耗时唯一拆出通信、计算和 overlap。现有 `execution_ledger.py` 与 `tile_execution_model.py` 已区分逻辑计数、条件依赖跨度和实测时间，本轮继续遵守这个边界。

本轮保留同一个 377 参数共享残差网络作控制，结构为：

```
执行身份与精度 → 正确性检查 → 身份对应的代价底座
                                      + 共享耗时残差
                                      ↓
                              每个候选的 log 耗时
                                      ↓
                    按耗时排序 + 同候选数据支持范围检查
```

四卡有同一训练折拟合的底座，残差只在原有整体形状凸包内启用；八卡没有经验证的底座，保留无底座预测仅供诊断。几何支持不保证预测正确，M512 正是反例。没有增加独立的选择输出头，也没有扩大网络。

## 已落地的三个改变

**1. 耗时拟合与候选差距使用一致目标。** 令误差 `e_c=s_c−log(T_c)`，每个形状内部权重归一，host/fused 两类各占一半：

\[
L=\sum_c w_c e_c^2
 +\sum_cw_c(e_c-\bar e_w)^2
 +\tau^2\,D_{KL}(q\Vert p),\quad
p=\operatorname{softmax}(-s/\tau),\quad
q=\operatorname{softmax}(-\log T/\tau).
\]

第二项等于加权两两 log 耗时差误差平方和的一半，对夸大和缩小差距都惩罚。三个数据项在预测等于实测时，梯度均为零。期望选择损失保留为指标，不再以它推动用于解释耗时的分数锐化；CE/KL 仍记录，但选择权重不是“最优候选的真实概率”。这里的零梯度性质不消除网络非凸性、权重衰减或有限数据外推问题。模块名中的 calibrated 指训练目标，并不表示留出预测已获校准认证。

这一组合同时改变了旧 best-gap、期望 regret 项和 CE 相对权重，因而对照测到的是整个损失组合的影响，不能把收益全部归于其中一个项。

**2. 检查 host 的直接工作量表达。** 原七项经验底座主要通过 `log2(ceil(M/64))` 表达 M；加入两个归一化、系数非负的项：每个目的卡的远端有效输入 `(P−1)MK`，以及 P 个 GEMM 的 tile 补齐工作量 `P·ceil(M/64)·ceil(N/128)·64·128·K`。后者与 padded FLOPs 成正比，但不是实测指令数。仅用于历史 P4、逐来源 FP16 CUTLASS；系数不解释为测得带宽或某一阶段耗时。

**3. 支持范围落实到同一候选和精度。** q2 在训练中没有出现、只有一个训练形状，或超出同候选形状凸包时，仍保留预测供检查，但 `chosen=null`、`requires_validation=true`，不自动回退 host。正确性未知也阻止选择；正确性失败候选显示为排除项。评价始终保留全部已测且正确候选的 provisional regret，不能把拒绝选择算作零损失。

## 固定对照及结果

方案先写入 [design-before-fit.json](run-01/design-before-fit.json)，再执行训练；没有根据留出结果追加轮次或调整超参数。四卡：原损失/原底座、新损失/原底座、新损失/工作量底座，分别用 AdamW 和 Muon，各四折。八卡没有可转用的底座，只比较两种损失与两种优化器，各四折，共 40 组、80 次种子训练。所有组使用相同架构、1000 步、种子 0/1，种子只按训练目标选择；学习率统一从 0.003 线性降至 1%。本轮控制组也使用该调度，不将历史恒定学习率结果混作结构对照。

使用 **PyTorch 2.14.1 官方 `torch.optim.Muon`**，只更新 hidden.weight，其他参数使用 AdamW；不是之前的 Dion3。`match_rms_adamw` 是缩放启发式，不保证实际有效步长相等。本轮记录各层真实相对更新、切向更新、角度变化、预测变化和零模长情况。网络参数/梯度为 FP32；官方 Muon 内部正交化使用 BF16，与被测 GPU 算子的 FP16/BF16 合同是两回事。[官方接口](https://docs.pytorch.org/docs/2.14/generated/torch.optim.Muon.html)

四卡共 41 个形状、346 个候选记录；表中 MAPE 先在各形状内平均，再对形状平均。regret 始终针对完整的已测正确候选集，包括未通过支持检查的 provisional choice：

| 模型 | 耗时 MAPE | 平均选择损失 | 最坏选择损失 |
|---|---:|---:|---:|
| 旧代价底座单独使用 | 3.628% | **0.361%** | 7.357% |
| 工作量底座单独使用 | 3.652% | **0.361%** | 7.357% |
| 原损失/原底座 + AdamW | 4.590% | 0.544% | 7.357% |
| 原损失/原底座 + Muon | 3.824% | 0.522% | 7.357% |
| 新损失/原底座 + AdamW | 2.941% | 0.492% | 7.357% |
| 新损失/原底座 + Muon | **2.875%** | 0.503% | 7.357% |
| 新损失/工作量底座 + AdamW | 3.051% | 0.514% | 7.357% |
| 新损失/工作量底座 + Muon | 2.990% | 0.433% | 7.357% |

因此新损失改善了这批四卡耗时拟合，但新网络组合的平均选择损失仍未超过简单旧底座。两种优化器各有胜负，不能宣称 Muon 普遍更好。新工作量底座还带来局部退步：Muon 新损失分支的最大 host 误差从 7.725% 升至 16.559%。不能只拿平均 regret 较低的一行宣布验收。

四卡支持检查通过 28/41 个形状（68.29%），其中仍包含 M512 错误；这说明支持检查只是最低条件。所有候选重排检查通过。上述选择损失均未因拒绝选择被删除或归零。

八卡仍只有四个形状、20 个正确候选标签。四个版本恰好都选对已测子集最快候选，但所有留出形状都未通过严格支持检查，且耗时明显错误：

| 八卡模型 | 留出耗时 MAPE | M256 预测 q2/q8 耗时比 |
|---|---:|---:|
| 原损失 + AdamW | 25.234% | 1.659 |
| 原损失 + Muon | 26.103% | 1.727 |
| 新损失 + AdamW | 27.248% | 1.843 |
| 新损失 + Muon | 28.183% | 1.726 |
| M256 实测 | — | **1.0072** |

新损失的八卡训练 MAPE 已低至约 0.00015%–0.00140%，却没有改善留出误差。q2 在 M256 留出折训练中为零记录，这是数据约束不足的直接证据。换优化器、提高拟合精度和扩大参数量都不能自动提供这条缺失约束。四个八卡形状都是 fused 优势点，也未验证 host/fused 双向选择。

## M512 具体剩在哪里

形状 `[4,512,4096,512]`，实测 host 1079.90 μs、q2 1005.90 μs，正确选择为 q2。

| 项目 | host 预测 | q2 预测 |
|---|---:|---:|
| 原底座 | 890.92 μs | 1082.79 μs |
| 工作量底座 | 916.30 μs | 1082.79 μs |
| 新损失/原底座 + Muon | 996.48 μs | 1046.87 μs |
| 新损失/工作量底座 + Muon | 995.65 μs | 1071.84 μs |

添加计数只使 host 底座增加约 25.37 μs，仍没有跨过决策边界。新工作量底座四折矩阵均满列秩 9，但三个折把 padded MKN 系数拟合为零；这不表示真实计算免费，而是总时间和现有经验项没有把这一项单独识别为需要的贡献。矩阵满秩也不等于每个系数具有独立物理解释。

所以 M512 不是“只有样本外置信问题”，也不是加一个 MKN 特征就解决；当前底座与通用残差的组合仍未正确表达这一处曲面。不能仅凭总耗时确定它具体来自通信、GEMM 服务速率、启动等待还是竞争。

## 下一步结构收敛与准入条件

保留本轮一致的耗时目标、正确性/精度边界、同候选外推暴露。**工作量底座和这批新权重暂不升级为默认选择器。** 接下来只针对 host 服务模型与 fused 竞争关系，沿已有执行图做条件分解，而不是再增加一批不受约束的多项式：

1. 固定真实执行图、tile 与 launch 计数；通信字节与 padded work 由执行身份导出。服务项才允许拟合，而且必须由同一身份的组件证据约束。资源竞争修正与独立计算/通信服务时间分别记录，不能用一个任意 overlap 系数同时吸收全部误差。
2. 依赖传播可写为 `finish(v)=service(v)+max(finish(pred(v)))`，但只有在节点服务时间适用于联合执行、且图包含相关串行约束时才有意义。现有 `conditional_dependency_span` 已提供这一步；缺失节点时保持缺失。未表达共享资源竞争时，不能把图跨度冒充真实墙钟时间或无条件上下界。
3. 共享网络若保留，应修正可解释且有覆盖的服务项，避免让无底座的 377 参数网络承担八卡全曲面外推。减少自由度/施加物理约束可以改变归纳偏好，但仍需要未用于设计的数据检验，不能证明未见 q2 正确。

验收继续同时看：耗时误差、两两顺序、选择 regret、支持覆盖及数值正确性。需要优于简单底座且不保留 M512 的严重误选；之后才用冻结六形状做一次独立检验。当前四卡回放已经多次用于设计，不能作为论文独立泛化结果。

## 交付与复现

- 代码：`EDM-IR/edmir/compiler/calibrated_candidate_selection.py`。
- 固定训练：`EDM-IR/tools/review_calibrated_structure.py`；40 组全部完成，约 93.35 秒。
- 不重训的底座拆解与速度检查：`EDM-IR/tools/analyze_calibrated_structure.py`。
- 单形状检查：`EDM-IR/tools/score_calibrated_candidates.py`。输出 provisional choice、耗时、支持原因、排除项，便于检查失败。
- [results.json](run-01/results.json) 是全部留出结果；[analysis.json](run-01/analysis.json) 包含底座对照、M512 分解、M256 比值与速度；每折文件包含权重、训练误差、实际更新记录。

在仓库根目录，使用本地 `/tmp/edmir-precision-score-venv/bin/python`；环境为 Python 3.12.14、torch 2.14.1、NumPy 2.3.5、SciPy 1.18.1。已有输出目录不允许覆盖：

```sh
python EDM-IR/tools/review_calibrated_structure.py --out experiments/2026-10-28-calibrated-structure/reproduction
python EDM-IR/tools/analyze_calibrated_structure.py --run experiments/2026-10-28-calibrated-structure/reproduction
python EDM-IR/tools/score_calibrated_candidates.py --model experiments/2026-10-28-calibrated-structure/run-01/p8-calibrated-original-muon-fold2.json --data experiments/2026-10-28-precision-scoring/datasets-with-evidence-contracts.json --shape 8 256 8192 512
```

35 项相关测试通过：新模块 9、精度模块 9、路径模型 8、形状评价 9。包括精确耗时处零梯度、自动微分检查、候选顺序、未知精度、未见候选、正确性证据、NumPy/PyTorch 推理一致性及训练/评价形状隔离。35 项是程序逻辑检查，不代表统计模型通过验收。

本地 CPU 遍历四卡 41 形状/346 候选，包含支持检查，冷缓存约 55.04 ms；10 次热缓存中位数 10.34 ms、最大 13.77 ms。训练单种子 20 秒、单任务 60 秒、整轮 600 秒上限，速度检查 30 秒上限。该计时是选择程序自身耗时，不是 GPU 算子耗时。

[integrity-after.json](run-01/integrity-after.json) 确认 22 个受保护文件与预登记源码哈希未变。两篇苏剑林文章的适用边界保留在 [Muon 阅读审查](../2026-10-28-muon-model-audit/README.md)，本轮没有把有效学习率或正交更新误当作泛化保证。
