# 损失与外推表达：三轮本地迭代

本轮完成三种实现及原有全套回放。第二轮显著降低了旧数据上的选择损失，但**三轮均未通过全部验收**，没有替换编译器默认选择器，也没有修改已冻结的 GPU 执行包。GPU 操作与新增独立标签均为 0。

代码入口：`EDM-IR/edmir/compiler/decision_loss_selection.py`。这是沿用既有执行属性的共享数值评分器，不是语言模型，也没有扩大为深层网络；每个候选用同一个参数向量得到一个分数，再对分数取最小值。直接耗时版本共有 19 个拟合系数，外加只用训练数据选择的既有基函数参数。

## 三轮分别改了什么

| 轮次 | 方法 | 改动 |
|---|---|---|
| 1 | `log_gap` | 保留前版 18 个输入特征、共享仿射修正和 additive prior；去掉 softmin 期望损失，改为绝对误差 + 成对耗时差误差 + 最优候选间隔惩罚。 |
| 2 | `traffic_gap` | 联合拟合正的直接耗时；host 引入 MK 规模及其对数尾部、K/N 深度耦合；fused 保留 K/q、串行阶段、额外 CTA、压力及 grouped-N 交互。固定损失配比。 |
| 3 | `traffic_nested` | 在第二轮表达上，只在训练折内部选择间隔损失权重与正则化；候选设置共 9 种，按实测选择损失、最坏损失、相对耗时误差依次比较。 |

第二轮同时改变了基函数、预测量纲和正系数约束，不能把改善单独归因于其中一个特征。这里的“执行代价”仍是经验拟合，不能解释成已经测得的通信带宽、占用率或各阶段服务时间。

## 新损失如何对齐实际选择

令同一形状下的已测候选为 C，真实最快候选为 b，预测为 s，观测为 T。直接耗时版本令 z=min(T)，对数版本令 z=1 并把 s、T 换成对数耗时。

- 绝对项：对 `(s_c-T_c)/z` 的平方加权，host 占一半、所有 fused 合计占一半。
- 成对项：拟合每一对候选的**有符号耗时差**；比较权重为 `w_i*w_j`，再除以该形状总对权重。实现用加权方差恒等式，避免构造随候选数平方增长的张量。
- 间隔项：`sum_c max(0, ((T_c-T_b)-(s_c-s_b))/z)^2`。
- 正则项：缩放后系数的平方和乘以 ridge。

固定版本四项权重分别为 1、1、1、0.001。第三轮只扫描间隔权重 `{0,1,4}` 和 ridge `{0.0001,0.001,0.01}`；没有接触外层测试标签来选择设置。

**可直接检查的性质：** 若选中候选 a，则 `s_a <= s_b`。间隔项中的第 a 项因此至少为 `((T_a-T_b)/z)^2`。直接耗时版本的整个间隔项是该形状上硬选择 regret 平方的上界；对数版本对应 `log1p(regret)^2`。这只对已测候选集合的训练目标成立，不能推出未见形状的泛化保证。为保留这个界，间隔项不除以候选数，因此候选较多的形状包含更多约束；其他两项按形状归一。

未测候选不补标签。所有候选共享一个势函数，因此成对比较不会形成循环偏好；没有位置特征，也没有“接近时强行选 host”的边界补丁。

## 相同门槛下的结果

选择损失定义为 `所选候选实测耗时 / 最快已测候选实测耗时 - 1`。下表不是新 GPU 速度提升。

| 方法 | 主回放平均 / 最大损失 | 留 K 平均 / 最大损失 | M512 正确 / 6 | M512 删组正确 / 24 | 大 N 删组正确 / 8 | 大 N ±1% 检查正确 / 34 |
|---|---:|---:|---:|---:|---:|---:|
| 前版 shared linear latency | 0.766% / 16.074% | 0.853% / 19.623% | 2 | 10 | 8 | 33 |
| 前版 shared MLP cost | 1.001% / 14.001% | 0.853% / 19.623% | 3 | 15 | 1 | 0 |
| 更早 traffic joint mean | 0.472% / 12.320% | 0.195% / 2.632% | 6 | 24 | 3 | 17 |
| 第一轮 log gap | 0.766% / 16.074% | 0.853% / 19.623% | 2 | 13 | 8 | 34 |
| 第二轮 traffic gap | **0.172% / 2.632%** | 0.301% / 4.364% | 5 | **23** | 5 | 31 |
| 第三轮 traffic nested | 0.195% / 2.632% | 0.301% / 4.364% | 5 | 20 | 6 | 32 |

每个主回放和留 K 回放均为 41 个形状；删组检查共 328 次决策。M512 / 6 是三个 M512 形状在两种外层协议上的合计。±1% 是固定标签敏感性测试，**不是硬件随机波动的概率估计**。历史数据已经反复被检查，本轮是回顾性工程验证，不是新的独立测试集。

第二轮在主回放上最好，但更早的 `traffic_joint_mean` 在留 K 和 M512 删组上更好。本轮不存在全面占优的版本，不能只挑一列宣布解决。

## 改善与剩余错误的具体位置

**M512、K4096、N512 的主回放：** 真实 host 为 1.0799 ms，q2 为 1.0059 ms，q4 为 1.0498 ms。前版 MLP 将 host 预测为 0.792444 ms，误选 host；第二轮预测 host 1.060166 ms、q2 1.020677 ms、q4 1.035664 ms，正确选择 q2。对 host 规模外推的修正确实改变了决策。

**同一形状的留 K 回放仍错：** 第二轮预测 q2 0.967436 ms、q4 0.967035 ms，误以为 q4 快约 0.401 微秒。实际 q4 慢 43.9 微秒，损失 4.364%。问题已缩小到 q2/q4 的差值表达，仍然是模型错误，不是程序遍历慢或必须归咎于硬件随机性。

**大 N 主回放：** 第二轮预测 host 0.646319 ms、q2 0.673462 ms、q4 0.671788 ms，正确选择 host；实测分别为 0.6453、0.7248、0.7209 ms。fused 绝对耗时仍被低估，但本次方向正确。

**稳定性还没过关：** 第二轮删除 `m256-n512-longk` 训练组后，M512/K4096 又误选 host；大 N 有 3/8 删组情况选错，34 个扰动情况也有 3 个选错。第三轮改善了大 N，却让 M512 删组退步，不能自动取代第二轮。

**为什么训练内选权重没解决：** 在 M512 留组折及 K4096 留 K 折，9 种设置的内层平均和最大 regret 都相同，最后实际由相对耗时误差打破平局。这说明当前内层决策反馈不足以区分这些配比，不能把“用了 nested CV”当成稳健性的证明。改变 optimizer 或继续增加参数量没有现成证据支持。

下一项有针对性的研究是：检查 q2/q4 差值在留 K 时的交叉点，以及训练删组导致的基函数选择变化；应比较连续的 K/q—串行工作表达和模型选择稳定性。不能用外层 43.9 微秒答案直接手调一个 q4 惩罚，也不能用 host 回退掩盖误选。

## 数值与工程验收

新目标对每次固定表达都是凸的。代码要求优化器成功、投影梯度不超过 1e-5；正则项使固定问题强凸。这个证书检查的是“当前目标是否充分求解”，不证明这个目标能泛化。已有测试独立核对解析梯度、显式成对求和、硬选择损失上界，并用另一个优化算法交叉检查小型凸问题。

独立重跑已完成：**47 项测试通过**，剔除墙钟耗时后，三轮完整数值输出与初次执行完全一致；旧源码证据、历史结果与 GPU 执行包校验和均未改变。每个方法执行 4100 次本地静态选择，遍历 41 个形状平均约 6.2–6.5 ms。完整复验约 142 秒，没有迭代超限。拟合计时绕过模型缓存，但允许复用基函数缓存；不能把这列解释成完整冷启动。

还检查：缺失标签掩码、候选重排、候选子集分数不变、训练折隔离、内层隔离、缓存键与标签变化、保存重载、硬件和 host 基线身份、grouped-N 的 M 范围以及拟合超时。host 始终是 `host_nccl_cutlass_sm80_per_source_v1`，即 GPU 上的 per-source CUTLASS 路径，不是 CPU 计算。

单次模型拟合预算 30 秒，最多 1500 次迭代；模型缓存 128 项，基函数缓存 256 项。每个方法外层执行预算 600 秒，完整回放子进程预算 1800 秒。保存的模型可以直接推断，不在推断时重训或再次扫参数。

## 文件与复现

- `design.json`：运行前写定的三轮配置与验收条件。
- `initial/results.json`：初次完整结果，包含失败记录。
- `verified/decision.json`：独立重跑、数值一致性、测试、耗时与校验和。
- `verified/replay/results.json`：重复执行的完整输出。
- `verified/models/*.json`：全数据拟合模型，仅用于研究推断；不能用其训练集结果代替外层成绩。
- `diagnostics.json`：事后解释，不参与训练或选择。
- `EDM-IR/tools/predict_decision_schedule.py`：显式加载模型文件的本地推断入口。

在仓库根目录，使用已安装 NumPy、SciPy 的 Python：

```sh
PYTHONPATH=EDM-IR:EDM-IR/tools OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python3 experiments/2026-10-21-decision-loss-iterations/run_review.py --out /tmp/decision-loss-review-new
```

输出目录必须是新目录。本地实际运行使用 Codex Python 3.12 和 `/tmp/edmir-review-deps` 中的 NumPy/SciPy；版本和机器耗时见验收记录。时间是本机 CPU 预测器开销，与 GPU kernel 耗时无关。
