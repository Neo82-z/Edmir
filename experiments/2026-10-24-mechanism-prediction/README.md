# 小范围数据与机制模型修订

2026-10-24 开始，10-25 完成本地核验。最终材料在 [final/README.md](final/README.md)。没有连接服务器，没有新增 GPU 实验。

**数据层已经核验并整理；模型已经输出可检查的耗时和成本分解，但还没有达到可靠性验收标准。** 当前结果不能用于宣称修复后的运行时更快，也没有接入自动编译器决策。

## 完成的修改

1. 核验原始包、136 个源文件、192 个生成/封存文件、63 个编译后二进制、20 个输入/参考张量文件和归档 NCCL 动态库。NCCL 两个头文件只有原构建记录的哈希，没有本地归档，不声称重新验证了全部外部构建依赖。
2. 保留 282 个主测进程和 24 个预热诊断进程的全部 30,600 次计时。69 个主要 prepared/merged 配置中，6 个完整配置有漂移等标记；63 个用于稳定性筛选后的标定。慢样本未删除，20/200 次预热未混用，profiler 不提供主测标签。全体主配置的敏感性分析另存。
3. fused 使用共享的 7 项显式成本表达，保留 K/q、grouped-N 与深度的耦合、CTA 数、A 工作集与逻辑重读、split-K 额外输出读写。四种 host 保持独立身份。第二轮给两种已知 CUTLASS host 增加 K 主循环深度。
4. 输出全量标定残差、按整个形状留出的数值预测、候选对误判、成本项差值、外推与秩不足标记。所有候选、阶段和重复测量都遵守完整形状留出边界。
5. 从三个旧时间线计算固定 kernel 时长假设下的队列依赖暴露；另列新策略的显式假设情景，不用旧标签冒充新策略验证。

标定是小规模、固定形式的非负最小二乘，仍然属于从数据估参。没有神经网络，没有超参数搜索。每个求解最多枚举 128 个非负解面；KKT 检查负责确认求解完成，不证明模型正确。原始数据此前已被查看，这些结果是开发验证，不是独立测试集结果。

## 找到并修正的确定性表示缺陷

初版 host 的输入只有固定项、远端 A 字节和 FLOPs。这会把下面两种 workload 表示成完全一样的向量：

| M / K / N | 远端 A | 逻辑计算量 | per-source CUTLASS 实测 |
|---|---:|---:|---:|
| 256 / 8192 / 512 | 48 MiB | 34.36 GFLOP | 1313.671 μs |
| 512 / 4096 / 512 | 48 MiB | 34.36 GFLOP | 1076.486 μs |

相同输入必须给出相同预测，因此不论换什么优化器，两个标签中至少一个的绝对误差不小于 **118.5925 μs**。这是针对这两个已测标签的代数下界，不是测量置信界。CUTLASS 的 K/32 循环深度能区分两者，因此修订输入表达；cuBLAS 的内部 tile 未知，不套用同一公式。

M512 host 的完整形状留出预测由 1219.3 μs 改为 **1101.6 μs**，实测 1076.5 μs。修正已经改善该点，但没有因此宣布所有机制都已解决。

## 验证结果

| 开发版本 | 按形状平均绝对相对误差 | 候选对错误方向 | 错选损失超过 10% 的候选对 |
|---|---:|---:|---:|
| 本轮精简计数对照 | 10.07% | 22 / 191 | 10 |
| 加入 fused 耦合项 | 10.16% | 14 / 191 | 4 |
| 再修正 CUTLASS 深度 | **8.52%** | **12 / 191** | **3** |

这些是同一批小范围开发数据的比较，不是与早期不同来源数据上的旧预测器进行公平跨版本测试。第二轮看过第一轮错误后才修正，也不构成独立泛化证据。

修正版在各形状“已测且稳定”的候选集合中，平均选择损失为 0.35%，最坏为 2.29%；但若只比较 fused，仍有 4 / 10 个形状误选，最坏损失 11.53%。geometry 阶段缺少三种强 host 的标签，不能把该阶段的候选最优称为完整最优。

**不能只报 0.35%。** 最大候选耗时误差仍为 27.01%，三个明显误判如下。三个候选对的逐进程差值方向都一致；这不等于统计显著性证明，但不能简单归咎于一个偶然慢样本。

| M / K / N | 比较 B−A | 预测差值 | 实测差值 | 错选的实际损失 |
|---|---|---:|---:|---:|
| 64 / 8192 / 512 | q8g2 − q8 | −18.6 μs | +75.2 μs | 11.53% |
| 192 / 3072 / 512 | q2 − host | +64.8 μs | −65.0 μs | 11.77% |
| 512 / 4096 / 512 | q2g2 − compiler-cuBLAS | +23.7 μs | −129.7 μs | 16.71% |

这里的 per-source host 与 compiler-cuBLAS 是不同基线；没有合并成一个“host”标签。

## 仍然暴露了什么

**grouped-N 的代价表达不充分。** M64/K8192/N512 的 q8g2，即使放回标定数据，仍预测 544.8 μs，实测 727.0 μs，相差 −182.3 μs。这个错误已经发生在拟合数据上，不能推给泛化。当前凸优化目标的 KKT 检查通过；多跑求解轮次不会改变这个优化问题的解，应该检查成本表达和损失权衡。

该点留出时，模型把 g2 的深度惩罚估为 +55.6 μs，却同时记入较少 CTA 的 −30.5 μs 和较少 A 逻辑重读的 −43.7 μs，合计预测快 18.6 μs。这里存在明确的表达限制：CTA 更少被建模为单向节省，未同时表达小网格下可用并行度降低。该点 g1/g2 的 CTA 数为 32/16；它们是结构计数，不是实际驻留或利用率测量。少 CTA、更多每 CTA 资源和缓存行为的实际作用仍未量化。留出这个形状后，q8g2 只剩一个 M256 形状支撑，材料中已列出。

**M512 的 grouped-N 仍被低估收益。** q2g2 的留出预测 927.3 μs，实测 776.3 μs；全量标定仍高估 121.6 μs。这说明统一的 A 重读系数加深度惩罚没有充分表达跨 M 的服务代价。不能把“逻辑读取量减少”直接当成等比例的时间节省；目前也不能指定缺失时间全部来自 HBM 或 NVLink。

**强 host 的部分外推不可识别。** 隔离漂移配置后，merged CUTLASS 只有三个稳定形状，四个成本项的设计矩阵秩为 3。留出唯一的大 N 形状时，一些库基线的训练形状又都在 N512，远端字节与 FLOPs 不能分开识别。数值正则能给出一个点估计，不能把它变成已识别的物理参数；输出已显式标记 `rank_deficient`。cuBLAS 算法选择没有单独建模。

## 暴露和条件预测

对旧 profiler 捕获重算 DAG，保持每个 kernel 的观测时长不变，M512/q2、M512/q4、大 N/q2 的条件队列暴露中位数分别为 **616.5、634.8、412.0 μs**。这是依赖约束在固定时长假设下的影响；不能当作移除依赖后一定能省下的墙钟时间。物理通信 ECR/EDMR 仍未知。

对精简策略提供了情景 `T′=T[a+(1−a)(4/11)b]`。例如明确假设不随路径缩短的部分 a=25%、并发后的服务时间倍率 b=1.25，以旧图的留出预测为锚：

| 形状 / 候选 | 旧图留出预测 | 上述假设下新图情景 |
|---|---:|---:|
| M512 / K4096 / N512 / q2 | 995.0 μs | 588.0 μs |
| M64 / K4096 / N2048 / q2 | 801.3 μs | 473.5 μs |

a、b 都尚未测得，这两行不是已校准的新图预测，更不是验收结果。情景文件也包含 b=3 时收益消失甚至退步的情况。新版本还有输入就绪修复，因此旧图误差和新源码差异均不能忽略。

## 复现和验收

```sh
python3 EDM-IR/tools/evaluate_mechanism_prediction.py --out /tmp/edmir-mechanism-review
python3 -m unittest discover -s EDM-IR/tests -p 'mechanism_prediction_test.py' -v
```

输出目录必须不存在。默认使用 `design-02.json`；`design.json` 和 `run-01/` 保留第一轮，`run-02/` 保留结构修订后的中间结果，`final/` 补齐候选支持范围、host 原生图身份和二进制核验。三次输出都没有覆盖原始测量。

本次完整生成约 1.14 秒，纯 Python 标准库；模型限制为最多 512 条配置、64 个形状、7 个特征，求解有明确时间上限。**44 项测试通过**：19 项新增数据/预测测试、18 项执行证据测试、7 项机制采集包测试。记录见 [validation.log](validation.log)。测试覆盖标签泄漏、候选顺序、哈希与统计篡改、协议混入、整个区组缺失、秩不足和求解上界。

当前开发验收为“平均误差 ≤10%、最大误差 ≤25%、错选损失超过 10% 的候选对为 0”。**修正版尚未通过后两项。** 数据、数值预测和错误位置现在可以复现；下一项应针对 grouped-N 的并行度/服务代价表达做可反驳的修正，不能靠删除这三个错误或默认选择强 host 来通过。

源码入口：[数据核验](../../EDM-IR/tools/clean_mechanism_data.py)、[显式机制模型](../../EDM-IR/edmir/compiler/mechanism_prediction.py)、[验证与报告](../../EDM-IR/tools/evaluate_mechanism_prediction.py)。
