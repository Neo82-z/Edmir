# M512：曲率限制、局部校正与剩余误选

2026-10-28。已完成既有证据核对、四轮有明确对照的本地结构试验与严格留出检查。**M512/K4096/N512 在原四折开发回放中选回 q2；总误选仍为 7/41，尚未通过完整验收。** 没有使用冻结六形状，没有 GPU 支出，也没有替换默认编译器。

## 找到的具体表达限制

旧 host 底座在固定 M/N 时可写成 `a+bK+cK²`，其中 NNLS 强制 `c≥0`。上一轮增加的 MK 和 padded MKN 项也只是关于 K 的线性项，因此仍然是凸函数。

但 M512/N512 的三个历史 host 标签为：

| K | host 实测 μs |
|---:|---:|
| 2048 | 727.90 |
| 4096 | 1079.90 |
| 8192 | 1529.80 |

两端连线在 K4096 的值为 `2/3×727.9 + 1/3×1529.8 = 995.2 μs`，实测中间点高出 **84.70 μs**。任何凸函数都不可能同时穿过这三个标签。对这三个标签，任意凸模型的最大绝对误差至少为 42.35 μs，最大相对误差至少为 **4.0817%**：

```
(1−ε)·Tmid ≤ predicted_mid ≤ weighted predicted_endpoints ≤ (1+ε)·Tchord
ε ≥ (Tmid−Tchord)/(Tmid+Tchord)
```

这是针对这些观测标签和 host 底座函数族的必要误差下界，不是硬件无噪声定律，也不是全体候选的平均 MAPE 下界。**它不约束后面叠加的非线性网络**；不能据此断言整个神经网络容量不足。具体缺口是原底座把 K 的曲率方向限制错了，网络需要额外抵消这一错误归纳偏好。

另外，M 的 `log2(ceil(M/64))` 表达与实际 tile 数增长不同。仅解除 K 曲率限制而保留 log M，并没有修复 M512；本轮分开记录了这两个变化，未合并成一个“优化器改进”。

## 修改后的模型

代码在 `EDM-IR/edmir/compiler/conditional_curve_selection.py`。它是显式指定的开发模型，不覆盖此前共享网络。

Host 使用非负分段斜率：

```
z = [1, ceil(M/64)−1, N/512]
r_i(K) = clamp(K−k_i, 0, k_(i+1)−k_i) / 4096
T_host = a·z + Σ_i r_i(K) · (b_i·z),   a,b_i ≥ 0
```

K 节点只来自当前训练折；同一组系数用于全部 host 形状。系数仍由原有 NNLS 求解，沿用该训练折底座的 ridge，检查 KKT 残差。各区间斜率可以升高或降低，取消的是凸性强制，不是正耗时/非负斜率条件。当前每折 15 个 host 系数，没有 M512 指示项或按目标点设置的阈值。它仍是经验端到端模型，系数不能称为已测带宽或通信时长。

Fused 保留原底座，只在**同执行身份、同候选、同 M/N、同精度**存在 K 两侧训练锚点时，线性插值 `实测时间−底座时间`，修正底座的微秒残差。新 host 曲线也限定在相同的局部 K 支持范围内。范围外保留原底座分数，随后照常暴露支持不足；不强制选 host，不删除候选，不把拒绝选择记为零 regret。

共享曲线规则独立评价每个候选，改变候选顺序或增删另一个候选，不改变本候选分数。FP16、BF16、实现身份与正确性证据继续分开；八卡没有套入四卡系数。没有引入新的交叉熵权重或继续搜索 Muon/AdamW 步长：这一轮检验的是结构约束，用确定的凸求解器拟合 host 系数。

## 原四折完整回放

所有行使用相同 41 个形状、346 个已测正确候选。当前及上一轮结果均是反复使用的开发数据，不能作为独立泛化成绩。支持覆盖均为 28/41；下表计算的是完整集合的 provisional 选择，未删除另外 13 个形状。

| 方法 | 误选形状 | host/fused 方向错误 | 平均选择损失 | 最坏选择损失 | MAPE |
|---|---:|---:|---:|---:|---:|
| 上轮 2.941% MAPE 网络 | 10/41 | 1 | 0.492% | 7.357% | 2.941% |
| 上轮误选最少的 Muon 分支 | 7/41 | 1 | 0.433% | 7.357% | 2.990% |
| 同折原代价底座 | 7/41 | 1 | 0.361% | 7.357% | 3.628% |
| 只改有支持的 host 曲线 | 7/41 | 0 | 0.288% | 4.364% | 3.487% |
| 只加 fused K 残差曲线 | 8/41 | 1 | 0.412% | 7.357% | 3.231% |
| **两者合用，限制局部支持** | **7/41** | **0** | **0.233%** | **2.632%** | **3.090%** |

它修复了严重的 host/fused 边界，但**没有减少相对原底座/最佳旧网络的总误选数**。平均耗时误差也未超过旧网络。不能以选择损失下降替代用户要求的误选率改善。

M512/K4096/N512：

| 候选 | 原底座 μs | 本轮预测 μs | 实测 μs |
|---|---:|---:|---:|
| host | 890.92 | 1071.39 | 1079.90 |
| q2 | 1082.79 | 1028.07 | 1005.90 |
| q4 | 1065.16 | 1051.70 | 1049.80 |

只改 host 时会从误选 host 改为误选 q4；加入受限 fused 曲线后才选回 q2。预测 host−q2 为 +43.32 μs，实测为 +74.00 μs，差值仍低估约 30.68 μs。因此这是开发留出上的选择修复，不能说耗时或机制已经完全解释。

## 失败如何保留

| 轮次 | 改动 | 结果 |
|---|---|---|
| run-01 | 同 M/N 的 K 原时间插值、残差插值 | 误选 9/41、8/41；原时间插值在大 N 重新误选，最坏损失 11.72% |
| run-02 | host 分段斜率，但仍使用 log M；有/无 fused 曲线的 2×2 对照 | 最坏损失升至 16.07%，不采用 |
| run-03 | log M 替换为实际 M tile 数；保持系数个数 | M512/K4096 选回 q2，但无局部锚点处外推变坏，最坏 18.18%，不采用 |
| run-04 | 新 host 曲线要求同 M/N 的 K 两侧锚点 | 不利形状仍全部计分，恢复边界原底座；得到上表最终结果 |

每轮设计先保存后执行。轮与轮之间的修改由已经看到的失败指导，所以不能把这些结果称为盲测。没有选择种子、追加训练轮次或搜索正则参数。中间结果和对应源码快照保留。`final-validation/` 是仅增强身份/系数校验后的复现，候选分数与 run-04 **逐值相同**，不是新增调参轮。

剩余七个误选集中在两类：

| `[P,M,K,N]` | 预测 → 实测最快 | 选择损失 |
|---|---|---:|
| `[4,64,512,128]` | q2 → direct | 2.632% |
| `[4,64,512,2048]` | q2 → direct | 0.584% |
| `[4,64,512,1024]` | q2 → direct | 0.577% |
| `[4,64,512,256]` | q2 → direct | 1.132% |
| `[4,128,512,512]` | q2 → direct | 1.580% |
| `[4,256,4096,512]` | q4 → q2 | 0.938% |
| `[4,64,1024,128]` | q4 → q2 | **2.100%，本轮相对原底座新增** |

前五个处于 K 训练范围的低端，没有 K 两侧锚点，局部曲线不介入。第三类硬凑新阈值不是本轮结论。最后一个点说明即便有插值锚点，内部 q 排序仍可能出错；“有数据支持”不等于“预测已准确”。

## 更严格的外推检查没有通过

复用此前的三个压力划分，未改变剔除规则：

| 整组留出 | 本轮平均/最坏选择损失 | 新曲线是否介入 |
|---|---:|---|
| 全部 M512 | **7.81% / 16.07%**，错 2/3 | 否，没有相同 M 的锚点；与原底座相同 |
| 全部 N2048 | 0.117% / 0.584% | 否，与原底座相同 |
| 全部三个 host 优势点 | 0% / 0% | 否，与原底座相同 |

因此当前改进只支持局部插值，不支持“未见大 M 已解决”。冻结六形状继续不动，默认选择器不升级。

## 既有 GPU 证据能解释到哪里

重新只读解析了三份 Nsight SQLite，核对来源哈希与 32,100 条先后关系。旧依赖图的加权最长路径在同一条时间线中约占 M512/q2 GEMM 执行跨度的 91.53%，q4 为 91.80%。这是已有串行约束的描述性证据，不是改图后的速度预测。

| profile | 本地输入 kernel 中位数 | peer 输入 kernel 中位数 | GPU GEMM 总跨度中位数 |
|---|---:|---:|---:|
| M512/q2 | 30.88 μs | 88.00 μs | 1001.74 μs |
| M512/q4 | 32.58 μs | 90.78 μs | 1025.75 μs |

在这些 profile 中 q4 的 kernel 自身已经更慢，不能把全部差距归为外围脚本。peer 与 local 的差值也不能直接命名为通信耗时：两者的访存路径、缓存和等待都可能不同。这是 10/21 prepared 执行的插桩数据，而评分器回放来自 8/29 的旧执行；没有混入训练。

已索引组件表有 72 行独立 GEMM、84 行独立 collective；前者没有 `(M512,K4096,N512)`，后者的 nccl-tests 口径不能替代本程序的 host 通信阶段。已采集的四份时间线中没有 M512 host。因而目前不能把严重误选唯一归因为某一个通信、计算或等待系数。新增的曲率证据是函数族限制，不是对物理成因的替代证明。

外部依据继续沿用[上一轮核对记录](../2026-10-28-overlap-evidence/README.md)：NCCL 的消息粒度/协议机制说明常数带宽假设不足；T-CCL 的受限资源曲线和 InferSim 的 profile 查询启发了本轮条件曲线对照。我们没有声称这几篇直接证明上述 spline、原样采用其模型，或把 H800/H100 数据移作 A100 标签。
