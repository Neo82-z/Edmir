# 共享候选评分、直接选择损失与顺序稳定性

三项实现及本地验收已完成。**软件检查通过，三个候选模型均未通过原有性能验收，没有替换默认编译器。** 本轮未运行 GPU，也没有新增独立标签；全部性能数字来自已被开发过程查看过的旧 A100 P4 数据。

推荐资料和六个仓库的适用范围见 [REFERENCES.md](REFERENCES.md)，固定版本与文件哈希见 [sources.json](sources.json)。公众号返回验证页，未读到文章正文；仓库列表来自用户截图。

## 实现

- 核心：`EDM-IR/edmir/compiler/shared_candidate_selection.py`。
- 命令行：`EDM-IR/tools/predict_shared_schedule.py`，读取保存模型，只接收静态输入，不加载实测标签，不重新拟合。
- 测试：`EDM-IR/tests/shared_candidate_selection_test.py`。
- 实验定义：`design.json`；重放：`evaluate.py`；完整检查：`run_review.py`。

```text
当前训练折 → 原 additive 代价模型及其内层选参 → 每个候选的基础预测
                                                 ↓
形状、执行属性、SM80 计数、基础预测 → 共享数值评分器 → log 延迟修正
                                                 ↓
                                  同一标准比较 host 与 fused
```

基础模型是已有的经验延迟模型，不是计数恒等式，也不是理论峰值给出的实际服务时间。它在每个训练折重新拟合，外层测试标签不进入基础模型、标准化或残差训练。

18 个特征包含 M/K/N、q、grouped-N、分区 K 深度、额外串行阶段、tile/CTA/整数 wave 计数、有效 tile 比例、A/B 工作集、额外输出访存和远程输入等。硬件仅支持已有 A100-SXM4-80GB、P4、108 SM 和明确的 per-source CUTLASS host 身份；单硬件数据不能学习硬件间迁移。grouped-N 支持范围、对齐检查和两条已测形状轴的限制保持原状。

预先固定三个对照：

| 方案 | 共享修正参数 | 训练差别 |
|---|---:|---|
| shared_linear_latency | 19 | log 延迟误差与正则化 |
| shared_linear_cost | 19 | 增加直接期望选择损失 |
| shared_mlp_cost | 179 | 同一损失，加 8 单元 tanh 隐层与线性跳接，学习交互 |

以上参数量只计共享修正，基础模型的系数另存于 `prior`。三者使用相同基础模型和输入，因此第二、三行分别检验目标与表达能力变化。与上一轮 traffic/resource 模型的比较只作结果参照，不能解释为单变量消融。

对同一形状的已测候选 C，训练使用：

`loss = balanced_log_time_MSE + λ * Σ p(c) [T(c)/min(T)-1] + 0.001 * ||θ||²`

- λ 在延迟对照中为 0，其余为 1；`p = softmax(-log(T_hat)/0.05)`。
- 每个形状权重相同。延迟项一半权重给 host，一半分给该形状所有已测 fused 候选。
- 直接计算所有已测候选的期望损失和梯度。缺失候选不补标签，padding 不贡献损失。
- p 是训练选择权重，不是“候选最优的真实概率”。运行时仍取预测延迟最小值。
- 每个候选独立经过同一个修正网络；候选位置、枚举序号和列表长度不是特征。精确平局先 host，再按 family 名排序，没有近似平局阈值。

## 结果

主检验按采集组留出，留 K 为另一协议。每个协议都覆盖 41 个形状；所有原验收门槛保持不变。

| 方案 | 主检验平均 / 最大选择损失 | 留 K 平均 / 最大选择损失 | M512 主检验+留 K 正确 / 6 | M512 删组正确 / 24 | 大 N 删组正确 / 8 | 大 N ±1% 正确 / 34 |
|---|---|---|---:|---:|---:|---:|
| 共享线性延迟 | 0.7661% / 16.0740% | 0.8527% / 19.6235% | 2 | 10 | 8 | 33 |
| 共享线性＋选择损失 | 0.9784% / 14.0006% | 0.8175% / 18.1788% | 3 | 14 | 1 | 2 |
| 共享非线性＋选择损失 | 1.0013% / 14.0006% | 0.8527% / 19.6235% | 3 | 15 | 1 | 0 |

上一轮 traffic 联合选参在主检验的平均/最大选择损失是 0.4723% / 12.3199%，M512 为 6/6；它自身也未通过大 N 稳定性验收。本轮新候选没有超过它，不能包装成预测器升级。

大 N 是 `(P=4,M=64,K=4096,N=2048)`。非线性模型在留组检验中预测 host 为 0.703959 ms、q4 为 0.639467 ms，选择 q4；旧实测分别为 0.645300 ms、0.720900 ms，实际损失 11.7155%。

M512/K4096/N512 上，非线性模型预测 host 为 0.792444 ms、q2 为 0.985266 ms，选择 host；旧实测为 1.079900 ms、1.005900 ms。基础模型在留出 M512 后的 host 外推仍被严重低估，共享修正没有纠正它。

这些误差来自模型对未参与该折训练的形状判断，不能解释成程序卡顿或 GPU 随机波动。

## 求解器与目标的诊断

最初的 400 次迭代预算使非线性方案 125 次拟合调用中有 111 次选中了达到上限的解。原结果和当时代码保存在 `optimizer-budget-400/`。随后只把迭代/函数评估上限提高到 3000/6500、收紧停止容差，没有改特征、损失权重、种子、数据划分或验收标准。

正式结果中，三个方案的全部 125 次所选拟合调用均正常收敛，最大梯度绝对值分别为 2.62e-15、3.25e-7、5.23e-7。非线性优化仍只证明数值上的局部收敛，不能证明全局最优。预算修正后边界误选仍在，因此不能继续以求解未完成解释本轮退步。

一个更具体的诊断是：全量训练集上的软期望损失从 2.5400% 降到 1.5154%、0.8886%，但硬选择的训练平均损失却为 0.3609%、0.3741%、0.3741%。也就是说，**软策略目标下降没有自动改善实际 argmin 选择**；与延迟锚定、正则化及有限表达能力共同作用后，它仍有目标不一致的空间。这些只是训练诊断，不是测试收益。可用 `diagnose.py` 重算。

因此，本轮只能得出：这组三方案和固定损失设置未解决问题。它不证明所有共享模型或所有非线性方法无效，也不证明增加参数可以解决问题。后续应检验相对差值约束与软/硬目标差异，并重新审查 host 外推，不能靠继续看外层答案选择超参数。

## 验证与运行成本

正式证据在 `verified/decision.json` 和 `verified/replay/results.json`。

- **37 项测试通过**：12 项新模型测试、2 项实验完整性检查，以及原 additive、traffic、计数模型回归。
- 解析梯度与中央差分相符；线性延迟对照与独立增广最小二乘相符。
- 实际检查了缺失候选遮罩、静态输入、训练折隔离、硬件/host 身份、候选重排、子集一致性、精确平局、保存加载、缓存键与超时。
- 每个方案执行 328 次删组决策、旧对抗数据回放和 34 次固定 ±1% 压力检查；±1% 是训练标签敏感性测试，不是硬件噪声估计。
- 修正预算后的初次运行和独立复跑结果精确一致。正式完整检查约 35.6 秒。
- 每个方案另执行 4,100 次本地选择。遍历 41 个形状平均 6.49–6.79 ms；单次无缓存拟合约 0.10–0.22 秒。没有卡死。这是本机 CPU 预测器耗时，不能与 GPU 执行时间混同。
- 已核对前几轮源文件、证据和冻结 GPU 包的原哈希；均未改动。

代码测试通过与预测模型通过是两件事。`candidate_accepted` 和 `compiler_admission` 仍为 false。

## 复现

环境需要 Python、NumPy、SciPy；现有 `EDM-IR[selector-fit]` 可安装拟合依赖。结果目录必须不存在。

```bash
python3 experiments/2026-10-21-shared-candidate-review/run_review.py --out /tmp/shared-candidate-review
python3 experiments/2026-10-21-shared-candidate-review/diagnose.py \
  --results /tmp/shared-candidate-review/replay/results.json --out /tmp/shared-training-diagnostics.json
```

只读取已保存模型、不进行训练：

```bash
python3 EDM-IR/tools/predict_shared_schedule.py \
  --model experiments/2026-10-21-shared-candidate-review/verified/models/shared_mlp_cost.json \
  --m 64 --k 4096 --n 2048 \
  --environment a100-sxm4-80gb-p4-2026-08-29 \
  --baseline host_nccl_cutlass_sm80_per_source_v1
```

注意保存模型使用全量旧数据拟合，上述示例会选择 host。它见过该点，不能拿这个输出覆盖留组模型在同一点选错 q4 的正式结果。
