# 本轮实现与结论：中间量审查、受控组合修订、强基线

已完成本地实现、留出评价与独立复核。**host 覆盖修订将 M512 的一项留出误差从 36.28% 降至 6.63%；fused 组合修订有局部改善，但没有一个版本满足全部晋升条件。** 不更换编译器默认选择器，不继续增加总耗时拟合项；下一步应取得能区分解释的阶段观测。没有连接服务器或产生新的 GPU 采集。

## 实际修改

借鉴 [Ernst 等的论文](https://arxiv.org/html/2204.14242v1) §4–5 分开评价中间指标与性能、§5.8 评价候选质量的做法。以下表达及检验是本项目的设计，没有移植论文的 stencil 缓存模型，也没有把它的硬件常数用于我们的算子。

1. **中间量单独核对。** `metric_evidence.py` 独立枚举 tile、K 分片、逻辑 A/B 重读和有序输出累加；单列资源上界，将 HBM/NVLink 流量、真实 occupancy 和等待时间保留为未测。逻辑计数正确不再与硬件指标正确混为一谈。
2. **实现有限的组合修订。** `retained_regime_prediction.py` 检验 `C+max(aL,bW)+ρ·min(aL,bW)`，只使用预先声明的五个 ρ，保留八项特征、固定损失/正则与 host 表达。求解器仍为有限分区的非负二次求解，ρ=0 与旧 max 一致，ρ=1 与 sum 对照一致。ρ 是组合参数，不是实测重叠率。
3. **补齐证据导入和基线评价。** 旧集合、新主集合、复跑、附加基线分开；逐项核验原始哈希与进程中位数。比较模型和固定“两种合并 host”，候选缺失时保留缺口。
4. **检查外推是否有足够依据。** `prediction_support.py` 检查目标特征是否在训练行空间中。满秩不保证准确，秩亏也不必然使每个目标都不可预测；不把正则化选出的一个解当成新增观测。

实现入口：[新表达](../../EDM-IR/edmir/compiler/retained_regime_prediction.py)、[中间量核对](../../EDM-IR/edmir/compiler/metric_evidence.py)、[外推支持检查](../../EDM-IR/edmir/compiler/prediction_support.py)、[完整评价](../../EDM-IR/tools/evaluate_post_gpu_revision.py)。

## 受控修订的收益与代价

以下均为**开发集整形状留出**，旧环境和新环境分别标定。不能与上轮“旧参数冻结后在新 GPU 上预测”的 4.15% 直接比较。这组表达检验中，复跑与附加 host 标签都没有加入拟合；下述 host 覆盖修订另行登记。

| 表达 | 旧数据 MAPE | 新主数据 MAPE | 旧 fused 最坏选择损失 | 新主 fused 最坏选择损失 |
|---|---:|---:|---:|---:|
| 当前 max | 4.18% | 4.72% | 3.22% | 6.13% |
| 保留 0.25 倍较小项 | 3.85% | 4.19% | 3.22% | 2.37% |
| 保留 0.5 倍较小项 | 4.82% | 5.02% | 5.51% | 2.37% |

ρ=0.25 把旧数据错序从 9/191 降到 7/191，新主数据从 17/100 降到 11/100；但旧 M192 新增一次首选错误，旧留 N 检查的最坏损失从 3.22% 升至 5.51%。不能因平均误差变好就晋升。

两个稳定反例的方向分解如下；差值定义始终相同：

| 新主数据上的比较 | 实测差值 | 当前 max 留形状预测 | ρ=0.25 | ρ=0.5 |
|---|---:|---:|---:|---:|
| M256/K8192/N512：q8−q2 | −79.18 μs | +96.60 μs | +19.28 μs | −35.91 μs |
| M64/K4096/N2048：q4g2−原 host | +37.48 μs | −13.84 μs | +1.89 μs | +17.98 μs |

ρ=0.5 修复了两项方向，复跑也保持方向，但代价是旧结果退步。ρ=0.25 的大 N 预测只有 +1.89 μs，仍未准确解释实测的 +37.48 μs。说明“较小项完全被隐藏”确实值得质疑，但一个全局保留比例不足以解决全部关系。

当前 max 对 M256 的留出预测中，q8−q2 的 L/W 项差值为零，主要剩下约 −105.80 μs 的 SM 分布代理和 +202.39 μs 的有序边界代理，合成错误的 +96.60 μs。这是**模型如何得出错误的解释**，不是测得真实 semaphore 等待约 202 μs。详见 [逐项分解](run-02/counterexamples.json)。

## M512 的另一类问题：数据无法分开确定各项成本

新主集合留出 M512 后，合并 CUTLASS 只剩三个 M64/K768、1024、1536/N512 训练形状。四项 host 特征的训练矩阵秩为 2，加入目标行后秩为 3。目标含有训练数据没有约束的线性方向，固定正则化仍会给出一个数，但无法据此证明这个外推值有依据。

该目标预测约 894.60 μs、实测 656.43 μs，误差 36.28%。这属于本次**重新留出评价**暴露的覆盖/可识别性问题，不是 GPU 实测从上一轮突然退化。合并 cuBLASLt 的同形状目标虽然也面对秩亏训练矩阵，却仍在训练行空间中；两者不能一概处理。详见 [支持审查](support-audit-final.json)。

这里无需立刻补测：已有附加基线提供了 8 条缺失的合并 host 标签。按[单独登记的覆盖修订](host-coverage-design.json)，只加入这些标签，重复的四条原 host 控制仍使用第一套标签、不平均也不重复加权。留出目标形状时，主集合和附加集合的该形状全部排除。保持同一 host 公式与正则，fused 预测逐条复用，完全不重拟合。

| 同一批 57 个主配置上的指标 | 覆盖修订前 | 覆盖修订后 |
|---|---:|---:|
| M512 合并 CUTLASS 留出预测 | 894.60 μs | 699.98 μs |
| 对应实测与误差 | 656.43 μs / 36.28% | 656.43 μs / 6.63% |
| 全体形状平均误差 | 4.72% | 4.07% |
| 最大候选误差 | 36.28% | 25.87% |

M512 的 host 特征矩阵现在满秩，改善有一部分来自**覆盖修正**，不是增加参数。但原 host 的 K8192 误差、严重错序和 fused 内部问题仍在，自动选择仍未通过。完整数据见 [host 覆盖结果](host-coverage-final/paired-comparison.json)及[留出预测](host-coverage-final/heldout-predictions.json)。

分别改变 M、K、N 的额外选点设计保留为可选项，**不再为了这项已用本地数据补齐的秩缺口租 GPU**。满秩仍不保证时间表达正确，阶段归因也仍未完成。

## 强基线的实际结论

新主集合中同时测得两种合并 host 的 **4 个形状**，固定“两种合并 host”与模型 top-2 的理想选择损失都为零；旧集合共同覆盖的 **3 个稳定形状**也是如此。这里只比较同一支持集，不能把只测得一种合并 host 的形状算进来。

加入 8 条附加标签后的开发集合中，共同覆盖增至 8 个形状，两个 top-2 策略仍都保留该集合最优项。这个扩展集合跨阶段补齐，不能当作新的同批独立实验；原冻结成绩不回填。当前数据没有证明模型 top-2 优于这个简单策略，实际选择开销仍待测量。

## 下一步的范围

[定向诊断设计](diagnostic-design.json) 已根据本地覆盖修订缩减为 **13 个配置、39 个无 profiler 主计时进程**，覆盖 q/M 增长、大 N 和短 K。另 10 个 host 支持配置仅为可选，不默认运行。阶段时间线、同二进制隔离 GEMM 与必要计数器另做诊断，不进入主性能计时。

这是测量设计，**尚不是可直接上传运行的诊断执行包**：诊断采集插桩仍需实现与本地检查，且不能提前宣称 GPU 校验通过。继续复查旧反例时使用冻结的旧 runtime；后来修复的 runtime 必须另建执行身份。

本轮没有任何版本达到全部本地门槛，因此执行预先约定的停止条件：保留修改和反例，停止扩展总耗时拟合，准备阶段证据。论文当前可写执行方式的适用边界和模型局限；新的自动选择收益仍需证明。
