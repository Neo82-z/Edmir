2. 原生性能基线
固定 128 条受控合成源请求（中文/英文/代码），tokenizer 生成精确 512 或 4096 输入 token；正式输出固定 128 token、ignore_eos=True、temperature=0。
四条件各三次，共 12 组、960 个正式请求、122880 个输出 token，全部成功；8 个短功能请求也均生成了非空输出。短功能请求仅验证生成链路，未评估答案质量。
计时范围为 native AsyncLLM streaming（包含引擎排队，不含 HTTP/tokenizer）；本轮不是 HTTP API 服务压测，也不是最大吞吐搜索。预热、模型加载与诊断采集不计入正式基线。

3. 专家路由与形状
独立 eager / synchronous 诊断，四条件共 320 个正式请求全部完成；其延迟不进入性能比较。每种全局阶段取最先三个实际出现的步骤，不足三个则保留实际数量。
共采样 25 个步骤，覆盖全部 8 rank、46 个 MoE 层。所有已采样步骤的路由计数均满足真实 token 数×top-4；真实 token、dummy 和 tile padding 分开记账。gate/up 与 down 的物理 kernel 形状、dtype、stride、tile 配置、专家归属和 padding 全部通过一致性校验。
S1: 6 个采样步骤，1539 个 token 观测，283176 个跨层路由分配；kernel_geometry_complete=True。
S32: 6 个采样步骤，49248 个 token 观测，9061632 个跨层路由分配；kernel_geometry_complete=True。
L1: 6 个采样步骤，12291 个 token 观测，2261544 个跨层路由分配；kernel_geometry_complete=True。
L32: 7 个采样步骤，131168 个 token 观测，24134912 个跨层路由分配；kernel_geometry_complete=True。
逻辑投影：gate/up K=2048,N=3072；down K=1536,N=2048。采样的单并发 decode 非空专家 M=1；高并发 decode 的非空 M 也远小于全局请求并发与总 token 数。长输入高并发存在 mixed 步骤。
这些结果支持区分请求并发、专家 token 行数与实际执行 padding。采样频率不是生产流量频率，更不是执行耗时占比；本轮没有证明原四点或六个保留形状覆盖了真实应用的某个百分比。
