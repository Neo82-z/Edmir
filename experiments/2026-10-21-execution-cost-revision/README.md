## 1. 修改了什么

### grouped-N：K 和 q 独立表达

旧 grouped 项只看 K/q 与基础网格，无法区分同一 K/q 下不同 K、q 的收益。
新项使用：

```text
grouped × [1, log2(K/4096), log2(q), log2(G_plain/64), log2(q)×log2(G_plain/64)]
```

因此 `(K,q)=(1024,1)` 与 `(8192,8)` 不再被强制映射为相同 grouped 收益。
K、q 独立表达消除了已确认的一类信息丢失，但不保证拟合系数已经学对。
grouped-N 仍要求 exact M/q 的成对数据及 K/N 范围支持；不会因为增加了特征就允许跨 M 外推。

### split-K：增加实际实现对应的工作量

`ExecutionGeometry` 显式记录每个源–目的 GEMM 的：

- tile：`64×(128g)×32`；线程数：`128g`；q 个 K 分区的实际跨度。
- 输出 tile 数、总 CTA 数、相对 q=1 增加的 CTA 数。
- 顺序执行的 q 段 epilogue，以及额外归约段的 padded tile 元素数。
- 输出逻辑读写量、额外中间结果读写量，以及 M/N 不满 tile 的有效比例。

对当前 beta=0 的串行 split-K，FP16 输出有 q 次写、q−1 次读：

```text
输出逻辑写入字节 = 2MNq
输出逻辑读取字节 = 2MN(q−1)
相对 q=1 的额外输出访问 = 4MN(q−1)
K 分区跨度 = 32 × ceil(ceil(K/32)/q)
```

新的 split 特征包括额外 CTA、归约链、额外输出访问相对 tensor footprint 的比例、
有效 tile 比例与 log(q) 的交互，以及分区深度。计算网格使用实际 g，而不是始终沿用 g=1。
q=1 时这些 split 差分特征严格为 0。

**这实现的是执行代价的特征层，尚不是经过标定的物理耗时模型。**
逻辑字节不等于 HBM 流量，padded 元素数不等于时钟周期，`ceil(CTA/108)` 仍是理想波次代理。
拟合系数描述 log 耗时比，不能直接解释为带宽倒数或单次 semaphore 等待时间。
未知的缓存命中、驻留限制和服务时间没有填入假定“实测值”。

### host/fused：双向判断与固定比较权重

推断仍用一个共同得分函数：host=0，选择最低得分的候选；额外优势阈值仍为 0。
本轮没有使用评分标签来决定候选，也没有已知形状特判。

训练的完整方案把每个工作负载的配对总权重设为 1，其中 host/fused 占 1/2，
fused/fused 占 1/2，避免候选数量改变 host 比较的相对权重。
这只是明确的损失设计，不是“各占一半必然最优”的定理。

评估同时记录：

- **错误回退**：选择 host，而合格 fused 中的最优已测耗时至少有超过 5% 的相对优势。
- **错误融合**：选择 fused，且其已测耗时比 host 慢超过 5%。
- **候选选错**：即便方向正确，仍按所选/已测最优−1 计算 regret。

四个重点形状必须完整出现，且各自 regret 不超过 5%；缺少形状不能通过。
平均、最坏、慢于 host 次数和留 K 压力检查也必须达标。
这些评分逻辑位于 `direction_diagnostics()` 与 `decision_gate()`，不进入推断特征。

## 2. 固定设计与结果

[design.json](design.json) 在本轮结果产生前确定三个顺序对照；ridge 固定为 1，
不搜索参数。预定完整方案是 `execution_balanced`，没有事后把成绩较好的消融改称最终方案。
数据仍为 P4 的 41 个历史形状；它们已经参与开发，不是新的独立验证集。

| 方法 | 留组平均 regret | 留组最坏 regret | 留 K 平均 regret | 留 K 最坏 regret |
| --- | ---: | ---: | ---: | ---: |
| 固定 q4 | 5.43% | 18.18% | 5.43% | 18.18% |
| 原相对模型 | 3.54% | 29.24% | 6.39% | 39.57% |
| 旧 wave 分解模型 | 9.88% | 39.57% | 13.74% | 39.57% |
| 上轮交互项＋联合拟合 | 3.25% | 17.83% | 4.57% | 39.57% |
| 仅修 grouped-N 表达 | **3.15%** | 17.83% | **3.84%** | **24.24%** |
| 再加入执行代价特征 | 3.69% | 17.83% | 6.33% | 39.57% |
| 再固定 host 比较权重，完整方案 | 3.18% | **18.13%** | **8.47%** | 39.57% |

全部旧对照的选择和汇总指标与上轮复现一致。增加机制相关特征没有自动带来更可靠的预测；
完整方案在留 K 检查上退步，因此明确拒绝采用。

四个重点形状，顺序为 (M,K,N)，P=4：

| 形状 | 历史已测最优 | 完整方案选择 | regret |
| --- | --- | --- | ---: |
| (64,1024,512) | q2 | q2 | 0 |
| (64,4096,2048) | host | q4 | **11.72%** |
| (64,8192,512) | q8 | q8 | 0 |
| (256,8192,512) | q4 | host | **18.13%** |

新双向标准正确拒绝了这份结果。测试通过说明实现符合检查契约，不能代替性能验证。

## 3. 剩余错误具体在哪里

把共同得分按 direct/host、split/direct、grouped/plain 的比值恒等式重新拆开，
两个重点错误表现为不同的分项偏差：

| 形状与比值 | 完整方案预测 | 历史实测 |
| --- | ---: | ---: |
| (64,4096,2048)，direct/host | 约 1.214 | 约 1.655 |
| (64,4096,2048)，q4/direct | 约 0.738 | 约 0.675 |
| (256,8192,512)，direct/host | 约 1.575 | 约 1.686 |
| (256,8192,512)，q4/direct | 约 0.649 | 约 0.502 |

第一处主要低估 direct 相对 host 的代价，第二处主要低估 split-K 的收益。
这使“继续统一挪 host 阈值”无法解决问题。

还能给出更强的必要条件证明。设规则为 `best_fused_score < threshold` 才选 fused：

```text
要让 (64,4096,2048) 正确选择 host：threshold ≤ −0.110165
要让 (256,8192,512) 正确选择 fused：threshold > +0.022176
```

两项条件没有交集。见 [threshold_obstruction.json](threshold_obstruction.json)。
这里使用历史标签作诊断，没有拟合新阈值或新增一版选择器。

全体形状的分项替换诊断也表明存在误差抵消：只替换真实 split 项，平均 regret 降到 0.82%；
只替换真实 direct/host 项却升到 9.19%。**这不是预测器成绩**，而是说明联合拟合的分项
不能直接解释为独立、已经辨识的物理耗时机制。

## 4. 稳健性与工程检查

对完整方案独立重建正规方程，与拟合使用的增广 SVD 解比较；
主要折的设计矩阵均满列秩：grouped 修订为 15/15，执行特征模型为 18/18。
没有发现导致上述退步的数值求解失败。

继续使用精确标签响应、带原始/对偶及互补松弛检查的线性规划，并实际重新拟合验证：

| 当前正确的重点形状 | 诱发明显错选的最大标签上调幅度 | 被诱发的候选 | 该候选历史 regret |
| --- | ---: | --- | ---: |
| (64,1024,512) | 约 0.357% | q4,g2 | 13.08% |
| (64,8192,512) | 约 1.900% | q8,g2 | 12.87% |

已经选错的另外两点对应扰动为 0。上述幅度允许训练标签按最坏方向协调变化，
不是测得的设备抖动或故障概率。与上轮相比，这两个正确点的判断边界也更敏感了。
再删除一个训练组的检查中，36/41 个形状始终保持选择；不能把稳定选错计为预测成功。

65 项本地检查通过，其中新增 10 项：

- 枚举不满 M/N tile 的每个有效输出元素，独立核对 q 段输出读写和 CTA 数。
- 核对 K 分区取整、q=1 零参考、相同 K/q 与相同 tile 网格的区分。
- 核对训练权重、工作负载缩放不变性、输入/基线/环境拒绝、评分标签隔离。
- 独立线性响应与实际重新拟合对照，以及双向门槛、错 q、重点形状缺失检查。

完整本地复跑约 5.56 秒；每阶段设置 60/120/180 秒进程组超时，LP 另限每次 10 秒。
没有修改运行时遍历逻辑，没有扩大 GPU 形状或启动 GPU 编译。

原 599 条记录及来源再次核验。冻结 GPU 包原清单内的 110 个源码、145 个生成文件和
四组输入/参考输出保持不变。**本轮新增预测器模块和评估工具不在旧包内**；
旧包不会自动包含本轮模型，未将它改写成已验证版本。

## 5. 使用与复查

显式使用实验模块，需安装 NumPy；它没有加入项目默认 CLI 导入链：

```python
from edmir.compiler.execution_cost_selection import ExecutionCostSelector

model = ExecutionCostSelector.fit(identified_training_data)
decision = model.select(static_candidates, baseline=identified_training_data.baseline)
```

`decision` 包含候选得分、逐特征贡献、执行几何与适用范围排除原因；
`eligible_for_compiler_admission` 始终为 false。不得把这段实验 API 当成生产准入。

从仓库根目录完整复查，输出目录必须尚不存在：

```sh
python3 experiments/2026-10-21-execution-cost-revision/run_local_revision.py \
  --out /tmp/edmir-execution-revision-new
```

使用 Python 3.12、NumPy 2.3.5、SciPy 1.16.3；当前 SciPy 在隔离目录
`/tmp/edmir-review-deps`，可用 `PYTHONPATH` 指定。不会自动安装依赖、租机器或下载替代数据。
来源核验需要历史原始 CSV、相邻 CUTLASS 仓库的历史 commit 和冻结包。
