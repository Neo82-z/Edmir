# 三个 host 优势点的误选审查与本地修订

2026-10-28。只使用原 P4/FP16、逐源 NCCL–CUTLASS 执行身份的历史数据。**六个冻结形状、冻结协议、上一版模型源码与试验结果均未修改；没有新 GPU 数据。** 下述 host 优势均相对于该点已经测量的候选，不包含未测 grouped 候选或新的合并 host。

## 结论

问题不是简单的“参数量不够”，也不能统一归因于损失函数或 host 胜例太少。

1. **线性版本有确切的表达限制。** 在全部 41 个形状中，host 与 direct 的 31 维特征只差 `host` 标志，因此线性模型预测的 `log(T_host/T_direct)` 是常数。而实测比值范围为 0.434–1.878。任何优化器或更多训练轮次都不能消除这个限制。
2. **小网络的两个大 N 误选与训练不足有关。** 保持输入、损失、学习率、初始化种子和划分不变，只把 AdamW 从 100 轮延长到 1,000 轮，两个大 N 点都选回 host。不是通过增加参数修好的。全数据拟合时原网络本来就能拟合三个 host 胜例，不能断言它没有表达这些点的容量。
3. **M512 主要暴露无约束外推的错误形状。** 增加轮次仍未解决。原共享网络从头拟合 log 时间，没有保留此前已存在的经验代价底座，这是上一版实现的建模退步。相同训练折下，旧代价模型能正确预测这三个 host 优势点。
4. **训练支持稀疏是风险，但“少数类太少”不是充分解释。** M512 目标所在折，同 M 只剩 K=4096 一个训练形状，K=8192 的训练样本最大 M=128。目标位于训练形状 log(M,K,N) 凸包之外；即使只留出这个点，网络仍误选。但删掉全部三个 host 胜例后，代价模型仍能通过其他点的连续耗时关系选对这三个点，说明不需要靠人为增加 host 分类权重才能恢复边界。

当前建议保留经验代价模型作为 top-1 对照和检查工具的默认策略。共享网络用于受限残差及候选排序实验；尚无证据让它替代代价模型。**这仍不是完成独立验收的通用预测器。**

## 三个误选点到底错在哪

单位 μs；这里是原 100 轮模型的留出预测，P=4。M/K/N 不等同于真实 MoE 的客户请求 batch。

| M/K/N | 实测 host | 当时选中候选及实测 | 预测 host / 选中候选 | 单改训练轮次后 |
|---|---:|---|---|---|
| 64/4096/2048 | 645.3 | q4，720.9 | 723.7 / 574.4 | 选回 host |
| 64/8192/2048 | 1047.1 | q4，1193.7 | 877.2 / 791.6 | 选回 host |
| 512/8192/512 | 1529.8 | q2，1830.0 | 1537.5 / 886.7 | 仍错，改选 q4 |

M512 上 host 原预测只高约 0.5%，选中的 q2 却低估约 51.5%。把 host 预测替换成实测值仍不能纠正选择；只修正 fused 预测即可选回 host。这首先是 fused 代价表达/外推的问题，不能简单通过 host 入选阈值修补。

更明确的证据见 [extrapolation-diagnosis.json](extrapolation-diagnosis.json)。保持 M512、N512、q4 不变，K 从 4096 增至 8192：

- 1,000 轮网络预测 **1097.9 → 874.5 μs**；
- 对应历史实测 **1049.8 → 1807.9 μs**。

网络把这段外推曲线预测反了。这里的反例针对已测范围，不宣称所有 GPU 延迟对 K 都严格单调。

同一折代价模型预测 M512/K8192 的 host/q4 为 **1551.4/1832.5 μs**，与实测 1529.8/1807.9 接近。该 q4 预测中，`partition_K_pressure` 与 `K_output_tiles` 的拟合贡献约 704.3 和 402.1 μs。它们说明原底座保留了工作量与网格耦合的增量代价；这些仍是拟合项，**不能解释为已经独立测得的通信或计算时长**，其 capacity=32 也是训练选择的经验阈值，不是 SM 数或实测 occupancy。

原始记录的单位和执行身份已检查。三个点使用相同的 30 warmup/300 timed 口径，mean/median/p95 的 host 与最佳 fused 排序方向一致；没有独立进程重复标签或全部原始逐次数据，因此不能构造配对置信区间。现有证据不支持把约 50% 的模型低估解释成运行噪声。未剔除慢样本或失败记录。

## 对照与修改

所有主表使用上一轮**完全相同的四折整形状划分和已测候选集合**，不替换不利形状。全部数据早已影响研究设计，所以仍是回顾性开发。

| 方法 | 平均选择损失 | 最坏选择损失 | host 更快却选 fused | fused 更快却选 host |
|---|---:|---:|---:|---:|
| 上一版共享网络，100 轮 | 1.89% | 19.62% | 3 | 0 |
| 仅延长为 1,000 轮 | 0.84% | 18.18% | 1 | 0 |
| 原经验代价底座，逐折重新拟合 | **0.36%** | **7.36%** | **0** | 1 |
| 代价底座＋不限制外推的学习残差 | 1.29% | 19.62% | 2 | 1 |
| 代价底座＋限制外推的学习残差 | 0.48% | 7.36% | **0** | 1 |

剩下的反向误选是 M512/K4096/N512：底座预测 host/q2 约 890.9/1082.8 μs，实测却是 1079.9/1005.9 μs。新的三点纠正不能掩盖这项 7.36% 的损失，也没有达到原定最坏损失 ≤3% 的要求。

第一轮为预先写入设计的有限消融：原/路径交互表示 × 原/全部跨路径差值损失 × 等权/训练内胜者类别平衡，以及一个线性对照。**9 个版本全部保存**，没有因失败删掉。其中增加路径交互后的一个版本最坏损失达到 81.59%；类别平衡还新增反向误选。这不支持“多几个特征或给 host 更大权重就能修好”的解释。

第二轮只比较已有代价底座上的两种损失和两种残差作用范围。新增的 frontier 项比较“预测最快 host 与预测最快 fused 的 log 差”与对应已测最小值的差，避免 host 权重很低时仅靠 softmin 梯度。但它没有稳定改进，**不作为推荐配置**。不同优化方法的附加诊断还保留在 `optimizer-control/`：它同时改为 L-BFGS 和显式 L2，不能当纯优化器消融；纯训练轮次对照在 `epoch-control/`。两者均不宣称神经网络达到了全局最优。

## 已落实的代码

[path_aware_selection.py](../../EDM-IR/edmir/compiler/path_aware_selection.py) 与冻结的 `shape_decision_model.py` 并存，后者字节不变。

- 共享 scorer 仍对每个候选使用同一函数；保留全信息实测损失、候选 mask、固定顺序和精确平局规则。
- 可接入**仅在当前训练折拟合**的经验底座，学习 log 时间残差。校验 prior 与残差的训练形状、执行身份完全相同，阻止整库拟合的底座泄漏进留出试验。
- 在 `training_hull` 模式下，神经残差仅在训练形状 log(M,K,N) 的凸包内生效；范围外使用底座的候选分数。它没有强制选择 host，范围外仍有选择 q2/q4/q8 的实例。这个支持域只是几何限制，不是概率校准或准确性保证。
- 外推限制不处理未识别的 runtime、dtype 或 GPU 数；P4 底座不能直接套到 P8、BF16 或合并 host。
- 所有 fit 限时 10 秒；支持域 LP 限时 0.25 秒，无法完成时明确报错，不能猜测在内/在外。支持缓存有 256 项上限。局部测试 41 个形状冷遍历约 36 ms，暖遍历中位数约 4.77 ms，不需要 GPU。

检查入口 [predict_path_aware.py](../../EDM-IR/tools/predict_path_aware.py) 默认使用经验底座；学习残差必须显式选择。结果明确返回是否使用残差、是否属于训练形状及候选预测，不把预测写成实测。`development-model.json` 是全 P4 开发集重新拟合的检查用模型，不能用其训练内结果证明泛化。

```bash
python3 EDM-IR/tools/predict_path_aware.py \
  --model experiments/2026-10-28-host-decision-audit/anchored/loss-False-fold-3.json \
  --shape 4 512 8192 512 --policy supported_residual
```

这条命令使用未包含该形状标签的第三折模型，返回 host；`residual_geometric_support=false`、`residual_applied=false`。需要安装项目现有 `selector-fit` 可选依赖中的 NumPy/SciPy。

## 更严格的检查，不能省略

额外冻结三项历史开发压力测试；均不用于追加训练轮次或改变模型结构：

| 留出方式 | 1,000 轮裸网络平均/最坏损失 | 底座及受限残差平均/最坏损失 |
|---|---:|---:|
| 全部 M512（三个形状） | 7.06% / 19.62% | **7.81% / 16.07%** |
| 全部 N2048（五个形状） | 5.14% / 14.00% | **0.12% / 0.58%** |
| 全部三个 host 胜例 | 14.63% / 18.18% | **0% / 0%** |

全部 M512 留出仍不好，平均值甚至比裸网络差。这表明大 M 的跨区域外推没有完成，不能借三个点修好就宣称可靠。

受限残差的 top-2 在主四折试验中包含全部 41 个已测 oracle；纯底座 top-2 为 40/41，top-3 为 41/41。这只是**候选集合的理想保留率**，未计入实测选择噪声、编译/搜索开销，也不是实际运行损失为零。它可以作为后续小预算验证的理由，但**不替代原 top-1 验收门槛**。

## 复现与记录

- `diagnose.py`：原模型误差分解、表达限制、带 L2 的数值优化诊断。
- `controls.py epochs|support 新输出目录`：复现纯轮次对照、同折代价基线、凸包与单点留出检查。
- `ablate.py`：有限的表示/损失/训练权重消融；`factorial/` 保存全部失败。
- `anchored.py`：底座＋残差及支持范围对照；`anchored/` 保存逐折模型与选择。
- `stress.py`：M512、N2048 和全部 host 胜例移除检查。
- `extrapolation-diagnosis.json`：固定候选随 K 的错误外推曲线与底座代数分解。
- `protected-before.json` / `delivery.json`：旧文件及冻结协议的哈希保护、测试与交付状态。
- `model-revision-addendum.json`：开发模型修改记录；六形状协议不重写，最终模型封存必须明确引用新的训练配置，不能把新模型冒充原 100 轮版本。

停止条件：保留反向误选及全部 M512 留出的失败，不再就这几个旧点追加超参数搜索或扩大网络。主线继续是可解释代价底座、受约束的学习修正、独立形状与真实 MoE 验证；后三项尚未通过的部分如实保留。
