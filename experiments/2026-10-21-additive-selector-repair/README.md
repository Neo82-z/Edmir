# 预测器修复与离线验收（2026-10-21）

本版通过了原有的七项离线验收门槛。四个重点形状均选中各自历史实测最优候选；没有放宽阈值，没有将“不确定”记作正确，也没有把测量标签传入预测接口。主实现是 [`additive_latency_selection.py`](../../EDM-IR/edmir/compiler/additive_latency_selection.py)。

验收结论只覆盖旧 A100 P4 数据上的本地工程检查。全部历史数据都参与过模型设计，嵌套留组也不能重新将它们变成独立数据。本轮新增独立标签为 0，GPU 操作为 0，默认编译器未启用此模型。

## 这次改了什么

之前把 `log(T_fused/T_host)` 拟合成线性特征和，虽然比值分解恒等式成立，却让固定开销、K 分段收益、host 成本相互补偿。上轮的大 N 和大 M 错误需要相反方向的修正，无法用统一阈值解决。

本版分别预测两种执行路径的完整毫秒耗时，再在同一尺度上取最小值。host 指主机发起 NCCL + GPU 上逐来源 CUTLASS GEMM，并非 CPU 做矩阵乘法。两条路径的计时范围仍是 `execute()+synchronize()` 的主机墙钟时间。

令 `k=K/4096`、`n=N/512`、`m=log2(ceil(M/64))`。host 使用非负基函数：

```
[1, k, k², k*m, k²*m, k*n, k²*n]
```

这避免将 M32 的 host 成本沿负的 `log2(M/64)` 外推，也去掉了没有足够证据支持的 N² 增长。K² 是经验曲率项，不是执行计数恒等式。M32 与 M64 在这组 host 特征中仍相同；本版没有宣称已解释所有部分 tile 的耗时差异。

fused 使用实际 tile 网格 `G=ceil(M/64)*ceil(N/(128*g))`，分开表示：

- 分区主循环深度 `K/q`；
- 有序累加级数 `q-1`；
- CTA 数 `G*q`；
- 经验压力项 `h=max(G*q/C-1,0)` 及其与 `K/q`、`q-1` 的耦合；
- grouped-N 额外的固定项、K/q、q、K 和实际网格项。

完整 fused 向量为：

```
[1, k/q, q-1, G*q/108, k/q*h, (q-1)*h/16, k*G/108,
 (g-1)*1, (g-1)*k/q, (g-1)*(q-1), (g-1)*k, (g-1)*G*q/108]
```

因此，同为 K/q=1024 的 K1024/q1 与 K8192/q8 不再强制具有相同 grouped-N 影响。g=2 的 tile 宽度、线程数和 CTA 数随真实实现变化。逻辑读写字节、分区跨度、线程数等仍单独输出，**不将它们称为实测 HBM 流量或耗时**。

所有系数由非负最小二乘拟合；固定项不加 ridge，其余项加 ridge。正系数约束消除了负成本抵消，但不意味着每个系数已被识别成某一种硬件服务时间。`C` 是经验压力阈值，**不是测出的驻留 CTA 数、SM 数或占用率**。

每次拟合只在训练集内部留出原 M/N 实验组，从 `C∈{16,32,64,108}`、`ridge∈{0.001,0.01,0.1}` 的 12 种组合中选参数。内层损失为 host 与 fused 各占一半的归一化耗时平方误差。外层测试标签不参与这一选择。所有参数分数与训练形状均写入模型；最终各外层折均选择 C=32，但代码没有固定这一答案。

## 稳定性与数值检查

[`verified/review_results.json`](verified/review_results.json) 保留了完整证明残差和反例：

- 生产求解使用 NNLS，审查用独立 BVLS 算法核对；同时检查非负约束的 KKT 条件。
- 72 次额外删除训练组并重新执行内层选参，共 328 次决策：39/41 个形状的选择始终不变。四个重点形状分别经 8 次删除后全部保持正确。
- 用线性规划构造使模型选错的训练耗时变化，再实际执行完整嵌套重训验证。

| 重点形状 M/K/N | 找到的最小已确认攻击样例：每条训练标签最大相对改动 |
|---|---:|
| 64 / 1024 / 512 | 9.55% |
| 64 / 4096 / 2048 | **1.12%** |
| 64 / 8192 / 512 | 4.54% |
| 256 / 8192 / 512 | 4.73% |

LP 只在原 NNLS 活跃约束集合和固定超参数内精确；随后完整重训确认样例确实诱发目标错误。表中数值是已构造反例的改动幅度，**不是全局最小攻击半径，不是“小于它就安全”的保证，也不是实际噪声概率**。大 N 的 host/fused 边界仍然敏感，应在下一次真实测量中优先确认。

## 适用范围与接口

- 环境：归档的 A100-SXM4-80GB、P=4 环境。新服务器、新运行时设置、P8 或其他卡均不自动继承证据。
- 基线：`host_nccl_cutlass_sm80_per_source_v1`。cuBLAS、merged CUTLASS、cuBLASLt 均不能替换这个分母。
- 形状：M64 的 N 扫描或 N512 的 M 扫描；M32–512、K512–8192、N128–2048，且 K 能按 32*q 对齐。未覆盖的 M/N 组合被拒绝。
- grouped-N：只在训练中有配对证据的精确 M/q 与 K/N 范围内参与选择，目前 M 仅为 64。
- 超出训练折范围必须显式打开诊断外推；留组、留 K 评估保留这种外推并统计其错误，没有删掉难点。
- 推理输入是没有耗时字段的 `ScheduleCandidate`。持久化模型可直接加载，无需 NumPy、SciPy 或测量文件。
- `compile-fused` 仍使用原准入流程。它的 fallback 是 cuBLAS，不能用本版 CUTLASS 数据证明可替换，因此未接入自动编译决策。

已保存 [`verified/selector.json`](verified/selector.json) 和 [`verified/priority_predictions.json`](verified/priority_predictions.json)。后者是全数据拟合后的预测，供后续实测对照，不能冒充留出验证结果。

## 执行与复现

在仓库根目录，用 Python 3.12 和本目录 `requirements-fit.txt` 中固定的 NumPy 2.3.5 / SciPy 1.16.3 执行：

```bash
python3 experiments/2026-10-21-additive-selector-repair/run_acceptance.py \
  --out /tmp/edmir-additive-acceptance
```

输出目录必须不存在。脚本逐阶段设置超时，失败立即写明阶段并停止；不会连接服务器或调用 GPU。正式回放 **81 项测试通过**，数值与第一次结果完全一致，总耗时约 **16 秒**。验证还重新核对了原始 CSV、内核源码和原 GPU 包哈希。

只查看已保存模型的选择，不安装拟合依赖也能执行：

```bash
python3 -S EDM-IR/tools/predict_additive_schedule.py \
  --model experiments/2026-10-21-additive-selector-repair/verified/selector.json \
  --environment a100-sxm4-80gb-p4-2026-08-29 \
  --baseline host_nccl_cutlass_sm80_per_source_v1 \
  --m 64 --k 8192 --n 512
```

本机实测 100 次完整遍历、共 4,100 次选择：每轮 41 个形状平均 **4.57 ms**，最慢 **4.91 ms**。这是 Python 预测器耗时，不能与 GPU 算子耗时混用。搜索固定 12 种参数组合；拟合有 30 秒截止时间、NNLS 迭代上限，外层验收进程有独立超时和进程组清理。
