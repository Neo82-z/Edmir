# 同工作量迁移与 M 尾块边界复核

2026-10-28 开始，2026-10-29 完成。继续在本地处理预算约束下的模型问题。没有租用、恢复、连接 GPU，没有优化器训练或参数搜索；冻结六形状仅核对哈希。

**本轮没有得到可替换评分器的新版本。** 上一轮显式实验版本仍为 2/41 错、最坏损失 1.1316%，但它本来也没有通过完整替换条件。原保留评分器仍为 3/41。不能把这两种状态混为“默认编译器已经达到 2/41”。

## 先看结果

同一 P4 FP16 开发集，41 形状、346 候选，原四折整形状留出。原分数逐值核对相同；所有候选保留，误选严格计数，没有平局容差。

| 对照 | 误选 | 平均选择损失 | 最坏选择损失 | 形状平均 MAPE |
|---|---:|---:|---:|---:|
| 原保留版本 | 3/41 | 0.0802% | 1.5801% | 2.8334% |
| 上轮 M 工作量外推实验 | 2/41 | 0.0417% | 1.1316% | 3.0553% |
| 等工作量残差迁移 | 3/41 | 0.0636% | 1.1316% | 2.9051% |
| 等工作量迁移 + 上轮 M 外推 | 3/41 | 0.0636% | 1.1316% | 3.0161% |
| M 外推加尾块边界检查 | 3/41 | 0.0802% | 1.5801% | 3.0138% |

等工作量对照修正了 `(4,64,512,1024)` 的短 K 误选，但新增 `(4,256,4096,512)` 的 q2/q4 错误，并翻转 `(4,64,8192,1024)` 的 grouped-N/q8 判断。大 N 与 host 优势压力切分出现 **12.3199%** 最坏损失，明确拒绝。

结合上轮 M 外推时，M512 整组留出仍为 0/3 错；这不能抵消上述退步。尾块检查保留 M512 的结果，却失去此前 M128 的改善，没有通过替换条件。全部结果保存在 `run-01/` 和 `verified/`，不根据单个压力组挑选对照。

## 查明的表达限制

新模块 [shape_transfer_selection.py](../../EDM-IR/edmir/compiler/shape_transfer_selection.py) 将以下量分别暴露：

- padded 计算量、实际有效计算量、CTA 数、主循环深度、输出写回；
- A/B 各自的逻辑读取量与独立张量大小；
- A/B 行跨度、A 沿 N tile 的复用、B 沿 M tile 的复用；
- 每个目的 GPU 的 P 次源 GEMM，以及这些 GEMM 共享的同一个 `weight.r` 缓冲区。

最后一点来自生成的程序结构：同一目的 rank 的各源 GEMM 复用同一份权重，不能把 P 次权重读取直接算成 P 份独立权重占用。逻辑访问量、独立地址范围和物理流量仍然是三件事；本轮没有推定 L2 命中率、内存分区映射或物理带宽。

固定 K=4096，对比两个形状：

| `(P,M,K,N)` | q2 实测 μs | q4 实测 μs | q4−q2 μs | 独立 A / B 大小 |
|---|---:|---:|---:|---|
| (4,64,4096,2048) | 724.8 | 720.9 | −3.9 | 0.5 / 16 MiB |
| (4,256,4096,512) | 682.1 | 688.5 | +6.4 | 2 / 4 MiB |

对每个相同 q，这两个形状的 CTA 数、分片深度、padded FLOPs、逻辑 A/B 读取量和输出读写量都相同，但 A/B 的独立大小、B 行跨度与复用方向不同，而且 q2/q4 的实测胜负相反。

因此，**仅以这些相同工作量计数为输入的单一函数无法同时精确表达两组观测**。如果分差只能给出同一个值，至少一组分差绝对误差不小于 `(6.4−(−3.9))/2 = 5.15 μs`。这是对所列计数表达、单个共享函数和旧观测的限制；不是四折误选率下界，也没有证明缓存就是硬件根因。现有更丰富的原评分器不受这一特定计数碰撞下界直接约束。

本轮等工作量对照故意省略不同的独立大小和跨度，以检验能否迁移残差。它保留这些不同量供解释，输出 `cache_equivalence_verified=false`，不把迁移假设包装成硬件等价事实。

## 上轮 M 外推的收益为何还不可靠

上轮从 3 错降为 2 错，修正的是 M128/K512/N512。其 M 方向锚点为 M32 和 M64：两者都是一个 M tile，前者只有一半有效行；查询 M128 则有两个满 tile。

这次同时改变了有效行比例与 CTA 数，不能用一条“随 M 变化”的斜率直接宣称已经识别了跨 tile 服务规律。对照禁止跨越这一边界的 fused 外推后，该点重新误选。它说明收益依赖这个未经验证的迁移假设，**不等于已证明该外推在真实硬件上必然错误**。

MAPE 退步也已逐项对账，而非归于优化器：

- M512/K2048/N512 的 host 原预测 740.41 μs，上轮外推 631.40 μs，实测 727.90 μs；
- M256/K8192/N512 的 host 原预测 1311.30 μs，外推 1422.60 μs，实测 1268.80 μs；
- M128 短 K 的 q8/q16 残差延长同样增大了误差。

18 个被改动的候选，对完整形状平均 MAPE 的贡献合计正好为 +0.22186 个百分点。用两个点延长斜率时出现的负权重会放大锚点误差；本轮未据此设候选专属阈值、忽略慢候选或按测试标签选择分支。

## 源码排查排除了什么

核对仓库历史 `f584d7d` 的 runtime/template，以及已封存 CUTLASS 提交 `dcf215af68a2d08d305076c152a06f201728cd53` 的对应实现：

1. 模板使用默认 `GemmIdentityThreadblockSwizzle<>`，默认 N 参数为 1，不会在这些 N 点触发可选 swizzle 宽度分支。
2. K512/q1 是 16 个 K32 迭代，q2 每片是 8 个，无尾部分片或空分片。
3. workspace 的 `cudaMemset` 在准备阶段；末分片将 semaphore 释放为零供下一次 grid 使用。不能把 q−1 写成每次执行额外的 memset 或 kernel launch。

这些是源码路径的事实。历史二进制及其完整依赖没有留档，源码审查不是对旧二进制和微秒级耗时的独立验证。具体快慢仍不能凭这三点推断。源码快照、哈希及算术证据见 `source-audit/audit.json`。

## 修改与验收范围

本轮增加可解释的布局/复用字段，以及三个显式对照，未改默认编译器或上轮评分模块。模型组装必须与原训练折的全部候选、身份、精度和观测一致；查询不读取耗时。序列化、顺序改变、候选删除不会改变其他候选的分数。

本轮未达到本地近乎完美目标，也不触发 GPU 采集。下一处本地研究应检验**A/B 分别占用与复用造成的服务变化**，并区分同一权重在 P 次源 GEMM 之间的复用；不再用单个总带宽或总 CTA 数代替这些量。只有得到有来源的服务证据，才可将条件模拟产生的候选排序接入评分；目前不补造微秒常数。
