# 八卡模型与原始实验回放

2026-10-25。本次按论文已有八卡实验重新设计规模相关表达，并在完整历史候选集上比较。没有新增 GPU 测量，也没有改变原始计时或开启编译器自动选择。最终结果目录为 [full-P4-P8-final](full-P4-P8-final/result.json)。

## 对照口径

“原模型”指论文原始 A100 选择实验中的 `TwoStageSelector(ablation="full", ridge=1)`，不是更早的 host 调度器，也不是 10 月的四卡机制模型。原模型结果已由独立历史脚本复现。

- P4：346 条记录、41 个形状，按原来的 9 个完整 sweep 留出。20 个形状有 11 个候选，另 21 个只有 6 个；不补造缺失候选。
- P8：253 条记录、23 个形状，每形状都有 11 个候选。保持原来的 4 个标定形状与 19 个评价形状。
- P8 标定形状为 `(P,M,K,N)`：`(8,32,1024,512)`、`(8,64,2048,1024)`、`(8,32,4096,2048)`、`(8,256,8192,512)`。M 仍是每个来源 peer 的行数，每个目标 GPU 接收 PM 行。
- 11 个候选为 host，以及 q∈{1,2,4,8,16} × g∈{1,2}；q=1 对应 direct。q/g 的含义分别是 K 分片数和 N tile 合并数。
- host 身份为 `host_nccl_cutlass_sm80_per_source_v1`，全系统 P² 个、每目标 GPU P 个 M×K GEMM。没有将它改称合并 CUTLASS 或 cuBLASLt。
- 计时为归档的 `execute()+synchronize()` 主机墙钟。保留原始 30/300 预热/迭代协议及已有 100/2000 复跑身份；10 条评价标签采用原协议既有的复跑覆盖，标定标签不替换。
- 全部是已查看过的历史开发数据。保持划分可避免这次拟合直接读取评价标签，但不能消除长期模型设计对旧评价集的适应。

## 八卡表达具体改变什么

[模型源码](../../EDM-IR/edmir/compiler/scale_aware_prediction.py)独立于已有 P4 生产身份检查，支持 P4/P8 和全部 11 个归档候选。新模型明确要求旧执行环境；其他拓扑、合并 host 和新依赖策略不能自动套用。

| 计数，固定 M/K/N | P4 | P8 |
|---|---:|---:|
| 每个目标 GPU 的 GEMM 数 | 4 | 8 |
| 全系统 GEMM 数 | 16 | 64 |
| 每目标 GPU 远端来源数 | 3 | 7 |
| fused 队列依赖边 | 31 | 157 |
| fused 单位耗时最长依赖链 | 11 | 33 |

后两项通过执行八月归档的 `model.py/schedule.py/dependence.py` 独立核对，不用当前已修改的依赖代码代替旧代码。[来源和哈希](full-P4-P8-final/source-audit.json)。单位耗时图深度不是实测关键路径时间。

每目标 GPU 的唯一远端输入量为 `2(P−1)MK`，固定 M 时 P8/P4 为 7/3；固定 PM、将 M 减半时为 7/6。全系统量另乘 P，不能混用这两个范围。fused 有用元素的远端 A 请求量为 `2(P−1)MK·ceil(N/(128g))`；它不是实测 NVLink 字节数。q 改变分片深度、CTA 数和串行累加，不减少唯一输入量。

host 保留四个非负项：全系统 GEMM 提交数、每卡远端输入量、每卡 FLOPs 和每卡顺序 K 深度。fused 保留八个非负项：提交数、grouped 深度、grouped 启动数、SM 覆盖不足代理、串行累加边界、额外输出读写、K 深度分支和远端请求分支。耗时组合为：

\[
\widehat T=C(x)+\max(aL,bW)+\rho\min(aL,bW).
\]

L 及若干延迟代理随归档依赖链变化，W 使用每卡远端请求量，提交数按 P² 变化；没有将整个四卡预测统一乘二。主版本固定 ρ=0，ρ=0.25 仅作事前声明的敏感性对照。两个版本全部报告，没有按八卡结果搜索 ρ。每项系数只是全程序计时的关联，不能解释成独立测得的启动延迟、网络带宽或重叠比例。单独标定一个 P 也无法识别跨 P 的缩放规律，所以迁移另列。

## 原模型与新模型

选择损失定义为 `T(所选候选)/T(同形状已测最优候选)−1`，按形状等权；不是 kernel 自身加速比。

| 协议 | 原模型平均 / 最大损失 | 新主模型平均 / 最大损失 | 最优候选命中数，原→新 |
|---|---:|---:|---:|
| P4 完整 sweep 留出 | 4.19% / 29.24% | **0.46% / 12.32%** | 23/41 → 35/41 |
| P4 参数直接迁移 P8 | 10.87% / 64.14% | **2.58% / 24.13%** | 11/19 → 16/19 |
| P8 原四形状重新标定 | 15.02% / 64.35% | **0% / 0%** | 3/19 → 19/19 |

P8 标定后，宏平均耗时误差从 18.59% 降到 8.04%；仍有 39/1045 对排序错误，最大单配置误差 38.74%。host 平均误差 1.86%、最大 7.04%，但只有 4 个标定形状，不能把低误差当成跨环境可靠性。

ρ=0.25 的 P4 平均/最大选择损失为 0.47%/11.72%，P8 迁移仍是 2.58%/24.13%，P8 标定后也是 0%/0%；后者耗时误差为 7.35%、错序 33/1045。没有据此替换事先确定的主版本。训练确定的固定候选在 P8 的平均/最大损失为 9.53%/64.35%。

若把 19 个 P8 评价形状各执行一次、直接代入历史计时，原模型所选候选耗时之和为 38.8501 ms，新模型为 32.4221 ms，相差 16.55%。这是**旧测量回放中的选择收益**，不包含选择/编译/校准成本，也不是新实测吞吐提升。

P8 原有数字门槛（方向≥99%、零 host 回退、均值≤0.5%、最大≤1%）在重新标定回放中通过；P4 和直接迁移不通过。它不等于生产晋升或独立泛化验收。P8 19 个评价形状的最优候选都是 fused，因此“方向100%”没有验证 host 获胜时的反向选择。

## 仍然暴露的错误

直接迁移 P8 的三个错误都错过了 grouped-N：

| P/M/K/N | 预测选择 | 实测最优 | 选择损失 |
|---|---|---|---:|
| 8/32/8192/2048 | q8 | q8g2 | 14.50% |
| 8/64/4096/2048 | q4 | q4g2 | 24.13% |
| 8/64/8192/1024 | q8 | q8g2 | 10.31% |

这说明显式 P 计数虽然改善了迁移，仍没有充分表达 grouped-N 的环境相关代价。P8 重标定改变系数可以修复这些历史选择，不等于识别了原因。迁移 top-2 包含全部 19 个已测最优候选，只是理想离线候选保留结果，尚未计入两候选实际测量开销。

P4 的主要旧错误仍是 M64/K4096/N2048：新主模型选择 q2 而实测 host 更快，损失 12.32%。另有五个短 K 形状选择 q2 而 direct 略快。P8 最大单配置误差来自 M512/K8192/N512/q16g2：预测 4977.01 μs、实测 3587.20 μs；当次没有影响最优候选选择，但成本表达仍不够准确。

旧数据还缺少 P8 合并 CUTLASS、合并 cuBLASLt 与现代生产 fused 基线。当前不支持“超过强基线”或完整 MoE/serving 加速声明。后续若用修复后的 `uniform_immutable_peer_v1` 执行策略，必须重新导出 P8 依赖账本和标定身份，不能沿用旧的 33 长链及其参数。

## 检查与复现

- [63 项测试](test-results.json)通过，其中新增 9 项覆盖旧源码图结构、独立 tile 枚举、P 缩放、q1/q16、候选重排、评价标签隔离、环境与范围拒绝。
- [独立验证](full-P4-P8-final/validation.json)核对 3820 条评分记录、869 个选择摘要、17525 次候选对比较以及 17 个输入/20 个输出哈希。它是实现核对，不是独立 GPU 实验。
- 完整回放约 4 秒；单次拟合上限 10 秒、整体上限 120 秒；不依赖 GPU。单次运行的耗时不是对所有机器的性能保证。
- [预先固定的设计](p8-design.json)、[各版本参数](full-P4-P8-final/models.json)、[逐候选预测](full-P4-P8-final/predictions.json)、[输入/源码快照与哈希](full-P4-P8-final/seal.json)均保留。

从仓库根目录运行（输出目录必须尚不存在）：

```sh
python3 EDM-IR/tools/replay_p8_model.py --out /tmp/edmir-p8-replay-new
python3 EDM-IR/tools/validate_p8_replay.py /tmp/edmir-p8-replay-new
python3 -m unittest discover -s EDM-IR/tests -p scale_aware_prediction_test.py -v
```

`legacy-P4/` 是本轮较早只比较共同候选的中间检查，不是最终比较；`full-P4-P8-run-01/` 是首次完整回放。最终目录修正了 host 几何字段的适用标记并补充边界检查，预测和选择数值与首次完整回放一致。论文推进顺序见[八卡论文与验证计划](../../paper/P8_PUBLICATION_PLAN.md)。
