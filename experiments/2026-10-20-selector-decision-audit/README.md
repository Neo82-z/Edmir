## 1. 审查的对象与口径

这里的预测器是**人工构造特征的岭回归选择器**，不是深度神经网络。
输入是形状、q/g、环境和基线身份，输出是候选相对 host 的预测 log 耗时。
候选按得分排序，最低 fused 得分小于 0 才选择 fused，否则选择 host。
额外的融合优势阈值为 0；此次大 K 错选不能归因于人为加了很大的保守门槛。

这里的 host 指主机端发起 NCCL 通信、GPU 上执行 GEMM 的路径，不是 CPU 做矩阵乘法。
本轮历史标签的 host 是 `host_nccl_cutlass_sm80_per_source_v1`。
每个源–目的对有 M 行；一个目的端合并后是 PM 行。全文形状顺序为 **(M,K,N)**，
JSON 中完整 shape 顺序为 **(P,M,K,N)**。

审查对象也不等于命令行编译器已经采用的策略：

| 路径 | 当前实际行为 |
| --- | --- |
| `splitk_revision.py` / `factorized_selection.py` | 实验预测器，历史数据上拟合和评分 |
| 本目录 `candidate_model.py` | 四个有限对照，未被编译器导入 |
| `edmir/cli.py::_compile_fused()` → `fused_selection.py` | 仍是经过准入检查的旧 K 规则，fallback 身份为逐源 cuBLAS |
| prepared、merged host | 实现和测量包已准备，但本轮历史数据没有匹配的完整算子标签 |

旧 CUTLASS host 的标签不能改名为 cuBLAS 或 merged host 的标签，
也不能直接给 prepared 路径打分。编译器拒绝不匹配的基线证据，是身份检查，
不是对 CUTLASS 算法优劣的判断。

## 2. 已排查的数据、数值与软件问题

结果见 [evidence_verification.json](certified_recheck/evidence_verification.json)：

- 599 条完整算子记录逐条与原 CSV 的形状、候选和中位数对应；20 个所引用 CSV 的哈希一致。
- 数据清单中 31 个输入文件哈希一致；P4/P8 历史 collector 的源码哈希一致。
- 本轮拟合只使用同一环境的 P4：346 条候选记录、41 个形状。20 个形状有 11 候选，21 个只有 6 候选。
- 没有把单 GPU GEMM 或独立 NCCL 数据当成完整融合算子的标签。
- 每个外层留出组与训练集的形状不重叠；标准化只用训练数据。
- 预测接口只收静态 `ScheduleCandidate`，不包含 `measured_ms`；更换评分标签不会改变预测输入。
- 用 NumPy 增广最小二乘独立重建旧 split 拟合，旧分数和旧选择均复现。
- 新联合模型的主要拟合设计矩阵满列秩；重点形状对应折的条件数约 22.8–23.6。
  正规方程响应与 SVD 拟合的系数差约 1e-14，没有发现足以解释错选的求解器数值误差。

这些检查支持将当前已复现的主要错误归于模型表达和决策目标。
它们不构成对任意输入、任意机器都无软件错误的证明。

## 3. 为什么恒等式成立，选择仍然错

对**真实标签**有：

```text
log(T(q,g)/T(host))
  = log(T(1,1)/T(host))
  + log(T(q,1)/T(1,1))
  + log(T(q,g)/T(q,1))
```

分别拟合右边三项后，预测误差也会相加。恒等式没有保证每一项可由当前特征准确预测，
也没有保证最后的符号或候选排序正确。

只在诊断中分别用实测比值替换其中一项，结果如下：

| 诊断操作 | 平均选择损失 | 最坏选择损失 |
| --- | ---: | ---: |
| 原 wave 分解预测 | 9.88% | 39.57% |
| 仅把 direct/host 项替换为实测 | 9.96% | 39.57% |
| 仅把 split/direct 项替换为实测 | **0.48%** | 11.72% |
| 仅把 grouped/plain 项替换为实测 | 9.88% | 39.57% |

这把当前主要失误集中到了 split-K 收益估计。**替换用到了答案，只能用于归因，
0.48% 不是可部署预测器的成绩。** grouped 项替换没有改变当前选择，也不表示该项正确：
原模型的准入错误可以遮住后续候选排序问题。

## 4. 两个可以直接证明的表达能力缺口

### 4.1 split-K 的 wave 特征会把不同情况压成相同输入

旧 wave 特征为：

```text
G = ceil(M/64) × ceil(N/128)
W0 = ceil(G/108)
Wq = ceil(Gq/108)
x = [log2(Wq/(qW0)), log2(q), (q-1)/16, 32(q-1)/K]
```

当几个网格都落在相同的波次区间，M/N 的差异可能完全消失。
例如 q=2、K=4096 的一个相同特征集合中，
实测 `T(q,1)/T(1,1)` 从 0.62725 到 0.92225。
同一特征必须输出同一预测，不能同时准确表达两端。

对任意相同输入的预测值 p，有：

```text
max(|p-y_min|, |p-y_max|) ≥ (y_max-y_min)/2
```

这里 y 是真实 log 比值。该集合的误差下界为 0.192737，对应至少 1.21256 的乘性误差因子。
这是 **split 分项对这些已有标签的拟合下界**，不是整个选择器必然产生 21.26% regret，
也不是对真实总体无噪声耗时的结论。

添加本轮两个交互项后，这一类混淆减轻，但没有完全消失。
例如 M=32 与 M=64 的部分形状仍共享相同 tile 网格；新增特征下最严重的相同输入集合
仍有约 1.04883 的乘性拟合误差下界。

### 4.2 grouped-N 只看 K/q 和基础网格，连收益方向都可能丢失

当前 grouped 项特征只有 `log2((K/q)/4096)` 和 `log2(G/64)`。
下表全部为 M=64、N=1024、K/q=1024，因此 grouped 项输入完全相同：

| K | q | 实测 `T(q,g=2)/T(q,g=1)` | grouped-N 方向 |
| ---: | ---: | ---: | --- |
| 1024 | 1 | 1.14167 | 慢 14.17% |
| 2048 | 2 | 1.09211 | 慢 9.21% |
| 4096 | 4 | 1.09642 | 慢 9.64% |
| 8192 | 8 | 0.89316 | 快 10.68% |

该集合对应的 log 误差下界为 0.122741，乘性因子至少 1.13059。
平均耗时口径下两端比值为 1.10077 和 0.88457，方向差异仍存在。

**调系数不能修复相同输入对应相反收益的问题。**
本轮联合拟合仍沿用这个 grouped 项，因此也没有解决此缺口。
需要重新表达 q、网格、tile 资源及归约之间的关系，而不是继续对同一组特征调正则化。

P4 的 grouped-N 成对数据全部在 M=64；限制 exact M/q 与 K/N 范围仍然必要。
这个限制只表示有相应训练覆盖，不证明域内预测正确，更不证明可以跨 M 泛化。
M=256 重点形状只有 6 个已测候选，不能宣称其 grouped-N 已经验证。

完整集合见 [structural_results.json](certified_recheck/structural_results.json)。

## 5. CUTLASS 语义与计数公式之间缺了什么

依据历史 CUTLASS commit `dcf215af68a2d08d305076c152a06f201728cd53`：

- `g=1`：threadblock `64×128×32`，warp `32×64×32`，128 threads/CTA。
- `g=2`：threadblock `64×256×32`，warp 不变，256 threads/CTA。
- q>1 使用 `SplitKSerial=true`。各分区执行自己的 MMA；
  epilogue 按分区序号等待 semaphore，后续分区读取 D 并累加，最后一个分区重置 semaphore。
- 实际 K 分区跨度是 `32 × ceil(ceil(K/32)/q)`；当前四个形状满足整除，才恰好等于 K/q。

依据文件：
[项目 kernel 别名](../../EDM-IR/runtime/src/cutlass_sm80_gemm.cuh)、
[项目调用代码](../../EDM-IR/runtime/src/nccl_device_fused_cutlass.cu)、
[历史 CUTLASS Gemm](https://github.com/NVIDIA/cutlass/blob/dcf215af68a2d08d305076c152a06f201728cd53/include/cutlass/gemm/kernel/gemm.h)。

因此，CTA 数、逻辑 K 分块和逻辑读取次数可以从代码推导；
`ceil(CTA/108)` 却不能自动变成真实执行轮数或耗时。
每 SM 的驻留 CTA、寄存器、共享内存、尾块有效工作、远端访问停顿和 epilogue 依赖，
都没有被这个除法完整描述。grouped-N 改了 tile 和线程资源，也不能只当成远端读取次数减半。

这些是已经核对的执行语义和模型遗漏，**尚未实测各项对耗时的贡献**。
不能把“可能影响性能”写成“已经证明它导致了某个毫秒数”。

项目这两个 CUDA 源文件与历史 `f584d7d` 相同；检查的三个 CUTLASS header 也与历史 commit 相同。
尝试在 macOS 上编译只读模板几何检查器失败，原因是 CUDA libcu++ 与系统 libc++ 头文件冲突。
保留 [geometry_build.txt](geometry_build.txt)，未绕过错误、未声称 CUDA 编译或 GPU 验证通过。
几何表是源码推导结果，实际共享内存用量和硬件 occupancy 仍未验证。

## 6. 有限对照：改哪里有效，哪里仍失败

[design.json](design.json) 在读取本轮结果前确定四个对照；
固定 ridge=1，不搜索超参数、不添加已知形状特判。
两个新增特征是 `log2(q)×log2(K/4096)` 与 `log2(q)×log2(G/64)`，
它们是几何交互代理，不能称为物理耗时定律。

主协议保持原有 P4 按 M/N sweep 留组。regret 定义为
`所选候选实测中位数 / 同形状已测最低中位数 - 1`。缺失候选没有补值。

| 方法 | 平均 regret | 最坏 regret | 慢于 host 的形状数 |
| --- | ---: | ---: | ---: |
| 训练组选定的固定候选 q=4 | 5.43% | 18.18% | 3 |
| 原相对模型，加适用范围限制 | 3.54% | 29.24% | 2 |
| 现有 wave，分项拟合 | 9.88% | 39.57% | 0 |
| 添加交互项，仍分项拟合 | 6.92% | 39.57% | 0 |
| 原 wave，改为共同相对得分拟合 | 6.38% | 39.57% | 1 |
| **交互项 + 共同拟合** | **3.25%** | **17.83%** | **2** |

两种改动共同使用才明显改善当前历史选择。相同的 ridge 数字在不同特征设计中
不代表完全相同的正则化效果，因此此表不能把收益全部归因于某一项物理机制。

四个重点形状：

| (M,K,N) | 现有 wave 选择 | 本轮共同拟合选择 | 历史已测最优 | 本轮 regret |
| --- | --- | --- | --- | ---: |
| (64,1024,512) | q4 | q2 | q2，0.3426 ms | 0 |
| (64,4096,2048) | host | **q4** | **host，0.6453 ms** | **11.72%** |
| (64,8192,512) | host | q8 | q8，0.6556 ms | 0 |
| (256,8192,512) | host | q4 | q4，1.0741 ms | 0 |

本轮没有四个重点全过：修正了两个大 K 回退，却把原本正确的 host 点改错。

另外，原先写下的局部门槛只检查了重点形状“错误选择 host”，没有对称检查“错误选择 fused”。
所以新对照确实通过了**原局部门槛**，但这个门槛不足以代表判断问题解决。
保留原门槛和原分数，没有事后修改它们制造“通过”。
`results_initial.json` 曾将局部通过误标为 `server_ready=true`；
当前规范结果已拆分为 `local_primary_gate_passed` 与 `server_ready=false`，数值结果没有改变。
初始文件仅保留审计轨迹，以本报告及 `server_decision.json` 为结论。

## 7. 严格的数学与泛化压力检查

### 精确的训练标签敏感性

对固定设计矩阵、标准化和 ridge，拟合系数是训练 log 耗时的**精确线性函数**：

```text
w = R log(t_train)
s_candidate = h_candidate · log(t_train)
```

据此用线性规划求最小 ε，使一组满足 `|δ_i| ≤ ε` 的训练 log 标签变化，
能让某个历史 regret 超过 5% 的候选击败所有其他合格候选。
要求至少 1e-7 的得分差，以避免把并列当成稳定错选。
使用 [SciPy HiGHS 接口](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html)，
运行版本为 SciPy 1.16.3；共有 29 个有界目标求解。

每次求解均检查原始约束、对偶残差、乘子符号、自由变量边界、互补松弛和对偶间隙，
并用修改后的训练标签**重新拟合**，
确认目标候选确实被选中。不是只算一阶梯度近似。

| (M,K,N) | 当前选择 | 能诱发明显错选的最小最大标签上调幅度 | 错选目标 | 该目标历史 regret |
| --- | --- | ---: | --- | ---: |
| (64,1024,512) | q2 | 3.53% | q4,g2 | 13.08% |
| (64,8192,512) | q8 | 4.85% | q8,g2 | 12.87% |
| (64,4096,2048) | q4，已错 | 0 | q4 | 11.72% |
| (256,8192,512) | q4 | **0.7234%** | **host** | **18.13%** |

这里“上调幅度”是 `exp(ε)-1`；每条训练标签可独立上调或下调，变化有意配合最坏方向。
**这不是故障概率，不是测出的真实抖动范围，也不能据此断言自然噪声必然触发错选。**
它证明当前拟合函数存在这样的脆弱边界。实际是否出现这种相关变化，需要独立重复数据。

### 删除训练组与留出 K

在每个外层留出组中，再各删除一个训练组，共 72 次拟合、328 次形状决策。
37/41 个形状的选择始终不变；这是有利结果，但其中也包括稳定选错的 host 边界点。
另一个形状 `(64,2048,128)` 在某次删组后错选的 regret 达到 22.34%。
“稳定”与“正确”必须分别报告。

预先声明的留 K 压力检查中，新共同拟合平均 regret 为 4.57%，最坏仍是 **39.57%**；
最坏点 `(128,8192,512)` 选择 host。说明原留组上的改善尚未解决对未见 K 的泛化。
这个压力结果没有再用于挑选新特征或新阈值。

### 计时统计量与证据独立性

冻结各模型选择，只更换评分统计量，新共同拟合的平均 regret 为：
中位数 3.25%、均值 3.22%、p95 5.00%；原相对模型的 p95 评分为 3.86%。
均值/p95 是不同优化目标，不能拿它们充当中位数的置信区间。

历史完整算子采用 host `steady_clock`，计入 `execute()` 和 `synchronize()`，
不能因处于毫秒级就排除主机和同步影响。但当前没有证据把主要错选归咎于这种影响。
单次进程中的 300 次迭代也不等于 300 个独立进程、独立环境验证。

这批 P4/P8 记录已经多轮参与开发；本轮留组和留 K 都是回顾性诊断，
新增独立性能样本数为 **0**。拟合时的 55 个候选配对也不是 55 个独立样本：
11 候选最多只有 10 个独立 log 对比。

成对平方误差的恒等式为：

```text
Σ_(a<b)(e_a-e_b)² / C(n,2) = 2/(n-1) × Σ_a(e_a-mean(e))²
```

它解释了为什么降低配对误差不等于降低最坏选择损失。
6 候选工作负载中，显式 host 配对占总权重 1/3；11 候选时只有 2/11。
工作负载总权重相等，并不代表 host 分界得到相同相对权重。

## 8. 下一版必须处理的具体事项

1. **先修正表达缺口。** grouped-N 要区分相同 K/q 下的不同 K、q 和归约关系；
   split-K 要保留网格、分块深度与有效 M 的区别。先写下执行依据，再确定有限特征，
   不按已知最优候选硬编码形状规则。
2. **把实际执行语义纳入模型设计。** tile、线程数、分区数、串行 epilogue 链可从源码获得；
   驻留能力、远端访问服务时间等尚未辨识的量明确保留未知，不能凭峰值带宽填成实测常数。
3. **重新冻结双向决策检查。** 重点形状同时检查错选 host 和错选 fused，
   并保留固定策略、平均损失、最坏损失；不能只用“没有比 host 慢”掩盖丢失的融合收益。
4. **区分支持范围与准确性。** 范围外不作已验证预测；范围内仍须检查误差和边界。
   模型拒绝判断不等于 host 最快，若实际选择 host，性能损失仍照实计算。
5. **继续本地修改，服务器只承担已定义的未知项。** 本轮不扩大四个重点形状，
   不将 prepared/merged host 的缺失标签混入旧模型。之后要测什么、一次失败说明什么、
   何时停止，都应在新数据到来前确定。

以上是下一轮修订要求，不是这些问题已经修复的声明。
