# 分片深度、流水线与并发条件：2026-10-29

本轮把单个 CTA 的主循环从一个黑箱耗时拆成源码约束的依赖图，并接入已有的条件驻留/串行 epilogue 递推。**结构核验通过，但仍不能替换评分模型。** 保留版本误选为 3/41，未通过验收的 M 工作量外推版本为 2/41，全部候选分数逐值不变。

最有用的结论是表达边界：在 CTA 均能同时入场、且每个 CTA 的服务不随网格负载变化的条件下，无论怎样细分流水线，短 K 的 q2/direct 分差仍与 N 无关。旧数据的分差却为 `+8、+3.5、−2、+1.8、+1.9 μs`。因此，**单独改进深度函数 a(d,g) 不足以解决这组错误**。这不是证明缓存、调度或测量中哪一个已被确定为根因。

## 源码给出的具体约束

核对固定 CUTLASS `dcf215af68a2d08d305076c152a06f201728cd53` 的 9 个头文件，逐个与该提交的 Git blob 对比，另核对项目历史内核模板。没有用当前源码冒充已验证的历史二进制。

- 模板是三 stage，warp K32、指令 K16，即每个 K32 主循环包含两个 warp MMA k-group。
- 启动先发出两个拷贝组；初次 `wait_group<1>` 等待最早的一组完成。
- 每轮先执行第一段 MMA，再发出后续拷贝的两个 A/B 子组，提交并等待，然后执行第二段 MMA。宽 tile 第二个拷贝子组没有 A 拷贝，不能把 A/B 全部合并成一个同顺序访问。
- 完成后有显式 commit、`wait_all` 和 CTA barrier。PTX 的 `wait_all` 还包含一个隐式空 commit；本模型区分显式调用与这一语义，不把空组算作有效内存加载。
- semaphore 等待发生在主循环之后、输出累加之前。它串行化同一输出 tile 的 epilogue，不串行化所有分片主循环。

`wait_group` 保证较早提交组完成，不表示所有传输都以同样延迟或顺序完成。源码模板选到 `.cg`，官方语义是 L2 层缓存提示、绕过 L1；这仍不能确定远端 A 的缓存位置或命中率。[NVIDIA PTX 说明](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async)

审计路径、哈希和行号在 [run-01/source-audit.json](run-01/source-audit.json)。

## 新表达中哪些量同时变化

记分片深度为 `d=K/(32q)`，每个源 GEMM 的输出链数为 `G=ceil(M/64)ceil(N/(128g))`，CTA 数为 `B=qG`。当前对齐条件下：

| 源码层计数 | 表达 |
| --- | --- |
| 有效 K 拷贝组总数 | `B*d = G*K/32`，q 增大不增加这一项 |
| 越过 K 末端的 masked 拷贝组位置 | `2B`，不等于额外有效全局读 |
| 主循环内 barrier 调用位置总数 | `B*(d+2)` |
| 每 CTA 显式 commit 调用 | `d+3`，另有一个 `wait_all` 的隐式空 commit |
| 有序累加边 | `G*(q−1)`，其实际等待次数/时间未知 |

| grouped-N 模板 | g1，64×128 | g2，64×256 |
| --- | ---: | ---: |
| warp / CTA | 4 | 8 |
| 每线程每 K32 的 A 拷贝循环次数 | 2 | 1 |
| 每线程每 K32 的 B 拷贝循环次数 | 4 | 4 |
| 满 tile A/B 字节 / stage | 4/8 KiB | 4/16 KiB |
| 每 warp 每 K32 的 MMA 指令位置数 | 32 | 32 |

这说明 g2 的 A 重复工作、线程级发射工作、每 CTA 总工作和资源占用不能用一个宽度倍率替代。计数是源码模板层面的，不是实测 SASS 指令数、寄存器数或物理流量。尾块另有 predication；BF16 不能借用这份 FP16 执行合同。

## 实现与本地对照

[pipeline_dependency_model.py](../../EDM-IR/edmir/compiler/pipeline_dependency_model.py) 新增有界依赖图。节点分别表示 A/B 发射、异步完成、MMA、等待和 barrier。前缀完成节点保留所有较早提交组的约束，避免为每个 wait 重复连接全部历史组；图构造和求值为 O(d)。每个服务耗时都由调用者显式给出，输出不包含 GPU 微秒预测或候选选择。

在三个 A 延迟、三个 B 延迟、两个 barrier 耗时、两种 warp 服务假设、两种驻留槽数和两个 epilogue 服务下，共做 **144 组固定场景、2,592 次条件 GEMM 求值**。216 个唯一 CTA 图复用计算，全部场景保留，没有搜索最接近标签的参数。

这里的 108 槽是假设每 SM 可运行一个 CTA 的全入场场景，4 槽是人为受限的压力对照；二者都不是实测 occupancy。warp 并行/串行、输出宽度与读写次数对应的耗时比例也只是显式场景。来源 GPU 争用、多 rank 执行和 CPU 提交尚不在模型内，不能把单源 GEMM 的结果直接乘 P 冒充整程序 wall-time。

结果：

- 72 组全入场场景全部满足短 K 分差与 N 无关。这个结论对该模型类中任意非负、固定的内部服务成立，不仅对本次参数网格成立。
- 包括 4 槽对照在内，没有场景复现 `+,+,−,+,+` 的短 K 方向。
- grouped 四格旧实测 q8−q4 在 g1 为 `+86.8 μs`，g2 为 `−84.3 μs`；本轮没有同时匹配这两个方向的场景。有限网格失败不能证明所有资源条件模型都不可能解释。
- 任何给五个短 K 形状同一个分差的共享函数，其最大绝对分差误差至少为 `(8−(−2))/2=5 μs`。这是限制模型类与旧标签的算术不相容证据，不是当前四折评分器的误差下界，更不是测量误差范围。
- 未采用评分修正；没有重新训练、增加拟合参数、删除错误样本或更改平局规则。

## 这一轮之后的收敛方向

不能再把“将 a(d,g) 拆得更细”本身当作降错方案。下一层表达需要明确区分：

1. **固定执行工作**：本轮可由模板得到的发射、有效加载、masked 控制、MMA、累加依赖。
2. **随执行条件变化的服务**：活动 CTA/warp、可发射 warp、可用传输队列、A 本地/远端路径、并发源 GPU 与缓存驻留。仅有总 CTA 数不足以确定这些状态。
3. **整程序外围时间**：旧标签的 CPU 提交、依赖事件及同步范围；不能把它们吸收到一组 CTA 物理常数后再解释为机制。

先要求候选模型在不读查询标签的情况下给出以上条件或明确缺失项，再检查能否同时解释短 K 和 grouped-N 四格。仅凭本轮结果，不能指定是哪一项负责，更不能借新增项把旧分数硬调到零错误。本轮交付的是可检验的依赖表达和失败边界，尚未达到近乎完美的预测验收。
