# M512 与大 N：三次本地联合选参尝试

本轮继续在本地修改选择方法，没有运行 GPU。三个预先写入 `design.json` 的方案均已完成原有验收，**没有任何一个同时解决 M512 和大 N，因此没有替换默认编译器，也没有改动已经交付的 GPU 执行包。**

所有数据都曾被开发过程查看。以下是回顾性工程检查，不是独立测试准确率；新增代码位于本实验目录，与原模型分开。

## 尝试的内容

旧方法分别按 host、fused 的耗时预测误差选择参数，再比较两者大小。这轮检验：直接按训练内的选择损失联合选参，能否改善边界判断。

1. `traffic_joint_mean`：保留旧 traffic 特征，联合选择平均选择损失最小的 host/fused 参数组合。
2. `resource_joint_mean`：沿用上轮分开 A/B 工作集的特征，使用相同的联合选参目标。
3. `resource_joint_worst`：使用相同工作集特征，先控制最差采集组的平均选择损失，再比较总体平均损失。

每种都枚举原有 **48 种 host 配置 × 12 种 fused 配置，共 576 对**。同一内层折只拟合 60 个分量模型，组合时复用预测；相同训练数据的结果使用容量为 128 的内存缓存。缓存键包含完整训练行及其耗时，不跨不同标签复用。

平均损失相同后依次比较最大损失、host/fused 差值预测的均方误差和固定参数顺序。推理仍选择预测绝对耗时最小者，无按 M512/N2048 特判、无额外 host 偏置。内层和最终推理均执行训练数据决定的 grouped-N 支持范围。

这里同时统一了内层候选资格，因此与旧方法的比较不是只改变一个损失函数的纯消融。绝对耗时的特征、非负拟合、权重和正则化网格均沿用旧实现。

## 结果

“选择损失”定义为所选方案耗时 / 同形状全部已测方案最短耗时 − 1。

| 方案 | M512 主检验及留 K，6 次 | M512 删组，24 次 | 大 N 删组，8 次 | 大 N ±1% 压力检查，34 次 |
|---|---:|---:|---:|---:|
| traffic 联合平均损失 | **6/6** | **24/24** | 3/8 | 17/34 |
| A/B 工作集联合平均损失 | 4/6 | 16/24 | 7/8 | 26/34 |
| A/B 工作集最差组损失 | 4/6 | 16/24 | 7/8 | 26/34 |

M512 检查覆盖 K=2048/4096/8192，N=512；大 N 指 M=64/K=4096/N=2048。±1% 是对训练标签施加的固定压力测试，不是 GPU 噪声估计。

traffic 方案在主检验的平均/最大选择损失为 **0.4723% / 12.3199%**；两个工作集方案均为 **0.3741% / 7.3566%**。留 K 检验中，traffic 为 **0.1947% / 2.6316%**，工作集方案为 **0.8903% / 11.9621%**。工作集方案在大 N 原始点上选对，删组及扰动后仍会选错；两种工作集目标没有带来本轮所需的区别。

traffic 的 M512 结果说明继续本地研究有价值，但其大 N 退步不能被平均指标抵消。全部方案均未通过原有综合验收。

## 错误具体在哪里

traffic 联合选参在大 N 点给出的预测是：

| 方案 | 预测 ms | 旧实测 ms | 预测误差 ms |
|---|---:|---:|---:|
| host | 0.672553 | 0.645300 | +0.027253 |
| split-K q2 | 0.672073 | 0.724800 | −0.052727 |

模型认为 q2 快约 **0.48 μs**，实际 q2 慢 **79.5 μs**。host 被高估、q2 被低估，共同翻转比较方向。小的预测优势不代表真实结果接近平局，更不能据此把错误解释为机器波动。

工作集方案在 M512/K4096 上相反：host 预测 1.041440 ms、实测 1.079900 ms；q2 预测 1.060455 ms、实测 1.005900 ms。它低估 host、高估 q2，错误选择 host，损失 7.3566%。

对训练内选参过程再做审查发现：

- traffic 的大 N 外层折中，144 对参数具有相同的最小内层平均选择损失；重新在该外层训练集拟合后，76 对选择 host，68 对选择 q2。
- 工作集方案的 M512 外层折中，82 对参数具有相同的最小内层平均选择损失；55 对选择 host，27 对选择 q2。

这里“相同”只指主选参指标，不表示差值误差、全部预测或完整排序条件相同。外层耗时仅用于事后解释，没有用于从这些组合中挑选新模型。枚举中存在选对的参数，不证明训练过程知道该选它。

本轮结果支持的判断是：**联合选择损失能改善部分边界，但当前特征及训练内排序仍不足以同时保持两处正确。** 这没有穷尽其他模型，也不是必须停止本地研究的证明。后续若继续，应提出新的代价结构或可检验约束；不能直接从已知外层答案反选一组参数。

## 验收与复现

正式结果在 `verified/`，初次运行在 `initial/`。两次完整评估及误差诊断精确一致，运行耗时不参与对照。**21 项测试全部通过，正式审查用时约 35 秒；模型验收仍未通过。**

- 每个方案都执行全部 41 个形状的留组及留 K 检查、328 次删组决策、旧对抗样本回放和 34 次既定压力检查；未减少或放宽原门槛。
- 新测试核对了静态推理输入、外层/内层隔离、576 对参数覆盖、候选资格、缓存键、顺序确定性和超时；另用 BVLS 检查所选分量拟合，并用显式枚举核对一个内层折的三组联合评分。
- 原模型、前几轮审查证据及已交付 GPU 压缩包均核对原哈希。未重新生成 GPU 包中的冻结预测。
- `verified/performance.json` 记录每个方案无缓存拟合和 4,100 次本地选择的开销。本机单次拟合约 0.28–0.29 秒，遍历 41 个形状平均约 3.34–4.43 ms，未发生卡死。它们是 CPU 预测器耗时，不是 GPU 算子耗时。

复跑需要 Python、NumPy、SciPy，输出目录必须不存在：

```bash
python3 experiments/2026-10-21-joint-decision-review/run_review.py \
  --out /tmp/edmir-joint-decision-review
```

`run_review.py` 为阶段设置进程超时，单次拟合也有截止时间。程序退出成功表示审查完成；是否通过验收以 `verified/decision.json` 的 `local_accepted` 为准，不能以测试通过代替模型通过。

主要文件：`candidate.py` 是三种候选；`evaluate.py` 沿用原验收；`diagnose.py` 保存差值分解和参数对照；`verified/replay/results.json` 包含完整拟合状态与决策；`verified/diagnosis.json` 包含全部 576 对参数的事后诊断。
