EDM-IR：P1 / P2 收尾实验与本地审计
2026-11-18

结论
P1 和 P2 的约定采集、回传与本地分析均已完成。预测器、系数、六个冻结形状及其协议未修改，没有重训，没有根据新结果选择另一折模型。
P1 支持受控依赖放宽与 grouped-N 的条件性收益。P2 的固定数值评分直接选择未胜过固定 q4/g2；将评分用于筛选少量候选，再用独立测量选择，效果更好。不能把后者改称为无需测量的预测胜出。
实例停费状态单列于 BILLING_STATUS.txt；数据回收完成不等于平台计算费已停止。

一、范围、身份与完整性
硬件：Excess Supply / Omaha，单机 8×A100 SXM4 80GB，108 SM，八卡 NV12。CUDA 12.8、NCCL 2.28.9、驱动 580.196.07。FP16 输入/输出、FP32 累加，原 FP16 serial split-K 归并路径。
语义：均衡 All-to-All–GEMM；M 为每个源—目的对的行数，不是请求 batch。输入上传、准备与内存分配在正式计时外；计时包括 host execute 和所有 rank 的完成同步。
封存主模型：此前最终大 N 复测使用的 coupled_geometry-large_n，SHA256 9877a7b8be5a616a577c182e3d3814b938b75fab498ad93e6d2c434fc84680c7。测前预测、候选排名及主分析规则均有封存哈希。
测量：51 组主体任务，加 6 组 P1 反转顺序配对。246 条正确性检查，294 条正式计时记录、29,400 个原始计时样本；四份 Nsight 追踪各含三次执行，独立于性能标签。
回收：279 个文件、17,927,152 字节逐一校验大小和 SHA256；最终 manifest SHA256 2683510242c1a0a564aae2d9168134cee7e09272da8012c19148837af79017e8。18 个保护文件哈希未变。
P2 每形状有三种子正确性检查、三个独立验证进程区组，以及一个单独的候选选择区组。性能验证使用固定种子；不能将三个验证区组称为三个不同输入种子。
统计单位是形状和进程区组；每条记录中的 100 次连续采样不是 100 个独立实验。主表对三个进程中位数再取中位数，逐区组损失另列。

二、P1：条件性机制证据
既有形状 (P,M,K,N)=(8,512,8192,512)。三个输入种子，每个种子正序与完全反序各一个区组；两个主要比较均有三次正序、三次反序。

比较                              六组配对加速比中位数    更快区组
pipeline / pipeline_serial         1.169×                  6/6
q4/g2 / q4/g1                      1.686×                  6/6

各候选的区组延迟中位数：serial 5136.46 µs，pipeline 4424.17 µs，q4/g1 1607.17 µs，q4/g2 952.66 µs。加速比使用区组内配对后的中位数，不由这四个汇总值重新相除。
原先六组未充分反转顺序的结果全部保留为次要复测，对应加速比 1.184×、1.705×；没有根据成绩选择主结果。新增主配对在任何性能标签出现之前即已指定，详见 SCOPE.txt 和远端测前修正回执。

serial/pipeline 的操作与缓冲完全相同。四份追踪均核对了八个设备、三个 execute 区间及全部操作区间；每 GPU 各有 24 次 GEMM，serial/pipeline 另有 42 次 NCCL kernel。
serial 与 pipeline 的 cudaStreamWaitEvent 调用在三次执行中分别为 2676、2256，即每次执行减少 140 次，恰好对应依赖图计数差。NCCL 内部也使用事件，因此全部 API 总数不能直接等同于本项目依赖图计数。
这支持“依赖策略改变会影响整程序执行成本”。CPU 提交开销与设备依赖同时变化，不能把全部 1.169× 收益解释成通信隐藏。

q4/g1 与 q4/g2 的追踪 API 调用计数相同，但内核配置不同：
项目                         q4/g1                 q4/g2
grid                         8×4×4（128 CTA）      8×2×4（64 CTA）
threads / CTA                128                   256
registers / thread           140                   134
dynamic shared memory / CTA  36,864 B              61,440 B
主 tile                      64×128×32             64×256×32

这说明 grouped-N 同时改变 CTA 数、线程数、共享内存需求和数据复用组织，不能只按逻辑读字节减少来解释性能。上述寄存器/共享内存为内核资源声明，不是实际占用率或物理流量计数；本轮没有据此估计 HBM/NVLink 带宽或因果通信隐藏比例。
追踪中 serial 的同 GPU NCCL/GEMM 时间交集为零，pipeline 仅两个 GPU 出现短交集，不能据此宣称广泛而充分的通信隐藏。profiler 耗时明显扰动执行，因此正文性能只使用无 profiler 配对计时。
Nsight 的会话级 CUDA/NVTX/OSRT 完整性提示全部保留。所需应用区间和预期 kernel 数均已逐设备核实，但不把它写成整个进程追踪绝对无丢失。工具过程记录见 trace-manual-review.json，不必以工具告警组织论文主文。

三、P2：六形状独立评价
这里评估的是封存数值评分头的迁移表现。严格 predict 接口仍拒绝六个新执行身份；没有伪装旧 context/source 哈希，也没有把诊断评分变成已获准部署的推荐。
候选总计 13 个；主评分只覆盖已有实现支持的 11 个，未训练支持的 q16 仍做正确性和 oracle 评价。14 条数值失败涉及 b3/b5/b6 上的两种 q16，共六个形状—候选组合；失败主导后续准入，不因其他种子通过而恢复。最终数值有效表面为 72/78 个组合。没有以 FP32 新候选替换失败项。

每形状的 102 种候选排列均得到逐位相同的分数和排名；没有穷举 13!。逐候选独立评分与按分数/host 身份/候选 ID 的规范平局规则没有位置特征，详见 order-invariance.json。
严格 top-1 命中 2/6；top-1/2/3 的 oracle 保留数为 2/6、3/6、5/6。所有实测最优都在原先支持的 11 候选内，因此本轮 top-1 损失来自支持范围内的排序，不是 q16 未进入模型造成的 oracle 覆盖损失。

原主协议的平均≤1%、最大≤3%、完整候选表面与双向>2%覆盖未全部通过；这是完整完成的一次评价，不能改写为主评分通过全部验收。

四、问题归因：本轮能够区分什么
1. 数值准入：q16 FP16 分片/归并路径在部分形状超出原数值契约；保留 14 条失败，不单独把原因归给某一次归并操作。
2. 顶部排序：b1/b2/b3 都把 q8/g2 排第一，但实测最优分别为 q2/g1、q4/g1、q4/g2。b1 的 oracle 排第六，前三名筛选仍漏掉；b2/b3 的最优位于前三名，独立测量能纠正。说明这里首先是分片深度与尾部/并行度耦合的排序边界。
3. 选择与验证转移：b4 的 oracle 已在前三名，但独立选择区组把 q4/g2 测得更快，验证汇总却是 q2/g2 更快，损失 1.7355%。不能把这项剩余损失完全归因于评分排名。b1/b2/b4 的区组最优也会改变；不把毫秒量级自动理解成绝无波动。
4. 表达可识别性与适用范围：主模型训练只有三个形状，K 均为 8192；六个冻结形状的 K=3072/6144 都是外推。45 个系数对应存储设计矩阵秩 28，prepared/log_P/log_K/log_SM 在训练中恒定。岭正则仍给出定义良好的解，但不能从这些训练点独立识别全部因素。没有证据将本轮错误唯一归为优化器未收敛，或据此断言增加参数即可解决。
四个汇总误选形状在各自全部三个验证区组中均有正损失，不能以“存在区组波动”抹掉直接 top-1 的排序问题。支持范围内共有 55/330 对候选方向翻转；整体排序大致可用与最顶部排序不够可靠可以同时成立。
当前主模型是对数耗时岭回归，不是采用交叉熵/Muon 训练的分类网络。本轮没有更换损失、训练方式或优化器。此处归因用于界定论文结论，不启动新一轮拟合。

五、能写入论文的结论与材料边界
可以写：一个既有点上，同工作依赖放宽稳定降低整程序延迟；grouped-N 的收益伴随实际内核资源配置变化，需与并行度和分片代价共同讨论。
可以写：六个测前冻结形状上，封存评分用于少量候选筛选具有条件性价值；直接 top-1 没有超过固定 q4/g2。应同时报告固定策略、独立选择、数值失败与最坏区组。
不能写：已验证双向 host/fused 分类；绝对耗时预测普遍准确；时间线证明大部分通信被隐藏；已在真实 BF16 MoE/vLLM 中获得 EDM-IR 端到端加速。
P1/P2 不再扩展；真实 MoE 引擎接入/A-B 仍按原决定暂缓。后续工作是论文图表与投稿材料收尾，不把本轮成绩作为再次上卡改预测器的理由。
