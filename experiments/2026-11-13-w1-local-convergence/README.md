# W1 本地修改与验证交付

2026-11-13。执行顺序：归并精度与候选准入 → 同执行条件评分 → q、g 与并行度耦合。仅使用既有四个 W1 开发形状，没有读取、哈希或修改六个冻结形状，没有连接服务器或启动 GPU。

当前结论：**精度失效机制和准入边界已在本地查清；有效候选评分已补齐；新增耦合表达没有赢过对照，保留为诊断，不替换生产选择器。** 下一步需要验证新 CUDA 路径和采集执行条件，不能把 CPU 算术重放当成 GPU 实测。

## 1. 归并精度与候选准入

原 CUTLASS split-K 的片内累加是 FP32，但每片的输出是 FP16，后续片会读回这个已舍入的值。原递推为 `D_i = FP16(dot_i + FP32(D_(i-1)))`，不是末尾只转一次 FP16。

本轮对四个形状 × 三个既定种子的全部输出做 CPU 重放，共 113,246,208 个元素。120 组 q/g 误差摘要在归档记录的有效精度内全部吻合，通过/失败判定也全部吻合。FP32 片间存储、末尾一次 FP16 转换的重放没有超限元素，最大 scaled error 为 0.000488043。详见 `arithmetic-comparison.json` 和 `arithmetic/`。

这只验证了既有二进制精确分数输入的算术机制：不是真实 MoE 激活分布、不是 BF16，也没有验证 GPU 同步或逐元素 GPU 输出。

已实现独立的 `_fp32reduce` 候选路径：原 SM80 GEMM 使用 FP32 C/D 中间矩阵，保持原片间信号量顺序，完成后在同一流启动 FP16 转换。它拥有独立实现身份、按算子分配且对齐的工作区，并显式计入新增存储/转换项。旧路径默认行为与旧候选身份保留。

新路径的 CUDA 翻译单元**尚未通过 nvcc 编译或真机验证**。本机没有 CUDA 工具链。主机侧契约、工作区溢出/边界、生成代码已验证；不能据此宣称新内核可用或更快。

准入绑定形状、实现、构建/执行身份、输入与参考文件哈希、误差契约及全部三个种子。任何一个种子失败则拒绝；少一个种子则未知。未知与失败候选均不补造耗时。没有把 q8 整体封禁：M256 的有效 q8 保留，M512 的失败 q8 排除。新 FP32 候选的旧计时和通过状态均不继承。

误差标准保留 `max(abs(error)/max(1,abs(reference))) <= 0.02`，不是通常的 atol+rtol allclose。新采集器会记录精度与误差契约，成功检查也用 17 位有效数字输出；旧归档不改写。

## 2. 同执行条件评分

重新校验了 129 个回收文件和 207 个封存源码文件。52 个主候选组合中 42 个通过全部正确性检查、10 个失败。4 个 pipeline 对照属于另外的采集阶段，只保留在审计附表，不混入主候选评分。

旧历史预测只有 19 个同时具备分数且在 W1 合法的组合；本轮对 42 个合法主候选全部给出同条件分数，失败候选全部排除。host、merged CUTLASS host、merged cuBLASLt host 的身份分开；cuBLASLt 的内部 tile 几何保持未知。

为了检验“新增表达是否有帮助”，采用固定 ridge 系数 0.01 的共享 log-time 评分器作受控诊断：相同权重、相同训练数据、相同整形留出，仅比较特征表达。每个形状的候选、种子、重复进程始终在同一折，标准化只用训练折。没有搜索优化器、学习率、种子或验证集参数。**这个原表达对照不是旧 AdamW 模型的复现，不能把二者的错误数直接比较。**

|整形留出的开发形状|两种表达的选择|实测中心最快|选择损失|
|---|---|---|---:|
|grouped|q8/g2|q8/g2|0.00%|
|M512|q4/g2|q4/g2|0.00%|
|large-N|q8/g2|q2/g1|5.26%|
|M256|q8/g2|q8/g2|0.00%|

平均选择损失 1.31%，最坏单次进程选择损失 5.83%。这是四个已参与研究的开发形状上的留出诊断，不是独立泛化验收。四个形状均为 fused 占优，也不能据此证明双向 host/fused 选择可靠。

## 3. q、g 与并行度耦合：负结果保留

新增表达包括每 CTA 的 warp 数、每 SM 的网格 warp 数、操作数暂存下限、K 分片深度与参考调度轮数/填充的耦合、片间回读流量、A/B 逻辑复用、host 通信组数和整程序启动数。FP32 新路径额外列出中间矩阵和转换启动。所有量都来自形状与源码，不从耗时反推；逻辑字节不是实测 HBM/NVLink 流量，参考调度轮数不是实测占用率。

g 从 1 到 2 时，输出 CTA 数约减半，但每 CTA warp 数由 4 变 8；三阶段操作数暂存下限由 36 KiB 变 60 KiB。q 增大同时改变 CTA 数、每片 K 深度、片间读写及等待链。只增加并行度计数会漏掉这些同步变化。

然而，新增表达的成对方向错误 **29/201 → 30/201**；MAPE 从 23.78% 降为 22.78%，最优选择未改善。M512 少错一对，M256 多错两对。不能用平均误差下降掩盖排序退步，故不提升为默认选择器。所有错误对及三轮差值均在 `round-05/*-<shape>.json`。

large-N 仍然把 q8/g2 估成 453.13 μs，实际 620.50 μs；q2/g1 估成 737.67 μs，实际 589.50 μs。方向仍错，必须保留。

留出 large-N 后，训练形状的 K 全是 8192、N 最大 1024，而待预测点为 K=4096、N=2048：K 与 N 同时外推，不能从剩余数据识别独立 K 效应。留出 M512 后 M 也超出训练的 64–256 范围，尽管它恰好选对。评分输出现在明确记录这些范围。

新增表达有 45 个系数，各折设计矩阵秩为 26。ridge 能给出确定解，并不意味着这些系数对应唯一物理机制。现有完整算子耗时不足以分辨 CPU 提交、CTA 活跃度、片间等待、远端访问和资源争用；继续据此加参数追分没有新证据。

- `arithmetic/`、`arithmetic-comparison.json`：12 份完整 CPU 算术重放及 120 组旧 GPU 摘要对照。
- `gpu-bundle-v2/`：当前待验证执行包。四个原形状，每形状 13 个原候选 + 4 个 FP32 候选，24 个进程组。输入/参考仍使用封存文件，不重新生成，不含新形状或旧预测标签。`gpu-bundle/` 是补充采集器精度校验之前的封存准备版，不用于下一次执行。
- `local-performance.json`：13 候选进行 1,000 次本地选择，包含冷启动，总耗时约 0.40 秒，中位约 0.36 ms。查询上限 32 候选，训练上限 256 行。该实现用于离线选择与诊断，没有接入逐 token 热路径。
- `validation/`：测试回执与日志。新准入/评分/采集契约 15 项、既有 backend 14 项、旧分析 6 项、采集恢复 3 项；C++ 契约/工作区及四组 registry 另行验证。

`round-01` 保留旧执行账本哈希拒绝 W1 运行时的记录，没有绕过旧审计或更新旧哈希；W1 改为独立验证源码并复用几何公式。`round-02` 保留报告字段重复的脚本错误。`round-03` 是首个完成的固定评分比较；04/05 仅增加外推/可辨识性记录及尚无标签的 FP32 成本字段，选择与主结论不变。这些轮次不是按验证结果调参追分。

主要实现：`EDM-IR/edmir/compiler/w1_candidate_selection.py`、`EDM-IR/tools/review_w1_local_convergence.py`、`EDM-IR/tools/replay_w1_precision.py`、`EDM-IR/tools/prepare_w1_precision_gpu.py`；CUDA 路径在 `EDM-IR/runtime/src/nccl_device_fused_cutlass.cu`。

## 下一步只补必须依赖设备的证据

1. 先在 Linux CUDA 12.8 环境编译新包；编译本身不需要 GPU。本机主机侧测试不替代 nvcc。
2. 8×A100 SXM、NV12 完整互访的同一执行条件下，先检查 M512 的 FP32 q8/q16、g1/g2 全量输出，再按包内顺序验证四形状三个种子。只对合法候选计时，不凭重放通过放行。
3. 主计时保持 20 次预热、100 次完整执行、三个独立进程，计入 CPU 提交、通信、归并和最终转换。主计时不开 profiler，新构建记录独立身份，保留原有效候选作当轮对照。
4. 随后按预算另采 M256 的 q4/q8 × g1/g2、large-N q2 与 q8/g2、M512 FP32 q8/g2 的时间线。包内提供独立 Nsight Systems case；SM 活跃度、共享存储/寄存器和停顿指标还需设备上的 Nsight Compute 检查，不能从 Systems 时间线冒充得到。

到这里暂停本轮：需要真机决定新归并路径是否正确、开销是否值得，以及未建模执行条件究竟是哪一项。当前仍不声明独立泛化、BF16、真实 MoE 或 serving 加速。
