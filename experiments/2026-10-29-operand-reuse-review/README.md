# A/B 复用审查：2026-10-29

这一轮补上了显式的操作数复用模型，但没有降低误选数。它区分同一 GEMM 内的 tile 复用、同一目的 GPU 上多个源 GEMM 共享权重，以及重复执行后的缓存状态。结论是：**这些差异值得表达，但本轮的容量与访问顺序模型仍不能解释短 K 的选择反转，不能据此修改评分系数。**

保留评分模型仍为 **3/41** 误选；此前未通过验收的 `M_work_extension` 实验仍为 **2/41**。两者全部候选分数与上一轮逐项相同。没有新训练、GPU 费用或冻结六形状的读取评估。

## 确认的源码事实

当前 P4 执行包中，每个目的 rank 只有一个权重缓冲区，来自四个源 rank 的 GEMM 读取同一权重。以 rank 0 为例，操作索引为 0、4、8、12，源依次为 0、1、2、3，权重均为 buffer 1。它们使用目的 rank 的 compute stream。历史 runtime 源码按依赖拓扑提交执行，并在该 stream 记录完成事件。

这支持“跨源 GEMM 复用同一权重地址”的表达，**不等于四次读取只产生一次物理显存流量**。其他 GPU 的远端读取、CTA 调度、缓存映射和驻留状态仍可能影响流量。当前生成头文件与历史 runtime 源码也不能代替未归档的历史可执行文件。

证据及摘要在 [run-01/audit.json](run-01/audit.json)。

## 本地模型与结果

实现：[operand_reuse_model.py](../../EDM-IR/edmir/compiler/operand_reuse_model.py)。它按有效张量元素构造 A/B/C 面板访问，在字节容量限制下执行全相联 LRU。面板不是硬件 cache line；每个 CTA 完整执行后的引用顺序是条件假设，不表示实际 CTA 串行运行。

本轮固定 20 个候选配置，遍历 4 种容量、2 种 tile 顺序、2 种远端 A 缓存位置，共 **320 组**。每组两遍：空缓存开始，再保留上一遍状态。所有场景保留，未按旧误选挑选“最佳容量”。

| 检查 | 结果 | 能说明什么 |
| --- | --- | --- |
| 短 K 的 q2/direct 配对 | 80/80 对的第二遍 A/B 未命中字节相同；q2 的 C 未命中不减少，写入增加 | 本层缓存模型没有给出 q2 的输入流量收益，无法单独解释 N=512 上 q2 更快 |
| 40 MiB 容量场景 | 80/80 组第二遍 B 未命中为零 | 在这些理想驻留假设下，权重容量不足不是解释；不能推广为真实硬件全命中 |
| 相同工作计数的两种形状 | 部分小容量场景的 A/B 未命中明显不同 | 总 FLOPs、CTA 数和逻辑字节数不足以表达复用；新增表达确实可区分这两个输入 |
| 原评分与 M 外推评分 | 全部候选分数不变；误选仍为 3/41 与 2/41 | 本轮是机制审查，未取得选择准确率提升 |

具体例子：P4、K4096、q2、M-fast、远端 A 可缓存，假设可用容量为 8 MiB，第二遍中 M64/N2048 的 B 未命中合计为 64 MiB，而 M256/N512 为 0。改为 40 MiB 后，两者均为 0。**这是容量假设敏感性，不能把 8 MiB 场景当作 A100 实测或按它决定 q2/q4 顺序。** 这里统计一个目的 GPU 消费所有源 GEMM 的逻辑引用，并不统计全机缓存流量。

这一批单目的模型的最大条件驻留集合为 22 MiB。NVIDIA 官方说明 A100 L2 总容量为 40 MB，分为两个分区，并存在驻留控制和数据压缩。因此，总容量不足以证明实际驻留、远端 A 放置或访存时间；本实现没有替这些未知量指定物理数值。[NVIDIA 原始技术说明](https://developer.nvidia.com/blog/nvidia-ampere-architecture-in-depth/)

输出分别记录读命中、读未命中、写入、脏面板驱逐和剩余脏数据；没有将未命中乘一个任意带宽生成微秒标签。写分配不虚构一次整面板读取，结束时也不强制刷新缓存。FP16 是当前源码合同；BF16 不借用这批行为做校准。

## 验证与资源界限

- 43 项本地测试通过，包括独立 LRU 参考、共享/独立权重、容量为零、尾部、split-K 读写恒等式、远端缓存位置和超时拒绝。
- 320 组共 6,152,704 次逻辑引用，review 总计约 3.49 秒，单组最大约 54.5 ms；这是本机 Python 耗时，不是 GPU 预测。
- 单组执行前限制 100 万次引用，驻留面板不超过 10 万，默认 CPU 时限 2 秒；整个 review 时限 60 秒。
- 129 个先前源码/结果哈希及 22 个受保护文件哈希保持不变。冻结六形状只计算哈希，没有解析、评分或训练。
- 记录：[design-before.json](design-before.json)、[run-01/results.json](run-01/results.json)、[verification.json](verification.json)。
