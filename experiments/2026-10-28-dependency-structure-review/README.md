# 本地结构修改：并行主循环、串行写回与资源限制

2026-10-28。本轮不训练、不调整已有系数、不读取或评分冻结六形状、不启动 GPU。新增条件执行模型，完成一个预先固定的参数不变对照。**没有得到可以替换现有评分器的新版本：现有误选仍为 3/41，最坏选择损失 1.5801%。** 失败对照和未标定量均保留。

## 新实现解决的表达问题

[dependency_wave_model.py](../../EDM-IR/edmir/compiler/dependency_wave_model.py) 将单次源 GEMM 表达为两类任务：各分片的主循环可以并行，同一输出 tile 的 epilogue 按分片顺序更新输出。等待中的 CTA 仍占驻留资源。没有把整个分片主循环串行化，也没有将 q−1 当成额外 kernel launch 数。

在明确的“相同驻留槽、指定入场顺序、给定服务时间”条件下，实现递推：

```
end[t,s] = max(start[t,s] + a[d,g], end[t,s-1]) + e[s,g]
```

`a` 包含主循环及到达 semaphore 等待前的独立工作；`e` 包含有序输出更新和 release。q1 与 serial split-K 的首个 epilogue 可以不同。程序提供 partition-major 和 tile-major 两种入场场景；它们不是对 CUDA 实际调度顺序的断言。

模型同时计算任务数、独立输出链数、依赖边、tile 尾部有效比例、逻辑读写量、工作量/槽数与依赖关键路径下界。驻留等待的总槽时间单独记录，不能把它直接加到端到端关键路径上。q1 自动退化为相同任务的分 wave 执行；只有一个槽时退化为串行服务总和。

grouped-N 的 tile 宽度、线程数和共享存储需求分别记录。对于当前三个 stage 的模板，窄/宽 CTA 的操作数共享存储负载分别为 36/60 KiB。结合架构资源只得到每 SM 至多 4/2 个 CTA 的上界；寄存器、epilogue 存储、实际 carveout 和其他内核还可能降低它。**上界不是实测 occupancy，也不是端到端模型的容量参数。** 架构约束来自 [NVIDIA Ampere Tuning Guide](https://docs.nvidia.com/cuda/ampere-tuning-guide/index.html#occupancy)。模板和 semaphore 顺序核对固定 CUTLASS `dcf215af68a2d08d305076c152a06f201728cd53` 的 `gemm/kernel/gemm.h`、`mma_base.h` 和 `default_mma_core_sm80.h`，以及本仓库 `cutlass_sm80_gemm.cuh`、`nccl_device_fused_cutlass.cu`。

服务时间未标定，接口不会把旧的整程序拟合系数当作 `a/e`。缺证据时返回 `prediction_us=null`、`chosen=null`。用于检验递推的固定数值全以 `synthetic_units` 标识，不能当作新 GPU 预测或标签；没有用拒绝判断降低旧模型的误选统计。

## 短 K：仅增加 wave/occupancy 表达仍然不够

| `(P,M,K,N)` | direct CTA 数 | q2 CTA 数 | 旧实测 q2−direct，μs |
|---|---:|---:|---:|
| (4,64,512,128) | 1 | 2 | +8.0 |
| (4,64,512,256) | 2 | 4 | +3.5 |
| (4,64,512,512) | 4 | 8 | −2.0 |
| (4,64,512,1024) | 8 | 16 | +1.8 |
| (4,128,512,512) | 8 | 16 | +4.9 |

在均匀入场、独占设备、每 SM 至少一个可运行 CTA、服务时间不随网格负载变化的条件下，以上都能同时入场。递推退化为 `a + e_first + (q−1)e_later`。因此 q2−direct 的差值不随输出链数量变化。即便允许 direct 与 serial 的首阶段服务不同，也仍不能解释上述方向变化。

这排除了“只增加 wave 数就能解释三个错误”的简单方案，**没有排除真实服务时间随访问负载变化、实际调度差异或程序外围开销**。旧标签是整程序 wall-time，不能据此认定哪个硬件机制负责。也不能将上述结论推广为任意 GPU 的占用率与并行度无关。

## 参数不变的容量替换对照：明确拒绝

实验前写入 [design-before.json](design-before.json)：只将经验压力项中的容量 32 替换为 108；深度曲线、非深度系数、公共偏移、host 模型全部固定。训练锚点残差按底座变化作代数平移，保留相同锚点耗时；不读查询标签，不拟合、不重新选择参数。

| 相同 41 个开发形状 | 保留版本 | 容量 108 对照 |
|---|---:|---:|
| 误选 | 3/41 | **10/41** |
| 平均选择损失 | 0.0802% | 1.9628% |
| 最坏选择损失 | 1.5801% | 19.4728% |
| host/fused 方向错误 | 0 | 2 |

新增 7 个错误，原 3 个短 K 错误均未修正。三个固定压力切分也退步：全部 M512 留出从 1/3 错到 3/3；全部 N2048 从 1/5 到 4/5；全部 host 优势点从 0/3 到 3/3。

该对照只能说明：**保留旧系数时，不能把经验容量直接替换成 SM 数。** 它不是对物理模型的否定。现有容量项吸收的整程序代价未被识别为独立硬件服务。

grouped 四格中，q8/g1 的旧压力项为 +117.378 μs；其他三格均为零。直接替换容量会去掉这项，使原本慢的 q8/g1 被选中，选择损失 11.9621%。这暴露了经验压力项的作用，不能把 117.378 μs 宣称为实测通信或驻留损失。

## grouped-N 与 M512 应分别怎样解释

grouped 四格在上述一槽/SM 场景下都能同时入场。因此，只比较总 CTA 数或 wave 数不够。条件模型的 q×g 交互为：

```
[a_g2(32)-a_g2(64)] - [a_g1(32)-a_g1(64)]
    + 4*(e_later_g2-e_later_g1)
```

它明确需要宽/窄模板随深度变化的服务，以及累加写回服务。旧端到端四格交互差值 −171.1 μs 不能独立识别这些量；原预测 −137.495 μs 的误差仍保留，没有靠对角胜负掩盖。

M512 的单独留出错误 `(4,512,4096,512)` 则首先是 host 外推问题：

| 候选 | 原预测 μs | 旧实测 μs | 预测误差 μs |
|---|---:|---:|---:|
| host | 835.999 | 1079.900 | −243.901 |
| q2 | 1056.826 | 1005.900 | +50.926 |
| q4 | 1054.888 | 1049.800 | +5.088 |

q2−host 的预测差为 +220.828 μs，实测为 −74 μs；总分差误差 294.828 μs 中约 82.7% 来自 host 的低估。这是有符号预测误差的算术分解，不是硬件耗时占比。此点没有同 M/N 的 K 锚点，host 使用原底座，不能把结果归因于新 tile 曲线已经验证的跨 M 外推。

仅在诊断中把 host 时间替换成实测值，仍会选 q4，损失 4.3643%。该替换是带标签的反事实诊断，不是可部署预测。因此 M512 需要同时检查 host 的 M 扩展与 q2/q4 排序，不能指望同一个 split-K 压力补丁全部解决。

## 验收与上机边界

本轮通过的是结构与复核检查，不是预测可靠性验收。测试覆盖递推极限、独立枚举对照、单位缩放、尾块计数、资源上界、输入精度与遍历上限；对照测试覆盖系数不变、训练锚点保持、标签无关、顺序无关、整形状隔离。完整结果与运行时间见 [verified/results.json](verified/results.json)，最终测试数量与文件哈希见 [verification.json](verification.json)。

- 41 形状/346 候选的旧评分逐值不变；原 3 个错误没有被隐藏。
- 现有四折模型及三个压力切分直接读取保存状态，没有训练调用；冻结六形状只核对文件哈希。
- 每次复核限时 60 秒；每个条件模型最多 4096 CTA，遍历复杂度 `O(B log min(B,C))`。没有后台任务、GPU 或租机费用。
- 默认编译器、已封存上机包、历史测量和预测结果保持不变。当前新增模块是条件结构模型，不准入自动选择。

本轮的停止边界已经具体化：先用已准备的同身份成对测量确认方向；若稳定复现，再对错误点单独记录设备执行、CPU 提交/同步区间及实际 kernel 资源，区分程序外围和设备服务。profile 窗口与主计时分开，不能将 kernel 时间或等待简单相加当作 wall-time。**现有采集包提供端到端重复和编译日志，尚不提供主循环/epilogue 的独立标定。** 没有这些观测，不给新条件模型补造微秒常数。
