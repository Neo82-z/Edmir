2. 远端 CPU 准备与验收
建议 4–8 vCPU、16–32 GiB RAM（优先 32 GiB）、约 200 GB 可复用存储；最终按镜像展开空间和平台规格核算。不在 CPU 上完整载入 62 GB 权重推理。
只准备一个模型：zai-org/GLM-4.7-Flash，revision 7dd20894a642a0aa287e9827cb1a1f7f91386b67，48 分片共 62.44 GB。
固定 vLLM 0.20.1 linux/amd64 镜像摘要 bf0486e51765766a069f6eb26a63a06748859a568b24200acd3aa4edb58f3d35，镜像层约 8.23 GB，配置声明 CUDA 13.0.2。算子继续用既有 CUDA 12.8.1 / NCCL 2.28.9 环境，两者分开运行。
全部可复用内容落卷：权重、tokenizer/chat template/config、OCI 镜像包、算子二进制和依赖、请求清单及校验回执。不能只把环境安装在 CPU 系统盘；卷迁移不会自动带走该系统盘的 Docker 缓存。
验收必须完成：
— 模型逐文件 SHA256/大小，以及 tensor header、dtype、shape、offset、索引一致性；无需分配完整权重。
— 镜像 manifest/config/layer 摘要、amd64 平台、便携包和离线导入。
— 固定实际镜像内断网加载 config/tokenizer，比较原始 tokenizer、Transformers 与 vLLM 分词，验证 chat template；保留并解释 regex 警告，不静默修补。
— 冻结八条请求的 token IDs；验证 engine-args 构造和模型注册，保存软件版本及入口代码哈希。
— 在 CPU 阶段完成卷解绑、重挂、资产读取验证，确认资产未放错盘。
— 算子执行包与固定队列的静态检查及 dry-run。

3. 八卡上只执行封存的两项任务
A. 大 N 复测
固定开发形状 (P,M,K,N)=(8,64,4096,2048)。候选为 q2/g1、q4/g1、q4/g2、q8/g2、merged CUTLASS host、merged cuBLASLt host。精度与归并配置按原包固定，不与原生 BF16 标签混用。
三个既有输入种子 × 六种 Williams 平衡顺序，每个候选均占据各位置一次、每个有向相邻候选对出现一次；区组再按固定种子打散。
先做三个种子的数值检查；任一种子失败的候选不进入正式计时，保留失败证据。每候选 20 次预热、100 次 execute+synchronize；最多 108 条计时记录、10,800 个原始样本，pilot 单列。
回来比较种子、位置、前序和进程区组下的排名/选择损失。100 个连续样本不是 100 个独立环境；平衡顺序不能证明温度等因素完全消除。排序若仍不稳定，保留不确定性，不制造单一赢家来训练。
六个冻结形状不参与本轮；本轮数据属于开发诊断，不作为独立泛化证据。

B. 原生 vLLM
同一八卡、同一个固定模型；BF16，TP4 / DP2 / EP8。20 个注意力头可被 TP4 整除，64 个专家可被 EP8 整除；这只是必要配置检查，不是实际分布式运行证明。
候选配置为 eager、Triton MoE、Triton MLA + FA2 prefill、allgather/reducescatter、每卡 2 GiB KV cache，关闭 EPLB/prefix caching/speculative decoding。经固定镜像 CPU 参数验收后封存。
八条固定请求，使用模型 chat template，关闭 thinking。完整并发批次预热两轮，再计三轮原生基线。保存输出文本、输入/输出 token、完成及失败原因、流式可见 TTFT/TPOT、整批有效输出吞吐。加载、首次 JIT 和预热单独计时。
路由诊断另起进程，保存 token×layer×top-k 原数组，不把诊断耗时作为性能标签。按固定版本源码识别 47 层缓冲，排除第 0 层 dense 零占位，统计 MoE 层 1..46；实际数组仍须上 GPU 核验。
官方返回没有 scheduler step 和 EP source rank，只能形成请求级路由证据，不能据此声称得到每步每卡专家 M/padding 分布。GLM 逻辑投影维度也不同于原四点，不能直接套用原加速比。
本轮成功意味着进入真实 MoE 调用，并拿到原生基线；后续方法收益仍需 BF16 完整层替换正确性及同条件 A/B。

4. 执行顺序、时间与停费
顺序：硬件及运行身份核验 → 大 N 数值检查和复测 → 结束算子进程 → 原生模型加载/预热/基线 → 单独路由诊断 → 回收校验与平台停费。
大 N 计时期间不驻留原生模型；两个任务不并行争抢 GPU、显存和通信资源。性能计时与诊断/profiler 分开。区组间或计时结束后回收，不让后台传输干扰正式样本。
一小时仅是排程目标：环境核对约 5 分钟，大 N 主体约 22 分钟，原生部分暂留约 23 分钟，回收预留 10 分钟。大 N 为旧数据估算；原生首次启动/JIT 未实测，不能保证一定塞进该窗口。远端 CPU 测完镜像导入/读盘开销后重新核算，必要时提前缩减可选诊断或调整窗口，不能现场无限延长计费。
CPU、存储、出站流量、GPU 均计入总支出。先展示具体报价和资源释放条件，再执行；今天没有付费操作。卷保留到何时要单列，避免再次长期无意扣费。
GPU 阶段从预装卷读取并禁止在线下载。镜像导入、权重加载和首次 JIT 仍需时间；CPU 不能证明真实驱动、NVLink/NCCL、跨卡启动和 GPU 数值执行已通过。设备特有失败保存证据，按退出规则处理，不开展开放式现场调试。
回传文件核验后在平台停止/删除计算；停止进程不等于停止计费。
