# M512 与大 N 边界复查（2026-10-21）

**本轮完成了定位、候选修改和复查，但候选没有通过稳定性验收，不替换上一版已验收模型。** 主检验的 M512 误选已经消除，更严的检查仍发现回归。代码测试通过与预测器可靠性是两件事。

最终判断见 [`verified/decision.json`](verified/decision.json)。上一版 [`additive-selector-repair/verified`](../2026-10-21-additive-selector-repair/verified/) 的源码和证据保持不变。本轮没有 GPU 操作，没有新增独立标签。

## 1. M512：不是程序慢，是 host 曲线外推方向不稳定

旧模型采用 `K*log2(ceil(M/64))`、`K²*log2(ceil(M/64))` 表达部分 host 成本。同一 M512，在不同留出条件下会产生相反的代价误差：

| 检验与形状（P4，M/K/N） | host 实测 | 旧 host 预测 | 误差 |
|---|---:|---:|---:|
| 留 M/N 组，512/2048/512 | 0.7279 ms | 0.6541 ms | −10.14% |
| 留 M/N 组，512/4096/512 | 1.0799 ms | 0.8360 ms | −22.59% |
| 留整个 K，512/8192/512 | 1.5298 ms | 2.3381 ms | +52.84% |

同时，旧模型把 M512/K4096 的 split-K=2 从实测 1.0059 ms 高估到 1.0894 ms。两边的误差共同导致错误选择 host，不能只修 host/fused 判定阈值。

候选做了这些修改：

- host 输入规模改为耦合的 `M*K` 基函数，保留线性项和训练内选择的分段项；不再用 `K²*log(M)` 代替输入规模变化。
- fused 分开表示基础 output tiles 与额外 split-K tiles，避免把 q=1 的工作与分区开销绑在同一系数里。
- 对训练耗时采用相对误差权重，减少慢候选的大绝对误差对拟合的支配。这些权重只来自训练标签；预测接口不接收测量耗时。

在主检验和留 K 检验中，M512 的 K2048、K4096、K8192 都分别选对 **q2、q2、host**。四个原重点形状也保持全对。

**但还不能说 M512 全面解决：** 留出 M512 组以后，再删除训练中的 `m256-n512-longk` 组，M512/K4096 会重新选择 host，损失 7.36%。其他两个 K 值在 8 次删组中均保持正确。这个反例说明当前修正仍依赖邻近 M 的校准证据。

## 2. 大 N：同时存在形状混淆与选参不稳定

旧模型在 M64/K4096/N2048 上把 host 从 0.6453 ms 预测为 0.6850 ms；把 fused q4 从 0.7209 ms 预测为 0.7130 ms。真实约 11.72% 的 host 优势，被压缩到约 4.09% 的预测优势。

本轮 host 的 N 方向改成分段深度与 log(N) 的耦合，主检验 host 预测降到 0.6398 ms，已接近实测。可是 fused q2 被预测为 0.6721 ms，实测是 0.7248 ms，仍然偏乐观。

还确认了一个结构缺陷：只用总 CTA 网格，无法区分 M 方向的 tiles 与 N 方向的远端 A 重读。下面两个已测候选在被完整复查的候选模型中具有相同 fused 特征：

| M/K/N，q4 | N 方向重读计数 | 实测耗时 |
|---|---:|---:|
| 64/8192/2048 | 16 | 1.1937 ms |
| 256/8192/512 | 4 | 1.0741 ms |

对完全相同的输入特征，任何固定确定性回归都只能输出同一个值；这两条数据给出的最坏乘性误差下界至少为 **1.0542 倍**。这是特征表示误差的界，不是选择损失，也不是机器噪声概率。完整碰撞与逐项误差见 [`diagnosis.json`](diagnosis.json)。

我另外试了 N 重读项、相同 M/K 的 N 配对校准，以及绝对/相对误差混合。这些探索全部保留：新增重读项在最大 N 留出折中未识别出非零系数；配对校准仍在留 K 时错选大 N；混合损失仍错排 M512 的 q2/q4。没有把这些失败探索当成已验收实现。

## 3. 平均分变好，稳定性仍未过关

下面是被完整审查的 `traffic_latency_selection.py` 候选；不同探索结果没有混在一张成绩表里。

| 指标 | 上一已验收版本 | 本轮候选 |
|---|---:|---:|
| 主检验平均选择损失 | 0.766% | 0.172% |
| 主检验最坏选择损失 | 16.074% | 2.632% |
| 留 K 平均选择损失 | 0.817% | 0.195% |
| 留 K 最坏选择损失 | 18.179% | 2.632% |
| M512 主检验与留 K 的六次选择 | 存在误选 | 6/6 最优 |

这些改善不足以支持替换，原因是：

- 上一轮大 N 的 1.1156% 协同标签修改反例，在新候选上已经不能诱发误选。
- **但新的固定种子 ±1% 扰动，34 组中有 2 组仍使大 N 错选 q2，损失 12.32%。** 32 组逐标签正负修改，加两组 host/fused 反向修改，全部重算训练权重和内层参数。
- 删除任一额外训练组的 8 次大 N 检验，只有 5 次保持 host，3 次错选 q2；上一版这项是 8/8。
- M512/K4096 的删组反例仍在。

这些是人为构造的模型压力测试，不是测到真实硬件存在 1% 随机噪声。也不能因旧攻击失败，就声称新的安全半径更大。条件 LP 仅在冻结训练权重、活跃约束和超参数时精确；只有完整重新训练确认的样例才记作有效反例。

`assessment.py` 现在明确拒绝“平均分通过、边界检查失败”的候选，也拒绝缺少压力测试记录的结果。最终状态是 **`local_accepted: false`**。

## 4. 代码与复现

- 实验候选：[`traffic_latency_selection.py`](../../EDM-IR/edmir/compiler/traffic_latency_selection.py)。没有接入默认编译器；host 仍严格标识为归档的 per-source CUTLASS，不能冒充 cuBLAS。
- 完整复查：[`verified/results.json`](verified/results.json)、[`verified/review_results.json`](verified/review_results.json)。
- 初始源码快照：`initial_sources/`。初次结果之后只补了反序列化参数类型检查，正式回放的模型数值与初次结果完全一致。
- 13 条结构探索路径及参数尝试保存在 `exploration*.json`、`paired_exploration.json`；这是自适应工程开发，不是独立验证或预注册实验。

在仓库根目录，用 Python 3.12 和本目录 `requirements-fit.txt` 中的依赖运行：

```bash
python3 experiments/2026-10-21-host-boundary-repair/run_review.py \
  --out /tmp/edmir-host-boundary-review
```

目录必须不存在。流程设置了训练、求解和进程超时。正式运行 **90 项代码/审查测试通过**，耗时约 **25 秒**；结果状态为 `completed_candidate_rejected`。这里的退出成功表示复查执行完毕，准入结论以 `decision.json` 为准。

已保存的 `verified/selector.json` 是未验收研究候选，不能替代上一版模型。它不需 NumPy/SciPy 即可做推断；41 个形状遍历平均约 5.19 ms。这个数值是 CPU 预测器开销，与 GPU 算子耗时无关。

## 5. 当前能确认与不能确认的事

可以确认：M/K 耦合和 fused 开销表达存在可修正的系统误差；M512 主检验已经能选对。也可以确认：目前候选把部分 N/M 形状映射到同一特征，并存在超参数切换带来的边界不稳定。

不能确认：两个问题已经彻底解决、剩余现象是 GPU 抖动、或者所有本地模型修法都已穷尽。本轮停止按已看过的外层结果继续追调，保留已发现的反例。

后续若补最少量的辨别性观测，应围绕 **相同 CTA 网格、不同 M/N 分配** 配对设计，例如 M64/N1536 与 M192/N512，在 K3072、K6144 上比较同身份 host、q2、q4、q8。它们用于辨别 N 重读与 M 扩展的影响；不是本轮已经运行的实验，也不足以单独声称完整候选集验证。新环境必须保留独立身份和计时边界。
