# 固定模型的问题定位：短 K 的结构限制与 grouped-N 的误差抵消

2026-10-28。本轮没有拟合、调整系数、搜索损失或改变选择策略。读取上一轮保存的四折模型，41 个开发形状的评分逐值相同，误选仍为 3/41。六个冻结形状未解析、评分或改动。工作收敛到三个剩余误选和一个脆弱的 grouped-N/q8 边界。

结论分成两层：**预测层已经定位到明确的表达限制和误差抵消；硬件层还不能在“收益高估”和“额外代价低估”之间作因果归因。** 现有端到端时间不能将两者拆开。

## 1. 三个短 K 误选，具体错在什么表达

形状顺序是 `(P,M,K,N)`。`direct` 是不做 split-K 的 fused 候选，不是 host。定义 `Δ=T(q2)−T(direct)`，正值应选 direct。

| 形状 | 预测 Δ，μs | 旧实测中位数 Δ，μs | 差值误差，μs |
|---|---:|---:|---:|
| `(4,64,512,256)` | -5.349 | +3.500 | -8.849 |
| `(4,64,512,1024)` | -3.708 | +1.800 | -5.508 |
| `(4,128,512,512)` | -4.371 | +4.900 | -9.271 |

三点都没有同 M/N、同候选 K 区间的残差修正，预测直接来自共享底座。逐项相减后，其他项全部抵消或为零：

| 形状中的 `(M,N)` | 深度曲线贡献 | 分片项贡献 | CTA 项贡献 | 压力项 |
|---|---:|---:|---:|---:|
| `(64,256)` | -39.008 | +33.333 | +0.326 | 0 |
| `(64,1024)` | -37.893 | +32.547 | +1.638 | 0 |
| `(128,512)` | -39.008 | +33.333 | +1.304 | 0 |

这些是模型内的贡献，不是实测的主循环、等待或归约耗时。公共截距和 host 参数没有进入差值，调整它们无法修复这三个 raw fused 排序。

对于 K512、g=1、q1/q2 都没有超过经验 capacity=32 的区域，现有模型严格退化为：

```
G = ceil(M/64) * ceil(N/128)
Delta_us = 1000 * (serial_stages + ctas*G/108 - depth_8_16/16)
```

这里 `ctas >= 0`，所以一个共用参数的 raw 差值只能随 G 不减。旧观测在 M64、K512 下为：

| N | 128 | 256 | 512 | 1024 | 2048 |
|---|---:|---:|---:|---:|---:|
| q2−direct，μs | +8.0 | +3.5 | -2.0 | +1.8 | +1.9 |

N128 与 N512 已形成反例：该 raw 函数族无法同时表达前者 direct 更快、后者 q2 更快。对这两个观测差值，共用单调函数的最大绝对误差至少为 5 μs。**这是此前发现的结构限制，在本轮采用的曲线迁移模型中仍然存在。** 它不是四折误选率下界：四折参数不同，训练锚点也可能改变其他点的最终预测。

所以，目前缺口不是深度曲线“还不够弯”，而是低并行度区域只留下了一个受限的 CTA 线性项，无法让分片净收益随实际执行并行度变化。

## 2. 为什么还不能直接说“同步代价少算了”

对已有七个 K512 形状构造 q2−direct 的特征差矩阵，四折都只有三个活跃列，矩阵秩均为 2。精确恒等式是：

```
serial_stages 增加 epsilon
depth_8_16 增加 16*epsilon
→ 所有这些短 K 差值保持不变
```

这是局部可识别性不足：这些对照只约束两项的组合，不能分别识别“深度缩短收益”和“串行分片代价”。它不表示整个训练矩阵秩不足，也不否认其他 K/q 观测能约束经验系数；但端到端标签仍没有把参数变成独立物理时间。

核对源码可确认以下执行事实：

- 当前模板为 SM80、FP16 输入/输出、FP32 累加、K tile=32、3 stages。
- q 增加分片 CTA，单次 GEMM 的 kernel launch 数仍为 1，不能把 `q−1` 解释成新增 kernel 启动次数。
- serial split-K 的后续分片通过 semaphore 顺序更新输出。累计链数 G 和分片 CTA 数 Gq 是不同的量。
- 是否有暴露在关键路径上的 semaphore 等待、填充/收尾损失、远端读取瓶颈，仍需要同身份的执行证据，源码本身不提供其微秒数。

源码位置：`EDM-IR/runtime/src/nccl_device_fused_cutlass.cu:105`、`cutlass_sm80_gemm.cuh:19`；执行包固定的 CUTLASS 提交 `dcf215af68a2d08d305076c152a06f201728cd53` 中 `gemm/kernel/gemm.h:129,303,339,357`。当前外围 runtime 与历史采集版本不同，结构审查不能证明新旧整程序时间可以混用。

## 3. grouped-N/q8：选对仍然包含两处相反的误差

在 `(4,64,8192,1024)` 上，已有四个必要组合，不需要靠补造标签分析交互：

| 候选 | 预测 μs | 旧实测中位数 μs |
|---|---:|---:|
| q4，g1 | 772.608 | 764.0 |
| q8，g1 | 831.962 | 850.8 |
| q4，g2 | 850.712 | 844.2 |
| q8，g2 | 772.571 | 759.9 |

沿 `q4,g1 → q8,g1 → q8,g2` 拆分差值：

| 对照 | 预测 μs | 实测 μs | 预测误差 μs |
|---|---:|---:|---:|
| 固定 g1，把 q4 改为 q8 | +59.354 | +86.800 | -27.446 |
| 固定 q8，把 g1 改为 g2 | -59.391 | -90.900 | +31.509 |
| 合计：q8,g2 − q4,g1 | **-0.037** | **-4.100** | +4.063 |

模型少算了增加 q 的损失，也少算了 q8 下 grouped-N 的收益，两处误差相抵。完整 q×g 交互差值预测为 -137.495 μs、观测为 -171.100 μs，相差 33.605 μs。因此，最终选择正确并不足以证明交互表达正确。

raw 差值中，深度项 -191.962 μs、K/output-tile 项 -50.267 μs，与其余合计约 +242.191 μs 抵消。深度区间系数只需减小约 **0.0192%**，即可让当前差值达到零。这是固定函数的解析敏感性计算，没有改动参数，也不是从数据估出的系数置信区间。该余量远大于本轮重建的浮点误差，不能归因于数值舍入。

两个对角候选虽然都是 32 个 CTA，却不是相同执行资源：

| 一次源 GEMM 的计数 | q4,g1 | q8,g2 |
|---|---:|---:|
| CTA tile | 64×128×32 | 64×256×32 |
| warp / CTA | 4 | 8 |
| thread / CTA | 128 | 256 |
| 每分片 K 迭代数 | 64 | 32 |
| 独立输出累加链 | 8 | 4 |
| 分片间顺序依赖边数 | 24 | 28 |

g2 是更宽的 CUTLASS 模板，不能理解成仅把网格数除以二。相同 CTA 总数不足以判断两者驻留能力，经验 capacity=32 也不是实测占用率。需要区分 tile 宽度、warp 数和累加链；尚不能据此认定哪一个硬件限制主导该点。

## 4. 测量记录支持什么，不支持什么

目标行均可追溯到旧归档：host `steady_clock` 包围 `backend.execute()` 和 `backend.synchronize()`，30 次预热、300 次计时，有 min/mean/median/p95/max 汇总，但这些行的 `repeat_observation` 为 null。现有行没有提供成对重复差值的原始序列或置信区间。300 次内部迭代不自动等于 300 次独立实验。

grouped 对角候选还有一个必须保留的事实：

- 中位数：q8,g2 比 q4,g1 快 4.1 μs，旧验收按此计为正确。
- 均值：q8,g2 为 783.2 μs，q4,g1 为 779.1 μs，前者反而慢 4.1 μs。

本轮没有切换验收目标，也没有用“可能有噪声”免除三个模型误选。该差异只说明排序依赖时间分布的统计口径；需要预先指定优化目标，并保留跨运行的成对原始结果，才能评价边界稳定性。min/p95 区间重叠不能替代显著性检验。

## 5. 后续只验证两个问题

### A. 短 K：非单调净收益是否可重复，出现在哪一层

保留三个错误形状，增加已有的 M64/K512/N128 与 N512 两个正反对照，固定候选为 host、direct、q2。总共 5 个形状、15 个候选测量点。N512 是必要的 q2 优势反例，避免把 K512 一律改为 direct。

先保持同一构建、精度、metadata 模式和计时口径，做候选顺序平衡的成对重复；完整保存逐迭代时间。若稳定复现方向变化，继续用单独的设备计时/执行记录区分设备关键路径与主机提交、同步部分。两类计时不能相加当作端到端时间，也不能通过混用历史/新版实现来归因。

### B. grouped-N：分别验证 q 变化和 tile 变宽

仅保留上面的 2×2 四格，另加身份统一的 host，共 5 个候选点。先验证两条边和交互差值，不能只报告对角胜负。必要的单独 profiling 窗口记录实际 kernel、grid、block、共享内存、寄存器和可解释的执行依赖；profile 时间不得进入稳态成绩。

**两组共 6 个已有开发形状、20 个测量点。** 这是诊断需求，不是新增 benchmark 大扫表。具体字段和停止条件见 [measurement-requirements.json](measurement-requirements.json)。冻结六形状仍留作独立验收，不进入这 20 点。

当前诊断依据 P4/FP16。未来租八卡时，可用同机四卡子集复核这些历史机制；原生八卡结果须另建执行身份、重新冻结对应预测，不能把 P4 的微秒数直接当作 P8 预测。本轮不启动服务器、不声称八卡执行包已验证，也不增加 BF16 分支。

结束条件：能把稳定的选择差异归到可观测的执行变化，或明确记录仍不可区分的原因及所缺证据。若成对测量仍无法确定方向，保留“证据不足”，不继续拟合到它选对。
