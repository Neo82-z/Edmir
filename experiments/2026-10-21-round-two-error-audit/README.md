# 第二轮剩余错误审查

本次审查对象是上一轮冻结的 `traffic_gap`。结论是：**剩余错误有可定位的结构原因，不是优化器没有求解好。至少一处输入信息丢失，使当前模型不可能同时给出正确的 fused 排序；另一类失稳来自联合拟合之前的离散基函数选择。**

没有修改旧模型、标签、验收阈值、编译器默认路径或 GPU 执行包。新增的是诊断代码、独立数值核查和失败归因。GPU 操作与新独立标签均为 0。本报告中的基函数冻结结果是事后干预对照，不能作为修复后的验收成绩。

## 1. 首先找到一个不能靠调参数消除的特征冲突

固定 P=4、K=4096：

| 形状 | 输出 tile 数 | 实测 q2 | 实测 q4 | fused 中较快者 |
|---|---:|---:|---:|---|
| M=256，N=512 | 4×4=16 | 0.6821 ms | 0.6885 ms | q2，快 6.4 μs |
| M=64，N=2048 | 1×16=16 | 0.7248 ms | 0.7209 ms | q4，快 3.9 μs |

当前 fused 分支的输入只通过 `grid=ceil(M/64)*ceil(N/(128*g))` 保留 M、N 的影响。两者的 grid 相同、K/q 和 g 相同，因此对应候选的**整条输入向量完全相同**。该冲突在四个 capacity 设置下都成立，不取决于某组拟合系数。

由此可直接推出：使用现有输入的共享确定性评分器，对这两种形状会输出相同的 q2/q4 排序。加训练步数、换优化器、调损失权重，甚至在这些相同输入上换更大的网络，都不能同时拟合这两种相反排序。

这两个形状的 host 可以不同，因为 host 分支保留了 MK；但这不能恢复 fused 候选之间已经丢失的信息。第二轮增加 MK 项主要改善了 host，fused 分支仍有此缺口。

**修复必须是能改变候选间差值的 M/N 交互。** 单纯给所有 fused 候选加同一个 `f(M,K,N)`，在 q4−q2 中会抵消。可研究分区工作集、A/B 复用、实际 tile 利用率与 q 的耦合；不能把“分区工作集除以 q”解释为总通信量也减少 q 倍。

证据：`verified/structure.json` 的 `feature_collisions`，对应源码 `EDM-IR/edmir/compiler/traffic_latency_selection.py::fused_features`。

## 2. M512 的 q2/q4 错误来自交叉点和候选差值表达

留出 K4096 后，M512/N512 的 q4−q2 预测差为：

| 拟合项 | 对 q4−q2 的贡献 |
|---|---:|
| K/q | −216.392 μs |
| q−1 串行阶段 | +65.105 μs |
| 额外 CTA | +25.725 μs |
| K/q 与压力交互 | +125.162 μs |
| 合计 | **−0.401 μs** |

这些是模型内部的有符号贡献，**不是分别实测出来的服务时间**。实际 q4−q2 为 **+43.9 μs**，所以误选 q4，损失 4.364%。

更关键的是，在固定 M、N、g、capacity 下，现有 q4−q2 特征差是 K 的仿射函数。虽然 fused 模型有 `max(K/4096−1,0)*grid/108` 这个非线性 K 项，但它不含 q，比较 q4 与 q2 时恰好抵消。其余相关项只剩 K/q 的线性项和与 K 无关的项。

该折将 q2/q4 的交叉点放在 **K≈4078**。同折中的预测与存档值是：

| K | 预测 q4−q2 | 存档 q4−q2 | 此折是否参与训练 |
|---|---:|---:|---|
| 2048 | +45.215 μs | +46.5 μs | 是 |
| 4096 | −0.401 μs | +43.9 μs | 否 |
| 8192 | −91.631 μs | −22.1 μs | 是 |

因此误差不只是留出点刚好落在一个很小的数值平局上：在已有的 K8192 训练点，q4−q2 的幅度也没有拟合好。当前表达和全局损失的折中把交叉点推早了。仅从三个点不能证明所有仿射表达都会选错；已经证明的是当前训练得到的交叉点错误，以及现有公共 K 非线性项无法纠正 q 之间的排序。

证据：`verified/outer_errors.json` 和 `verified/identifiability.json`。

## 3. 大 N 和 M512 删组失稳，主要由重新选择基函数触发

做了两条路径的严格对照，候选集合均与原准入规则一致，包含全部 6 个允许候选：

1. 原流程：数据变化后重新选择 host 的输入阈值、深度阈值及 fused capacity，再联合拟合。
2. 诊断对照：保留干预前的基函数选择，**只使用干预后的训练数据重新拟合系数**。

| 检查 | 原流程 | 冻结基函数的诊断对照 |
|---|---:|---:|
| 大 N：34 个固定 ±1% 扰动 | 31/34 选择 host | 34/34 选择 host |
| 大 N：8 次删组 | 5/8 选择 host | 8/8 选择 host |
| M512：24 次删组 | 23/24 正确 | 24/24 正确 |

这些分数不能当成新模型通过验收。尤其删组对照中的固定基函数，曾经使用被删除组选择过，因此只用来区分“重新选择表达”和“重新拟合系数”各自的影响。

大 N 的三个失败扰动都把 host 的深度阈值从 **2.0 切到 0.5**。例如 `seeded_signs_8`：

- 0% 扰动：预测最佳 fused 比 host 慢 25.47 μs，选择 host。
- 0.25%：慢 26.21 μs，仍选择 host。
- 0.5%：基函数切换，变成 fused 快 2.20 μs，选择 q4。
- 1%：原流程预测 host 0.677912 ms；冻结基函数重新拟合为 0.646741 ms，恢复正确方向。

M512/K4096 删去 `m256-n512-longk` 组时，host 的两个阈值由 `(2,0.5)` 切到 `(1,1)`：原流程把 host 估成 0.944664 ms，误选 host；冻结原基函数后估成 1.056392 ms，正确选择 q2。

**具体代码问题在流程衔接：** `decision_loss_selection._prior()` 仍调用旧的 `TrafficLatencySelector.fit()`；它按 host/fused 各自的相对耗时均方误差选择基函数。后续才用新的联合差值/间隔损失拟合系数。第三轮只选择损失权重，没有改变这个前置选择目标。因此“最终损失面向决策”并不等于整条模型选择流程都面向决策。

证据：`verified/deletions.json`、`verified/perturbations.json`，包含固定幅度变化轨迹以及每次内层候选分数。

## 4. 留 K 后还有真正的不可辨识性

留出 K4096 时，训练 K 只剩 `{512,1024,2048,8192}`。令 k=K/4096，host 的深度列为 `max(k−b,0)*log2(N/128)`。

在这些训练点上：

`深度列(b=0.5) = 1.5 × 深度列(b=1.0)`。

缩放后的两列完全相同。两种表达具有相同的联合训练目标，但在被留出的 K4096 上不同：b=0.5 激活，b=1.0 不激活。独立求解得到的 host 预测分别是 **1.045186 ms** 和 **1.025316 ms**，相差 **19.87 μs**。

旧内层 CV 两个最优分数相差约 **1.3×10⁻¹⁸**，实际由浮点末位决定选择。这个差异没有可解释的统计优势。它不是本次 q2/q4 错误的原因——此对照下 q2/q4 的预测没有变化——但暴露了 host 外推在缺少区分信息时，仍强行选定一个表达的问题。

修复应识别训练上等价/近等价的表达，显式记录其外推分歧，并让基函数选择层接受决策和稳定性检查。不能把比较精度调得更细，当作新增了信息；也不能因为看过测试答案就固定选择 0.5 或 2.0。

## 5. 完整错误清单和损失组合的偏置

两种外层协议各 41 个形状，共 14 条相对“所有已测候选最佳”的非零损失记录：

- **10 条：** 五个 K512 形状在两个协议中，都误选 q2，实际 direct 更快。最大损失 2.632%。全数据拟合也在这五点选错，属于训练拟合/表达与目标的折中，不只是外推问题。
- **2 条：** 留 K4096 后，M256、M512 的 q2/q4 排序错，损失分别 0.938% 和 4.364%。
- **2 条：** M64/K8192/N1024 的最快候选是 `splitk8_groupedn2`，但它超出该折的 grouped-N 训练支持范围，被准入规则排除。在允许的候选里选出的 q4 是最快的。不能把这个 0.540% 差距和模型误排序混为一谈，更不能因此放开没有证据支持的 grouped-N 范围。

全部 328 次删组决策中有 54 次非零损失；本次对其中四个目标边界的 32 次决策进行了固定表达干预，其他删组失败保留完整清单。

损失还有一个容易忽略的权重问题：当前先给 host 行一半权重、fused 行合计一半，再用 `w_i*w_j` 分配成对项。对 6 候选形状，每一对 host/fused 的权重是每一对 fused/fused 的 **5 倍**；host/fused 合计占成对项的 **71.43%**。对 11 候选形状，单对比例变成 **10 倍**，合计占 **68.97%**。这不是计算 bug，但意味着“用了成对损失”并没有给 q2/q4 等内部排序同等关注。新增候选还会改变这些权重比例。

K512 的执行属性也值得修正：源码中 direct 使用 `SplitKSerial=false`，q>1 使用 `true` 并需要 semaphore workspace；当前表示没有独立的 split-K 模式启用项，只用 q−1 等连续计数吸收这些差别。workspace 分配/初始化发生在 prepare，不能误加为每次稳态 kernel 都承担的代价。尚未实测确认固定启用成本的数值，不能把它当成已经查明的唯一时间来源。

## 6. 排除了什么，仍未证明什么

对全部 14 条外层失败记录，独立展开每一对候选与间隔项，使用 SLSQP，再解当前分段二次目标的有效区域线性系统；检查系数下界、全局投影梯度和强凸目标下界。所有选择均与原结果一致，预测耗时最大变化只有 **0.000107 μs**。M512/K4096 的 q4−q2 从 −0.400601 μs 变为 −0.400594 μs，误选没有消失。

辅助求解达到约 1e-14 的投影梯度；本次最关心的 K4096 折，原目标的剩余优化误差上界约 5.98e-12，精化后约 1.84e-25（目标函数单位）。这些检查针对给定目标的数值求解，不是泛化保证，也不把旧测量自动当作无误差的硬件真值。

诊断代码新增 **6 项测试，全部通过**：显式目标与梯度、辅助求解器下界、全部错误覆盖、完整候选集合、特征冲突/共线性、旧交付物哈希未改变。最初两次诊断尝试因辅助求解器对 ridge-only 列的零解与 1e-10 下界处理不一致而主动停止；修复并补测试后完成。停止日志和源码快照均保留，没有把它算成预测器修复。

## 修复优先级

1. **先修 fused 表达的信息损失。** 明确区分 M 与 N，并让新增资源特征与 q/分区执行属性交互；检验同 grid 不同工作集的形状可以有不同排序，以及 K 非线性确实进入候选差值。
2. **再修基函数选择层。** 对齐最终决策目标，加入训练内稳定性检查与等价表达识别，避免绝对误差略好就切换整个 host 外推形状。固定一个事后有利阈值不是合格修复。
3. **随后校正成对权重与 split-K 启用表达。** 保留各块消融，不把统计损失减少归因于未经验证的物理服务时间。

这些修改与回放均可继续在本地进行。不能把本次诊断对照当作新模型已经通过原验收。

## 复现与文件

在仓库根目录、已安装 NumPy/SciPy 的 Python 环境中：

```sh
PYTHONPATH=EDM-IR:EDM-IR/tools OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python3 experiments/2026-10-21-round-two-error-audit/audit.py --out /tmp/round-two-audit-new
```

输出目录须为新目录，脚本总预算 600 秒；本机完整诊断约 8 秒。`structure.py` 生成补充静态分析，`test_audit.py` 核验仓库内 `verified/` 结果。实际运行环境与上一轮相同：Codex Python 3.12、NumPy 2.3.5、SciPy 1.16.3。

- `verified/outer_errors.json`：完整外层失败列表、逐项分解和独立求解证据。

- `verified/perturbations.json`：34 次扰动与 15 个幅度轨迹点。
- `verified/identifiability.json`：留 K 后共线基函数、预测交叉点。
