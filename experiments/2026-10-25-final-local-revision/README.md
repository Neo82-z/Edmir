## 2. M256 的表达缺口与修订结果

旧表达为 `C(x) + max(aL, bW)`，其中 `L=K/(2048q)`，`W=2MK·ceil(N/(128g))/2^20`。
当 W 分支占优，max 部分完全丢掉 L 的变化；它可能把 q 增大后的深度收益遮蔽掉，余下串行累加代价主导排序。反过来，L 分支占优时，也不表达较小 W 在平台内的增长。这是表达限制，尚不是设备瓶颈的因果定位。

本轮只检验一个假设：吞吐阶段仍有未被隐藏的分片深度成本。将公共项中的 SM 分布缺口替换为 L，得到 `C'(x) + dL + max(aL, bW)`。fused 仍为八个非负系数；原 SM 项在全量拟合中为零，但替换仍明确视为模型修改。保持求解器、形状权重、正则、数据划分与质量规则不变。

| 同一批 63 个稳定配置、10 个形状的留出指标 | 原 `regime_max` | 新 `residual_depth` |
|---|---:|---:|
| 按形状平均的绝对相对误差 | 4.18% | 4.02% |
| 方向错误 | 9/191 | 12/191 |
| fused 最坏选择损失 | 3.22% | 3.22% |
| 全部已测稳定候选的最坏选择损失 | 2.29% | 9.02% |
| 最大候选误差 | 27.01% | 27.01% |

M256 的两对排序仍错，且新增其他形状的误选。平均误差下降不足以支持替换模型。保留失败结果，停止本轮继续调整旧标签；下一步用固定 M/K/N 对照检查平台、增长段和 q/g 交互。参见 [指标](results/metrics.json)、[决定](results/decision.json)、[整条 M 留出](results/leave-M-out.json)。

## 3. host 的 27.01% 误差没有被修复

短 K 的 merged-cuBLASLt 实测 211.654 μs，留出预测约 268.824 μs。五个稳定形状对应五个不同的**完整算法配置**；每个留出目标的配置在该折训练中都没有出现。算法 ID 相同也不能合并：tile、split-K、reduction、stages 和 workspace 可能不同。

现有样本无法把形状效应与库算法切换的效应拆开，因此本轮没有编造算法几何、将整数 ID 当连续特征，或利用目标测量后的算法信息改写预测。只在新模型输出中增加算法支持范围说明，数值预测和错误仍保留。见 [algorithm-support.json](results/algorithm-support.json)。新采集补短 K 邻点和四种 host 的完整算法记录；它能检查算法切换是否伴随误差改变，不能预先断言全部误差由算法切换造成。

## 4. 质量异常如何翻转判断

在 M64/K3072/N1536，q4−host 实测为 +52.759 μs。排除这个完整形状后，控制训练中加入哪些原先带质量标记的配置：

| 标定干预 | q4−host 预测差 μs |
|---|---:|
| 仅稳定配置 | +3.825 |
| 仅加入带标记的 host 配置 | −1.044 |
| 仅加入带标记的 fused 配置 | +1.213 |
| 加入全部带标记配置 | −3.656 |
| 仅加入 M64/K1024/N512 的 host | −1.721 |

最后一个配置的三个进程中位数为 329.649、364.619、451.993 μs，同时存在进程内漂移和进程间跨度。它单独就足以改变这个边界，说明此前严重误判主要受到 host 标定的影响。加入全部标记配置时，损失 10.80% 的错误仍完整报告。

这项干预定位的是**模型对数据的敏感性**，没有证明设备漂移的原因，也没有证明原 +3.825 μs 的边界可靠。新包将 20 次预热的主测量和 200 次预热的 host 诊断分开，不能用后者覆盖前者。详见 [quality-sensitivity.json](results/quality-sensitivity.json)。
